# ch-bsd — refmatrix overlay

Read with the neutral `.claude/agents/ch-bsd.md`. Facts the auditor needs for THIS project.

## Production roots and how code gets executed

- `src/refmatrix/` is production. Entry points: `rmx` console script → `cli.py:cli_entry` (click
  tree); daemon ops via the `OPS` / `CLI_OPS` dicts in `daemon.py` (an `_op_*` not registered
  there never runs); hub ops in `hub.py`; MCP tools = the `TOOLS` list in `mcp.py` dispatching to
  `verbs.py` (`@verb`) — a tool that calls daemon/handoff directly bypasses the capability layer;
  hooks generated by `hooks.py:_claude_hook_block` + `search_hooks.py` — the INSTALLED file is
  `.claude/settings.json` (rmx block) and must equal the generated block (`rmx install-hooks --check`).
- Templates shipped to other projects: `src/refmatrix/templates/{commands,agents}/`.
- The deployed runtime is `~/refmatrix/.venv` behind `~/bin/rmx`; verify what it imports with
  `~/refmatrix/.venv/bin/python -c "import refmatrix; print(refmatrix.__file__)"`. Dev is `.venv-eval/`.

## Where deferrals hide (Python)

Module docstrings ("Phase N", "deferred to v1", "for now"), `# TODO`, `_ = unused`, env-flag-only
facades (`RMX_*` read once, no caller), `except Exception: pass` on write paths, and `|| true` /
`2>/dev/null` inside generated hook strings.

## Runtime evidence you may use (read-only)

- `.refmatrix/cli.log`, `query.log`, `facts.log`, `rmxd.log`, `daemon.stderr.log`, `~/.refmatrix/hub.log`.
- `rmx daemon status`, `rmx hub status`, `rmx memory get <name>`, `rmx memory recall --recent`.
- Do NOT run `.venv-eval/bin/rmx` against the live store with a bumped version (fleet restart).
  Do NOT run `rmx grep` in a loop while the daemon is unhealthy; use Python for searching then.

## E2E

No browser suite. The end-to-end paths are: `rmx save-state` → `rmx recall-state` round trip on a
tmp store; `rmx install-hooks --check`; the verb parity test (`tests/test_verb_parity.py`); the
production benchmark harness `eval/production/`.

## Ledger

`workflow/bullshit/` (INDEX.md, IMPRESSIONS.md, last_run.log, one report per run). Memory
impressions may also be written as GMD under `~/.claude/projects/-Users-tholley-claude-tools-refmatrix/memory/impressions/`.

Stamp every ledger artifact with the REAL time it was written — `date +%FT%T%z` at write time, the
same value in the filename, `INDEX.md` and `last_run.log`, and no `GIT_AUTHOR_DATE` /
`GIT_COMMITTER_DATE` override on the commit that carries them. The r3 artifacts were written at
00:53, named `0105`, logged `01:05:00` and committed with an author and committer date of exactly
`01:00:00`; INDEX.md is the evidence trail for WHICH TREE an audit saw, so a forward-dated stamp
turns "which commits existed when this ran" into a guess (ch-bsd r4 #m-1-r4).

**IMPRESSIONS.md size cap (replaces the base rule's scope).** The cap is the file: `IMPRESSIONS.md`
is at most 50 lines (`wc -l`; `tests/test_gmd_body_anchors.py::test_impressions_window_is_under_its_cap`
fails over it). The pointer register is its own file, `workflow/bullshit/IMPRESSION_ANCHORS.md`
(id `bsd-impression-anchors`), which the cap does not count. Fold procedure: (1) fold the oldest
bullets verbatim, ids unchanged, into one new `impression_bsd_ledger_*` memory (the lead writes the
memory and runs the bridge); (2) add one pointer line per folded id to the register, one id per
line, never several (the linter accepts packed ids, but the store ingester registers only the first
anchor on a line, so efa5f33's packing made 188 of 200 pointer ids unknown to `rmx` while lint
stayed green, fixed 2026-11-09):
`` - `imp-x` → [[impression_bsd_ledger_<date>#imp-x]]. `` followed by its anchor; (3) rewrite every
`[[bsd-impressions#<id>]]` citation of a folded id to `[[bsd-impression-anchors#<id>]]`
(`./scripts/lint-gmd.sh` reports a missed one as `dangling-anchor`); (4) confirm a sample with
`rmx context "bsd-impression-anchors#<id>" --no-grep` after the next ingest.

**Findings ledger column.** Name the self-audit question per BULLSHIT (`SA-1`..`SA-8`, or
`none: <proposal>`); the lead copies it into the `question` column of `OPEN.md` / `CLOSED.md`, and
`python3 scripts/bsd-tally.py` tallies it (exit 1 on an empty cell).

## One pass, and close the loop (L165, L166)

You review a large change once. Authors now answer `workflow/SELF_AUDIT.md` in their summary:
check their answers against reality first (re-run their "ran it for real" command, re-grep their
census). For every BULLSHIT, name the self-audit question that should have caught it, or say
"none would have" and propose a new question or a lint (name the mechanical rule). Only BULLSHIT
earns a second round.

## Check the test discipline (CLAUDE.md #test-discipline)

In every review, list any new test file named for a round/bug/fix, any new variant that should be
a parametrized case, any patched `ping`/`daemon.call`/guard input in a test about busy or down
behaviour, any test that waits out a real timeout, and any new source-text test without a planted
must-fail case. Each is at least SKETCHY. A test or guard that cannot fail for its stated
property, a patched guard input, or a waited-out timeout that hides a defect is BULLSHIT (P1
clause 4 or 6).
