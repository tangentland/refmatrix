## Context {#context}

The user's design question (2026-11-24): *for each rule type/subject, what is the most
automatic, reliable, repeatable, efficient way to inject rules / memories / instructions /
content into context without relying on the model to remember to retrieve it?*

Today rules reach the model four ways, and three of them depend on luck or on the model:
- **Always-on** (~62 KB: CLAUDE.md, PROJECT_PROFILE, PRIMER, MEMORY.md index, global files):
  automatic but costly, and diluted by volume.
- **Prompt-keyed recall** (UserPromptSubmit scan-prompt + memory recall): automatic but
  probabilistic. It fires on the prompt's words, not on what the model is about to DO.
- **Model-fetched** (ORCHESTRATION.md, PLANNING_WORKFLOW, 340 memories, `rmx context`): only
  when the model remembers. Today's release re-derived `--force`, `hub relaunch-fleet`, the hub
  restart and the brief shape this way.
- **Enforcement** (PreToolUse denies: test-to-file, rmx-grep, the C1 read gate; p20-0 guardrail
  memories → auto-mode rules): the only fully reliable channel, and it costs nothing until
  violated.

The gap: nothing injects a rule or procedure **keyed on the tool call, path or state
transition where it applies**.

## Principle {#principle}

Bind each rule to the **earliest mandatory event at which it becomes actionable**, inject it
**there only, once per session** (an inject-once marker, like the composite's), and **record
whether it was used** (telemetry) so tuning is data-driven. Prefer **enforcement** (deny with
the rule as the reason) over reminders whenever the violation is detectable. Mirrors the
existing feedback rule "bind capture to mandatory artifacts".

## Rule types → mechanism (pre-mod now / post-mod) {#rule-types-mechanism-pre-mod-now-post-mo}

**Verified 2026-11-24 (Claude Code docs: memory.md, hooks.md, skills.md, sub-agents.md):**
- `.claude/rules/*.md` with `paths:` load when Read/Write/Edit (or a single-file Bash
  `cat`/`head`) touches a matching file, in the main session AND subagents; not on Glob/Grep;
  after `/compact` they reload on the next touch. Rules without `paths:` load at launch (so
  today's `bug-registry.md` rule is always-on). Nested CLAUDE.md: same trigger, same scope.
- Skills: `paths:` frontmatter activates a skill conditionally; an agent's `skills:` field
  preloads full skill bodies at agent start; bodies survive compaction (first 5k tokens each,
  25k total). Descriptions are always listed (≤ 1,536 chars each).
- Hooks: PreToolUse may return `additionalContext` WITH an allow (and deny with a reason);
  PostToolUse adds context next to the result; SubagentStart injects into the subagent before
  its first prompt (cannot block); Stop / SubagentStop add context or `block` to keep going;
  tool hooks fire inside subagents with `agent_type`. Every injection ≤ 10,000 chars (over it:
  file + 2,000-char preview). UserPromptSubmit / SessionStart inside subagents: not documented.
- `InstructionsLoaded` hook reports each CLAUDE.md / rules load: usage telemetry for rules.
- Auto memory: only the first 200 lines or 25 KB of MEMORY.md load.

Consequence: path- and tool-specific injection is buildable **now**, natively; the mod adds
cache-stable sections, `skill.prompt` enrichment, `session.measure`-driven tuning and plugin
distribution, not the basic capability.
