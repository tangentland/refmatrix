Two MEH-level gaps:

### n-1 (MEH): the ring's dropped-key list exists twice {#n-1}

- **Where:** `instructions.RING_DROPPED_KEYS` copies the literal at `cli.py:2392`
  (`("content", "new_string", "old_string", "edits")`). The writer does not read the constant.
- **Consequence:** if the writer later drops or keeps a different key, replay goes quietly wrong
  again. The b-1 test's precondition pins only the two keys it uses.
- **Fix:** have `_tool_event_fields` read `instructions.RING_DROPPED_KEYS`; it is a one-line
  convergence.

### n-2 (MEH): "unmeasurable" is decided per bind, not per (bind, tool) {#n-2}

- **The gap:** take a bind with no `tool`, or a pattern that covers Bash and other tools (for
  example `Bash|Task`), with a key other than `command` (for example `description`).
- **What happens:** the bind is counted as measurable. Its Bash calls can never hit, because the
  ring keeps only `command` for Bash, and no line says so.
- **Also:** `_NON_BASH_TOOLS` is a fixed list. A pattern `Bash.*` (which matches `BashOutput`) is
  read as Bash-only. That over-reports "unmeasurable"; it never under-reports.
- **Consequence today:** none. This is narrow, and no unit ships with such a bind.
