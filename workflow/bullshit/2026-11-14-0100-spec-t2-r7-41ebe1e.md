**File:** `task-26.5…:571-577`, `:764`
**What:** "`ingest_gmd_paths` (`as_memory=False`) checks for an open invocation on EVERY call …

AC-220 (f): "bug-216's X1 pins re-run green."
**Why it's sketchy:** the rule is right (L63), but nothing scopes its blast radius, and one choice
it forces decides whether the new guard can still catch anything in tests.
**Evidence** (`git grep` at `4b4b96e`):
- **The bug-216 family, which AC-220 (f) requires to stay green.** These call `ingest_gmd_paths`
  without `as_memory`, or call `_op_ingest_gmd` straight from the test thread, outside any

  - `ingest_gmd_paths` without `as_memory`: `tests/test_bug216_binding.py`, `_rel_landing.py` (2),
    `_replay_fidelity.py`, `_rev4.py`, `_surfaces.py`;
  - `_op_ingest_gmd(d, …)` called directly: `tests/test_bug216_hidden_no_pollution.py` (the X1
    pins, 2 routes), `_rule_docs_e2e.py` (3), `_rev4.py`, `tests/test_memory_only_guard.py`.
  - The X1 file's project routes also call `ingest_path` and the sync functions directly on a
    Store. Every one of these raises `NoInvocationError` once 26.5 lands, as soon as its fixture

- **Others calling `ingest_gmd_paths` without the flag:** `tests/test_derive_history.py`,

- (a) one explicit `with memory_reroute.invocation():` at each direct call site; and

That must be named, or it reads as bending pins.

  (a small test helper is fine), never an autouse fixture.
- List the files above in Files as "wrap only, no assertion change".
- Add (f)'s wording: "the X1 pins re-run green with only the invocation wrap added".
- Add a guard: a test that fails if any conftest opens an invocation implicitly.

### MEH: in (p), Y's same-store group is refused while X's job runs, so "each group is dispatched once" fails on a correct build {#z2}

**File:** `task-26.5…:848-856`, `:686-687`
**What:** Y is "a `sync_files` op over its own (i)-shaped fixture", and (p) asserts "each group is
dispatched once". But (i) runs both slug → A and slug → B. If Y's fixture maps to A, Y's drain is
same-store with no parent job. By R-220c: "A drain with no parent job has no exemption. If another
job is active, the group is `rerouted_failed`". X's ingest job IS active, because X is gated
mid-walk. A correct build therefore reports Y's group as `rerouted_failed: ingest already active`,
and (p) fails.
**Fix:** say that Y's fixture maps to B (cross-store, B up), or that (p) expects Y's same-store
group as `rerouted_failed` with that reason.

### MEH: (q)'s daemon synchronous leg has no carrier for the drain result on an error reply {#z3}

**File:** `task-26.5…:588`, `:861-864`
**What:** "The drain result rides back on `run`'s return into the reply". (q) requires a raising
synchronous op's "reply … carries both the error and the reroute result". When the handler raises,
`run` returns nothing. `_handle`'s `except Exception` builds `{"ok": False, "error": str(exc)}`
(`daemon.py:3394-3395`), so the result the wrap drained in its `finally` has no way into that
reply.
**Fix:** name the carrier. For example, the wrap attaches the drain result to the exception
(`exc.reroute`), and `_handle`'s error reply copies it as a `reroute` key. The CLI prints it next
to the error.
