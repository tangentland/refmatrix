## Findings {#findings}

### BULLSHIT b1: after /clear the mod's timers are dead and the shell hooks resume beside the mod hooks {#b1}

24.5 R1 stops the timers at `session.end`, and R10 and AC-11 say "after `session.end` no timer
fires". The types (SessionEndInput, session.start) say `/clear` raises `session.end` reason `clear`
and that no `session.start` fires for it. So after every `/clear`:
- the health tick, the status line and the bus wake are dead for the rest of the process;
- 24.6 d8's `RMX_MOD_LIVE` is no longer refreshed, so 45 s later every guarded shell entry runs
  again while `prompt.submit` and `tool.call` still fire in the mod. Every observation, injection
  and STM write happens twice.

AC-11 pins this broken behaviour.
**Fix:** on `session.end` reason `clear`, keep the timers and re-key them to the new id (or
restart them on `classic.SessionStart` source `clear`). Stop them only for exit, logout and the
end of a `-p` run. Add an AC: after a mocked `/clear` the tick still fires and the marker is
under 15 s old.

### BULLSHIT b2: 24.5 d4 returns an object as the tool result; the engine rejects it {#b2}

d4 sets the tool result to `{ result: <verb dict> }`, and an error to `{ result: { error } }`. The
probe at 5aac253 got exactly this error from the engine (`probe-run1.out`): "result does not match
its output shape … expected string, received object". So every G4 tool call fails.
**Fix:** `result` = `JSON.stringify(dict)`, the text the MCP server returns today, or content
blocks. An error is `isError` text. Add an AC that feeds a real verb dict through `$.tool.call`
under `claude plugin test`.

### BULLSHIT b3: 24.0 R8's OBJC fix is anchored to a completed task that does not carry it {#b3}

R8 says the fix "ships with 3.7, so it is live before the BEFORE window". The facts:
- the 3.7 clone is `status: completed` (260aa3f, 41c3568);
- its `hooks.py:26` HOOK_ENV is still `export RMX_INVOCATION_SOURCE=hook;` with no OBJC variable;
- the 3.7 spec has no AC for it.

This is a stale deferral (rule 9a). Without the fix, the baseline credits the mod with the re-exec.
**Fix:** put it in a live spec with an AC. Either 24.0 R3's per-invocation helper prefixes
`OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`, with AC-3 asserting it on every invocation, or a 3.7
amendment adds an AC before merge.

### SKETCHY s1: the stand-down marker has gaps beyond b1 {#s1}

- (a) d8 refreshes the marker only from the 15 s tick. Set it synchronously at the top of
  `session.start`, before the discovery await. Probe whether the settings SessionStart entry sees
  it; if it does not, SessionStart is observed twice.
- (b) The 45 s window is hard-coded, but 24.5 R14 lets `health_interval_s` be set to any value.
  Run the marker on its own ≤ 15 s timer, or bound the field.
- (c) d9 wants per-context class lists, but `$.env` is one process-wide value that the main loop
  and its subagents share. The guard must read `agent_id` from the envelope, or the classes must
  be split by context.

### SKETCHY s2: R12's secret scrub alters what the model reads {#s2}

The types say a `session.append` rewrite is "stored and sent after; the model and the transcript
file never read [the original]". Two consequences:
- A Read of a file that holds a secret-shaped string shows `[redacted:…]`, and an Edit or Write
  round-trip then writes the marker into the file. scrub.ts's own AC-10 fixtures are such files.
- AC-10 tests object identity, not this.

No goal from G1 to G6 needs the scrub.
**Fix:** move it to the follow-up candidates, or limit it to Bash output and never file-reading
tools. Add an AC: Read a fixture file, Edit it, and its bytes are unchanged.

### SKETCHY s3: the final answer is recorded twice, as `reason` and as `say` {#s3}

The `response` door rows include the final answer, which `turn.complete` also records as `say`.
**Fix:** dedupe by row uuid or text hash, or skip the turn's last response block. Add an AC.

### SKETCHY s4: subagents lose the primer {#s4}

The probe shows `prompt.compose` does not fire for subagent requests. 24.6 d4/R9 drops the
`@.refmatrix/PRIMER.md` import, which subagents read through CLAUDE.md today, so they get no
primer at all. `turn.complete` with `agentId` (the SubagentStop row) is also unprobed.
**Fix:** keep the import until an `agent.spawn` / `skill.prompt` probe gives subagents a route.
Mark the subagent rows of the event map "unprobed".

### SKETCHY s5: the curator call does not match 3.7's verb {#s5}

24.6 calls `rmx_curator(status, drain)`. 3.7's verb takes one `action`, and a drain requires the
status `token`. A drain on every prompt is also exactly 3.7 r1 B3's defect.
**Fix:** call status per prompt, and drain with the token only after the curator has consumed the
entries.

### SKETCHY s6: the 24.2 thread model {#s6}

I found no deadlock: op pools never wait on `verb_pool`, and `dispatch` takes no `_store_lock`.
The thread model has these gaps:
- (a) The HTTP request is read on a `verb_pool` thread, so an idle client pins a worker for 30 s
  (bug-041's shape). Read and parse on the accept thread; submit only the verb run.
- (b) A write's `fut.result()` is unbounded. Observe writes (two per tool call) fill the 4 workers
  behind a long `bg_pool` op and starve reads. Use separate lanes, or bound the wait.
- (c) R8 records a key only after the verb succeeds. An outbox replay of a write still queued in
  the daemon therefore runs twice. Reserve the key while the write is in flight.
- (d) d8 runs `fn` in the verb thread outside `dispatch`: no in-flight entry, no fast-exit check,
  and an unbounded wait on the writer under `_store_lock`. That is the second path d2 forbids.
- (e) State that `CALLER` is set inside the pool thread, because `submit` does not copy
  contextvars.
