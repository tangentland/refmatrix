### SKETCHY s-3: the verb's own mode map still sends `recent` to the retired `precompact` budget {#s-3}

**File:** `src/refmatrix/verbs.py:1135` (`_PACK_CHANNEL_OF_MODE = {…, "recent": "precompact",
…}`), read by `pack_recall` at 1160-1164.
**What:** m-4's fix retired the `precompact` entry from `hook_budget.CHANNEL_BUDGET_BYTES` and
re-mapped `recent` in the CLI (`cli.py`, `"recent": "session_start"`). It left the verb layer's
twin map unchanged. In `pack_recall`, `label = "precompact"` is not in the table, so the
fallback looks up the same map again and gets `"precompact"` again. `hook_budget.resolve` then
raises.
**Evidence:** a direct call on a sandbox store at 4784cdd5:
`verbs.pack_recall(root, [], mode="recent", query=None, k=5, max_bytes=None)` raises
`VerbArgsError: hook_budget: unknown channel 'precompact'; known: curator_status, …`. The same
call with modes `session-start` and `dense` returns a pack.

`verbs.memory_recall` takes `channel` only from its CLI-internal `internal` dict. The MCP tool
`rmx_memory_recall` exposes `pack` and `recent`. So an agent's `rmx_memory_recall(recent=true,
pack=true)` with no `max_bytes` now fails, where at cbbe9e3f it packed to 9,000 B. The CLI
`rmx memory recall --recent --pack` still works in the sandbox (`budget 9000 B`), because the
CLI passes its own channel.

The MCP end-to-end call was not run: it needs a sandbox daemon. The failure is shown at
`pack_recall`, and the path to it is traced in code. `test_no_precompact_budget_channel_or_producer_remains`
does not cover the verb map.
**Fix:** one line, `"recent": "session_start"` in `verbs._PACK_CHANNEL_OF_MODE`, mirroring the
CLI. Add a case to the m-4 test that calls `pack_recall(mode="recent")` with no channel and no
`max_bytes`.
**Pattern match:** YES. `feedback_check_the_sibling_condition` and
`imp-default-reaches-every-caller`: the retirement reached one of two maps.
