## Findings {#findings}

### SKETCHY s1: R3's facts.log claims are false, and AC-2's "replay digest matches HEAD's" pins a HEAD replay defect {#s1}

**File:** [[task-bug185-bulk-gmd-ingest#r3]], [[task-bug185-bulk-gmd-ingest#ac-2]]
**What:** R3 says "facts.log events are unchanged as a multiset". AC-2 requires the new code's
replay digest to equal HEAD's.
**Why it's sketchy:**
- **The multiset changes by construction.**
  - `Store.link` logs an event on every call, including calls on bits already set
    (`store.py:4635-4690`). `bulk_link` logs only NEWLY added bits (`newly_added_for_log`, the same
    on bug-178).
  - `add_concept` logs entity events per call, so an anchor linked 3 times gives 3×(1+variants)
    events. `_bulk_add_concepts` dedups first.
- **HEAD's direct-call replay is lossy.**
  - On the direct-call path (`_op_ingest_gmd`, the CLI fallbacks, `ingest.py:1203`), the
    per-row `link(None)` creates the bit first. The doc's `bulk_link(link_batch,
    update_weight=True)` then sets the tf weight but logs nothing, because the bit is not new.
  - Probe [[#p-semantics]]: catalog 3.0, replay None.
  - A correct bulk implementation that writes the anchor mentions after `link_batch` logs the tf
    and replays 3.0. It therefore FAILS "matches HEAD's replay digest", unless it copies HEAD's
    ordering to keep the defect. That is the cheap-fix trap: the test gets bent, or the bug gets
    kept.
- **HEAD has two link semantics, by caller.**
  - Under `_sync_paths` (`with s.transaction(), s.deferred_links()`, `sync.py:191`), every per-row
    `link` is buffered and flushed at scope exit through a first-wins `bulk_link`. So `link_batch`
    lands first.
  - Direct callers write per-row `link` immediately.
  - AC-2 names no calling context, so a golden recorded in one context does not pin the other.

**Fix:**
1. Replace R3's multiset sentence with what holds:
   - (a) the catalog dump equals HEAD's;
   - (b) every `entity_links` row of the call has at least one link event naming it, and every
     entity event precedes any link event that names it;
   - (c) the new code's replay digest equals the new code's OWN catalog digest (replay fidelity).
     HEAD's replay digest is recorded, and every mismatch is attributed to the logged-weight defect
     below.
2. Record the AC-2 golden in BOTH contexts: sync (`transaction` + `deferred_links`) and direct (no
   transaction).
3. Log a bug row: `bulk_link` never logs a weight change on an existing bit. Together with
   per-row `link(None)` landing first, a facts.log replay drops tf weights on the direct ingest
   path.
   - Probe: [[#p-semantics]].
   - The row names its own owner (a new task, or folded into bug-185 R2 with a log event per
     weight-updated row). Leaving it with no owner is an unanchored deferral.
   - **Pattern match:** YES. `feedback_never_explain_away_a_failing_guard`: an equivalence gate
     against a defective baseline.

### SKETCHY s4: R2 leaves resolution order and the description rule open, and the golden lacks the shapes that pin them {#s4}

**File:** [[task-bug185-bulk-gmd-ingest#r2]], [[task-bug185-bulk-gmd-ingest#ac-2]]
**What:** "Pass 2 first resolves every wikilink target for the document … in ONE batched store
read". The anchor concepts go through `_bulk_add_concepts` with "first description wins".
**Why it's sketchy (probes [[#p-semantics]], [[#p-corpus]]):**
- **HEAD resolution sees its own earlier writes.**
  - The unconditional concept bulk write runs BEFORE resolution. Read literally, "first" moves the
    batched read ahead of it. That changes 2 real rel targets and 7 real unresolved refs on a
    first ingest.
  - Each `add_concept` (canonical + space/dash variants) also becomes resolvable for LATER targets
    in the same doc. That is 0 cases in the corpus, but it is the probe's `rel -> [[zeta-x]]`.
- **The description rule is last-wins across calls, not first-wins.**
  - `entities.meta` is COALESCE, last non-null wins ACROSS calls, and the anchor description
    overwrites the body-term one.
  - Folding the anchor specs into the unconditional `concept_specs` (the natural "one bulk call")
    makes the body-term description win instead, and changes `meta` (and `updated_at`) on every
    collided concept.
- **The golden fixtures do not exercise either shape**, so an implementation that changes them
  passes AC-2.
**Fix:**
1. R2 states the order:
   - resolve after `_bulk_add_concepts(concept_specs)`;
   - resolve in HEAD's walk order (node → rels → refs);
   - a target that is not cached and not in the store resolves to a concept minted earlier in the
     same doc (canonical or variant), as HEAD does;
   - the ADR slash fallback is part of the same batched read;
   - rel targets are in the batched read.
2. The anchor `_bulk_add_concepts` call is a SEPARATE call AFTER the unconditional one.
3. Mention links go in their own `bulk_link`, AFTER `link_batch`.
4. Add AC-2 fixture shapes:
   - a bare target equal to a body term;
   - `[[#x-y]]` followed by a bare `[[x-y]]` and a `rel: … -> [[x-y]]`;
   - a node linking an anchor named like its own title or body term (also the [[#m4]] collision).

### MEH m3: AC-2's dump rules are delegated where they need to be fixed {#m3}

- **Ids.** HEAD calls `add_concept` again on every repeated anchor, and each conflict attempt
  consumes a sequence value; the bulk call dedups. Ids of later entities therefore differ, so the
  dump must be keyed by `(kind, name)` with ids mapped to names, never raw ids.
- **Timestamps.** Exclude `created_at` / `updated_at` / `ts`.
- **Fragments.** Flush before the dump.
- **Anchors removed between versions.** Add a v1 → v2 fixture (an anchor and a wikilink removed),
  re-ingested through BOTH paths:
  - sync's `purge_path` removes the old node rows and their links;
  - the job path does not, so stale nodes persist at HEAD and must persist after.
