### BULLSHIT: the hub boundary swallows `ok:false` in every bus verb and in `queues`; `rmx bus pub` regressed from a named error to a bare `KeyError`; a hub timeout is a raw traceback {#b-1}

**File:** `src/refmatrix/verbs.py:1000-1004` (`_hub_rpc`: `hub_mod.rpc(op, args).get("result", {})`), `verbs.py:826-830` (`queues`: same shape), `src/refmatrix/cli.py:2202-2209` (`_bus_verb` catches `VerbError` only), `cli.py:2466-2474` (`hub_queues`, same)
**What:** The remedy fixed the `.get("result", {})`-on-`ok:false` swallow in `global_recall_rows` (#sk-7) and then migrated all ten `rmx bus *` commands plus the new `rmx hub queues` onto `_hub_rpc`/`queues`, which have exactly that swallow. A hub op that answers `{"ok": false, "error": …}` becomes `{}` in the verb; a socket error or timeout from `hub.rpc` propagates as a raw `OSError`/`TimeoutError` that neither the verb nor the CLI twin names.
**Why it's bullshit:** (1) Regression: at 8ba4799 `rmx bus pub` did `if not resp.get("ok"): raise click.ClickException(resp.get("error", "bus error"))` — the diff removes that line (six `if not resp.get("ok")` guards go out of cli.py) and the new twin does `r['message']['id']` on `{}`. Probe `workflow/review-output/pytest-bsd-plan3-r2-hubrpc.log`: with the hub answering `ok:false "bus is read-only"`, `verbs.bus_pub` returns `{}` (no `VerbError`), and `rmx bus pub global:t hi` exits 1 with **empty output** and `KeyError('message')`. `bus delete` on the same answer prints "not found"; `bus purge` prints "purged 0"; `hub queues` prints "no projects reported". (2) Observed live during this audit: `rmx hub queues` at 21:43:07 → 30 017 ms, `TimeoutError: timed out`, full Python traceback on the terminal (cli.log records it); the same path is under every `bus *` twin. On MCP the raw exception becomes an `isError` text `TimeoutError: timed out` — survivable, but the CLI is the surface an operator sees. This is the no-silent-failures constraint violated at the one process boundary the plan moved every bus capability across, and it is the finding-at-the-quoted-line shape from [[bsd-impressions#imp-fix-at-quoted-line]]: the swallow named in #sk-7 was fixed, its twin twenty lines away in the same file was not.
**Evidence:** `git diff 54fceb9..209270d -- src/refmatrix/cli.py | grep -n '^-.*resp.get("ok")'` → 6 removed guards; probe log above; `.refmatrix/cli.log` 21:43:07 `{"argv": ["hub","queues"], "exit_code": 1, "latency_ms": 30017, "error": "TimeoutError: timed out"}`.
**Fix:** `_hub_rpc` and `queues` raise `VerbError(resp["error"])` on `ok:false` and wrap `OSError`/`socket.timeout` from `hub.rpc` as `VerbError("hub rpc <op> failed: …")`; `_bus_verb`/`hub_queues` already convert `VerbError` to `ClickException`. One test per (a recorded `ok:false` at the process boundary is a legitimate fake here; register it under the existing `hub.rpc` row). Effort: minutes.
**Pattern match:** YES — [[bsd-impressions#imp-silent-memory]] (bus is not a memory path, but the constraint is project-wide) and [[bsd-impressions#imp-fix-at-quoted-line]] (2nd sighting).

### BULLSHIT (escalated, 3rd sighting): the verb layer calls a busy or starting daemon "not running", and the CLI twins dispatch on that string {#b-2}

**File:** `src/refmatrix/verbs.py:168-175` (`_call`: `if not daemon_mod.ping(root): raise VerbError(f"daemon not running for {root}")`), `src/refmatrix/search.py` (`federated_locate`: `roots = [r for r in discover_roots() if daemon_mod.ping(r)]`, per-store `except Exception: part = {}`), `src/refmatrix/cli.py:9151-9160` (`memory_get`), `cli.py:9137-9147` (`memory_add` → `_store()` direct write), `cli.py:8047-8052` (`ingest_status`), `cli.py:9801-9804` (`memory_recall` fallback) — all four match `"daemon not running" in str(e)`.
**What:** `discovery.daemon_status` (bug-006, plan-2) distinguishes *busy* (socket present, process alive, not answering) from *absent*. The verb layer's only liveness check is a bare `ping`, so every capability migrated in this diff inherits the conflation, and the CLI twins now string-match the verb's message to choose their fallback.
**Why it's bullshit:** Observed live, three commands in one two-minute window while the hub watchdog was kickstarting the refmatrix daemon (`hub.log` 21:44:14 and 21:45:54; `daemon.stderr.log` new pid at 21:44:16; `rmxd.log` loading the reranker at 21:44:17): `rmx ingest-status` 21:43:52 → exit 1 `daemon not running — ingest jobs are daemon-resident` (1 970 ms; pid 98982 was alive); `rmx memory recall --recent -k 1 --json` 21:44:24 → `daemon not running for …; reading the store directly` eight seconds after the new daemon started; `rmx locate verbs.py` → `no matches` because the store whose daemon did not answer the ping was dropped from the fan-out with no warning (once `daemon_status` reported `busy: False` the same call returned `/Users/tholley/claude_tools/refmatrix/src/refmatrix/verbs.py`). The write path is the sharp end: `rmx memory add` on a `daemon not running` `VerbError` opens `_store()` and writes directly — against a daemon that is merely busy that is a second writer on a held catalog, the lock-crash family in `workflow/bug_registry.md`. Pre-existing in `_call` since task 3.1 (I credited "daemon down now raises VerbError" in r1 without asking about busy); it is escalated, not regressed: [[bsd-plan2-hooks-reproducible-03f46b8]] (`--detach` guard), [[bsd-plan2-hooks-reproducible-r3-c9d75af#s-2]] (`focus summarize`), now the verb layer — the third sighting of [[bsd-impressions#imp-fix-at-quoted-line]] / bug-006's pattern, which the escalation rule (SKETCHY seen 3+ times) makes BULLSHIT.
**Evidence:** `.refmatrix/cli.log` rows at 21:43:52 and 21:44:24 (above); `~/.refmatrix/hub.log` `watchdog kickstarted /Users/tholley/claude_tools/refmatrix/.refmatrix` at 21:44:14 and 21:45:54; probe via the deployed module: `discovery.daemon_status(root)` → `{'up': True, 'busy': False, …}` then `federated_locate("verbs.py")` → refmatrix hit; earlier (during the restart) → `{'results': []}`.
**Fix:** `_call` classifies with `discovery.daemon_status(root)` and raises a distinct, typed condition for busy (`VerbBusyError` or `VerbError("daemon busy for …")`) that no CLI twin treats as absent — the `memory add` bootstrap fallback in particular must only fire on *absent*; `federated_locate`/`federated_where`/`federated_query` return a `skipped: [{root, reason}]` (or `warnings`) leg for stores that did not answer, and `rmx locate` prints it on stderr. Replace the four `"daemon not running" in str(e)` string matches with the typed condition. A test per surface using the pid-file + listening-socket simulation from plan-2 r3 ([[bsd-impressions#imp-socket-sim-probe]]).
**Pattern match:** YES — 3rd sighting; escalated per the ch-bsd escalation rules.
