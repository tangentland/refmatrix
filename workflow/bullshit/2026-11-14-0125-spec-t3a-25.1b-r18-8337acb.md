## Findings {#findings}

### BULLSHIT: AC-28's SessionStart / PreCompact "no daemon" leg requires a skip that this path never takes {#b1}

**The AC.** AC-28 (`:366-367`): "**Generated SessionStart and PreCompact recall commands:** both
print one skip line in the no-daemon setup."

**The code (`cli.py`).** On the `--session-start` / `--recent` path (`:12744-12775`), the verb's
`(VerbBusyError, VerbAbsentError)` is caught. `rs` = the hook's replica reader (`_replica =
_reader_store() if hook_mode`), else a reader only for a busy daemon. Only
`isinstance(e, VerbBusyError) and hook_mode` with no reader reaches `_degrade_or_raise`
(`:12771-12773`). A `VerbAbsentError`, which is the no-daemon case, ALWAYS falls through to
`rs = _read_store()` and prints a real pack from the store. Even `_left`'s deadline, raised
inside that `try` (`:12748`), lands on the replica when one exists. The d8 / AC-4 (c) skip is the
DENSE per-prompt path only: hub-only embedder, `VerbAbsentError(RECALL_ABSENT_MSG)` at
`verbs.py:1259` → `cli.py:12870-12872`.

**Why it's bullshit:**
- **The leg is RED for a reason that is not a defect.** In the no-daemon sandbox these commands
  print a pack, not a skip.
- **The only way to turn it green is a regression.** An unattended builder would make SessionStart
  and PreCompact skip when the daemon is down. That throws away the daemonless store read that
  25.1 kept on purpose, and turns a working SessionStart recall into an empty one. That is the
  very harm bug-224 is about.
- **R18 doesn't ask for it.** R18 asks for a skip LINE wherever a skip already happens, not for
  new skips.

**Fix:**
- Re-scope this leg to the setup in which these modes really skip: a busy daemon (held or
  stopped) AND no reader store. Assert one skip line there.
- Add a guard leg: in the no-daemon setup, SessionStart / PreCompact still print their pack and
  NO skip line. Mutation: "absent treated as a skip on the session-start path" makes the guard
  FAIL.

### SKETCHY: the five-cause map cannot be built from the exception TYPE that `rec.degraded` records {#s1}

**The spec.** R18 (`:270-272`): "ONE function maps the exception type to it, the same exception
that `rec.degraded` records". AC-28's unit table (`:368-370`) lists: "`VerbBusyError`,
`VerbAbsentError`, a worker-probe timeout, `ConnectionRefusedError`, `JSONDecodeError`".

**What actually reaches `rec.degraded(_raw_transport_cause(e))`:**

| raw exception | where it comes from | true cause |
|---|---|---|
| bare `VerbBusyError` (no transport cause) | `_left`'s deadline (`cli.py:12622-12628`) | budget spent |
| bare `VerbBusyError` | `require_daemon`'s busy ping (`verbs.py:216`) | daemon busy |
| bare `VerbBusyError` | `replica_memory_recall`'s deadline (`recall.py:1094-1095`) | budget spent |
| `TimeoutError` / `socket.timeout` | a DAEMON op timeout, under the classifier's busy (`verbs.py:265-276`, `raise … from e` `:287`) | daemon busy |
| `OSError` / `JSONDecodeError` | mid-request transport | transport error |
| `ConnectionRefusedError` | a refused connect after a good ping (`verbs.py:1255-1259`); the classifier calls it `VerbAbsentError` "daemon not running" | absent, or transport? |
| bare `VerbAbsentError` | d8, no daemon (`verbs.py:219` → `:1259`) | daemon absent |

**The problems:**
- **(a) Two causes share one type.** "budget spent" and "daemon busy" are both a bare
  `VerbBusyError`. A type-only map gives both the same cause, so AC-28's budget-spent leg (expects
  `budget spent`) and the table's `VerbBusyError` row cannot both pass.
- **(b) "worker timeout" never reaches the degrade path.** The shared-worker header
  `TimeoutError` is caught and logged inside the probe (`recall.py:446-452`). Any other replica-leg
  exception returns `None`, so the next leg serves (`:1098-1100`). The only `TimeoutError` that
  `rec.degraded` ever sees is a daemon op timeout. Mapping it to "worker timeout" mislabels a busy
  daemon.
- **(c) The refused row has no stated cause.** The mutation says a text map would read it
  `daemon busy`, but the spec never says which of the five a refused connect IS. The classifier's
  own words say absent, and the row's `outcome` is `error`.
- **(d) The budget-spent leg isn't deterministic.** With `--timeout 0.01`, the first `_left` call
  can still return a tiny positive remainder. The next dial then times out, giving a `TimeoutError`
  cause rather than the deadline, so which cause prints depends on timing.

**Fix:**
- Separate the causes by type:
  - `_left` and the replica deadline raise a subclass, e.g. `VerbDeadlineError(VerbBusyError)`.
    It still counts as `skipped_budget`, because `_budget_exception_types` matches subclasses.
  - Map that subclass → `budget spent`; bare `VerbBusyError` / `TimeoutError` → `daemon busy`.
- Drop `worker timeout`, or name the exception that carries it to this path.
- State the refused row's cause (recommended: `daemon absent`, which agrees with the classifier's
  words).
- Make the budget-spent leg assert on the deadline type, not on wall-clock luck.
- **On the argv deviation:** recording it is honest; `--timeout` is a real flag and no mock is
  used. But "no other way to spend the budget without a mock" overstates it: a held or stopped
  sandbox daemon spends it too. That setup tests `daemon busy`, which is exactly why the two causes
  need distinct types.

### MEH: R18 adds a stdout writer that R12's list and AC-26's structural check don't cover {#m1}

- **R12's list is now incomplete.** R12 (`:162`) enumerates "nine writer entries, which are nine
  functions" for AC-26's structural check. R18 makes the nested `_memory_recall_impl._degrade_or_raise`
  a stdout writer (the skip line), and it is on neither list.
- **AC-28's stated failure reason is wrong.** It says the mutation "printed with `click.echo`
  instead of `hook_budget.emit`" FAILS via "AC-26's structural check, and no command id on the
  row".
  - AC-26's check doesn't look at this function.
  - A ≤ 300 B line never cuts, so `emit` writes no `capped` row either way.
  - The mutation is still killed, but only by AC-28's own "`payload_bytes` equals that line's
    bytes", because a bare `click.echo` leaves `rec.payload` unset.
- **Fix:** add the skip writer to R12's list (and to the structural check, which must handle a
  nested `def`), and correct the FAIL reason.

### MEH: the "over 300 B" mutation needs a fixture that exceeds 300 B {#m2}

- The sandbox's classifier words are about 120-200 B (`RECALL_ABSENT_MSG`, `verbs.py:1060`, plus
  a short root). Removing the cut therefore changes nothing on AC-28's fixtures, and the mutation
  survives.
- A long sandbox root is not a fix, because it trips the AF_UNIX "path too long" branch instead.
- **Fix:** a unit leg on the line builder, fed classifier words over 300 B.
