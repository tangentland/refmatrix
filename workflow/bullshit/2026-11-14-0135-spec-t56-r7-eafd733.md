## Findings {#findings}

### MEH M1: AC-6's "fresh process" cannot see `_DERIVE_SRC_DIR` {#m1}

**File:** G22 AC-6, on-disk leg (task-dq1 `:393`): "The next `cached_adjacency` call (in a fresh process, so no instance cache) …".

**What:** `store._DERIVE_SRC_DIR` is a module global set in-process by tests (`store.py:783`). No environment variable carries it into a subprocess. A fresh process therefore hashes the REAL module tree, not the edited copy. That hash equals the old pair's key, because the copy began identical to the tree, so the stale pair is served and the AC fails on correct code.

**Fix:** drop the instance cache in the same process, either with a new `Store` instance or by clearing `store._adjacency_cache`, while `_DERIVE_SRC_DIR` still points at the copy. Alternatively, a subprocess runner that sets `store._DERIVE_SRC_DIR` before it calls `cached_adjacency`. `derive_code_hash`'s own cache keys on `(path, mtime_ns, ctime_ns, ino, size)`, so the edit to the copy invalidates it either way.
