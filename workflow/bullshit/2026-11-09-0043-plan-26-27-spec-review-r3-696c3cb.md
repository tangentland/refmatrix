## Findings {#findings}

### SKETCHY: 26.1 AC-9 says "exactly HEAD" and "no sidecar is created"; HEAD always creates one, and AC-4 still says every dir {#s1}

**File:** `task-26.1-layout-module-and-index-walk.md` AC-4, AC-9 (`#marker-gate`)

**What:** the spec says three things that cannot all hold.
- AC-9: in a dir without the marker, `write` "renders exactly as at HEAD … and it writes no new
  sidecar". The test asserts that "no `.memory_hooks.json` is created".
- AC-4: the id-keyed sidecar "Applies to EVERY dir".
- AC-9 also says the id-keyed sidecar is marker-gated.

**Why:**
- At HEAD, `write` calls `save_hooks` on every write (`memory_index.py:221`). The probe shows the
  sidecar going from absent to present.
- An implementation that is "exactly HEAD" therefore fails AC-9's test.
- An implementation that writes no sidecar regresses bug-050: folded entries lose their hooks, and
  the index is no longer idempotent on its own output.
- AC-4 and AC-9 disagree about which dirs get the id-keyed sidecar.

**Evidence:** [[#writer-walk]]; the HEAD probe.

**Fix:**
- An un-organised dir gets HEAD's render AND HEAD's path-keyed `save_hooks`.
- `load_hooks` reads both key shapes everywhere. That is a reader, so it stays dual.
- Scope AC-4's id-keyed write to organised dirs.
- Change AC-9's test to assert that the sidecar bytes equal HEAD's on the marker-off twin, not
  that the sidecar is absent.

**Pattern match:** YES, `imp-sort-key-granularity` (IMPRESSIONS): run the spec's own test through HEAD.

### SKETCHY: 26.8 AC-0 measures `refresh_pending` on a memdir COPY, so every row "disagrees" {#s2}

**File:** `task-26.8-refmatrix-live-rollout.md` AC-0, AC-2; `task-26.2-bridge-move-safety.md`
AC-3; `task-27.1-fleet-inventory.md` AC-6

**What:**
- The dev build copies the memdir and the store's read snapshot under `mkdtemp()`, then runs
  `ingest-gmd --as-memory --dry-run` against the copies.
- 26.2 AC-2/AC-3 count a row as pending when its stored resolved `source_path` disagrees with
  the file's resolved path.

**Why:**
- Every row in the snapshot copy stores the LIVE memdir path, and every file in the copy resolves
  under `mkdtemp()`. The measurement reports about 100% pending: it counts the relocation the
  copy made, not the refresh the deploy will cause.
- 26.8 AC-2 then expects the first marker-on bridge to equal this count, within ±5. Correct code
  fails that check, and the >50 stop fires on a false number.
- 27.1 inherits the number.

**Fix:**
- The dry-run writes nothing. Run it on the LIVE memdir path (a read-only walk) against the
  snapshot COPY of the store. The store copy is where the hard rule applies.
- Alternatively, give the dry-run a `--path-map <live>=<copy>`.
- Add a twin where the copy is relocated and nothing changed: it must report 0.
- Pre-register the expected count: rows with a missing `source_path`, plus symlink-path rows.

**Pattern match:** YES, `feedback_measure_the_path_users_run`.

### SKETCHY: 27.2a's "lossless checker" has no artifact, no RED case, and two branches it cannot verify {#s3}

**File:** `task-27.2a-index-prose-to-memories.md` AC-2, `#files`, `#test-strategy`

**What:** the checker "fails if any line's text is not found verbatim in some new memory, or
still carried in `MEMORY.md`".

**Why:**
- **No artifact.** Files lists no checker script and no test, only a log. Nothing can be
  reviewed, re-run in 27.6, or proven RED.
- **No RED.** The test strategy runs the checker on a copy. No AC plants a loss (one line dropped
  from a converted memory) and asserts that the checker fails and names the line.
- **The ADR-link branch has no verbatim target.** A block that "becomes a link to an existing ADR"
  leaves its lines nowhere verbatim. Either the checker fails on correct work, or someone
  weakens it later (a cheap fix waiting to happen).
- **Verbatim headers conflict with GMD.** 17 of viascope's 62 prose lines are headers, and none
  is anchored. Copied into a memory, a header needs `{#anchor}` to pass lint, and then it no
  longer matches verbatim. Several are grouping headers over ENTRY lines
  (`### Security & Operational Safety`), so "a header and its lines" yields a memory with no
  prose in it.

**Fix:**
- Put the checker in Files (for example `tools/` or `tests/test_prose_conversion.py`) with a
  committed fixture: a copy of viascope's prose block plus a converted set.
- RED: (a) one dropped line fails, naming it; (b) a header with an appended `{#anchor}` passes
  under ONE defined normalisation (strip a trailing `{#…}`, nothing else).
- The ADR branch either quotes the block verbatim in the memory, or the checker verifies the
  lines against the ADR file's text.
- Grouping headers with no prose stay carried.

**Pattern match:** YES, `imp-measure-the-if` (IMPRESSIONS): the step exists now, but its proof does not.

  (`feedback_mcp_server_reload_and_orphans`), so they write date-only `updated:` next to the new
  CLI's datetimes.

  date-only save lose.
- Rule: when either side is date-only and the dates are equal, fall to mtime. Add the mixed case
  to 26.3 AC-3.
