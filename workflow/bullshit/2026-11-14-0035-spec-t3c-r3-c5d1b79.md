## Findings {#findings}

### MEH: the runner never aborts on `arm_error` {#r3-m1}

**Files:** `task-28.1-session-arms-and-push-switch.md` R3; `task-28.2-paired-reentry-runner.md` R2.

R3 sends a bad as-of to "admit nothing" and a bad cell or run to `A+dedupe`, each with
`arm_error`. The runner aborts only when the SessionStart row shows the wrong cell, or for C,
any rmx hook row. A run with a valid cell but a bad `AS_OF` therefore continues with no memories
at all. In C, which has no hook rows, `arm_error` appears only on the pull calls' rows, which the
runner never checks.

**Fix:**
- The runner validates its three values with `paired_override`'s own parser before it launches.
- It aborts and excludes any run whose telemetry carries `arm_error`, counted per cell.

### MEH: the `as_of` verb argument's surface is not stated {#r3-m2}

**File:** `task-28.1` R4 and Files (`verbs.py` and the CLI/MCP adapters).

`as_of` becomes a verb parameter. The verb parity rules expect every verb parameter to appear in
the MCP schema (`tests/test_verb_parity.py:184-185`) or to be listed as having no CLI twin
(`:208-218`). As written, `as_of` would show up as an argument on the MCP tool in every session
across the fleet. The model could then pass a later `as_of` itself, or none.

**Fix:** State one of these in R4, and add an AC-9-style mutation for it:
- the adapters inject `as_of` from `paired_override` and it is kept out of the MCP schema and off
  the CLI, with its handling in the parity test named; or
- a model-supplied `as_of` is always overridden by the env value.
