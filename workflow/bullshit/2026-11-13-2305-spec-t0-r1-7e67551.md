### BULLSHIT: bug-155 is half-diagnosed, so AC-1.4 and the R7.5 clone twin cannot go green {#b-1}

**File:** `workflow/plans/task-t0-suite-trust-sweep.md:133-145` (cause), `:161-165` (R1.3),
`:186-191` (AC-1.4), `:624-626` (R7.5), `:748` (`#done`: "R7.4 and R7.5 are committed and clean").

**What:** the spec puts bug-155 down to one cause, the namespace (`project_name()` reads the dir name).
Its probe ran "over the same scope **and the main memory dir**" (`:134-135`).

**Why it's bullshit:** in a real clone the gate never has a memory dir.
- `scripts/lint-gmd.sh:41-51` adds `$HOME/.claude/projects/<clone-slug>/memory` only if that dir exists.
- `tests/test_gmd_lint_requires_version.py:125-131` copies that same slug's dir into a decoy HOME, and
  copies nothing when it is missing. The test's own comment says the refs "surface as dangling-doc, as
  the script intends".
- `ls ~/.claude/projects/-Volumes-littlebig-refmatrix*/memory` finds **zero** dirs, so no clone has one.

Reproduced in this clone (`refmatrix-spec-t0`, base `1cf3b9f`) over the script's own SCOPE:

```
python3 tools/gmd/lint.py CLAUDE.md docs/ workflow/ eval/ .claude/PROJECT_PROFILE.md
  -> 1084 errors: 1079 dangling-doc, 5 no-gmd-version   (exit 1)
   + ~/.claude/projects/-Users-tholley-claude-tools-refmatrix/memory
  -> 38 errors: 33 dangling-doc (32 adr/architecture + agent-brief-bsd-pop-r1), 5 no-gmd-version
```

So `project: refmatrix` removes 32 of the roughly 1,080 errors. The remaining ~1,046 are memory-id
refs (`[[project-queued-work]]`, `[[feedback_prefer_existing_infra]]`, …) and are unaffected. The
consequences:
- AC-1.4's "Its E line lists the 32 … It is green after R1.3. `./scripts/lint-gmd.sh` exits 0 in
  the clone" is false at both ends.
- R7.5's clone twin "exits 0" cannot pass, because this test fails in every clone.
- R7.6 then reads that failure as bug-155's "fix did not hold: it reopens", and the loop has no exit.
- T0's `#done` is unreachable.

**Fix:** bug-155 has two causes. The second, which clone has which memory dir, needs a design choice,
and no D-Q or L-row settles it, so it goes to the lead (open item **T0-O6**). The options, recommended
first:
- **(a)** `lint-gmd.sh` and the test resolve the memory dir from the checkout's **origin**. Every
  littlebig clone's `origin` is `/Users/tholley/claude_tools/refmatrix` (`git remote -v`), so they use
  that path's slug when their own slug has no dir. The test copies exactly that dir, as it does today.
- **(b)** An explicit `RMX_GMD_MEMDIR` override that the clone recipe sets.
- **(c)** Pin the test as clone-only. I recommend against it: it re-creates the blind spot T0 exists to
  remove, and R0.5 forbids it in spirit.

Whichever is chosen, AC-1.4's E-line count and M1.3 must be restated against a clone that has
resolved its memory dir.

**Pattern match:** YES. `imp-probe-real-dirs-not-fixture`: the probe ran under a condition the gate
itself never has.

### SKETCHY: the T0.3 bands do not support the stated confidence, and the harness cannot be built as written {#s-2}

**File:** `:271-282`.

1. **The confidence claim.** "At an unchanged 30% failure rate, 20/20 … p ≈ 0.0008" is correct
   arithmetic (0.7^20 = 0.0008), but the reproducer band does not establish 30%.
   - 3 failures in 10 has a 95% Clopper-Pearson interval of 0.067-0.652.
   - At p = 0.10, a 3/10 reproducer still appears 7% of the time, and 20/20 then passes by luck
     0.9^20 = **0.12** of the time. At the lower bound (0.067), 20/20 by luck is **0.25**.
   - Escalating 3 → 5 → 8 and keeping "the first level that reaches 3/10" is a selection on the
     maximum, which biases the estimated rate upward.

   The band can certify luck as a fix.
2. **The harness.** "Heaviest means the top files by `--durations` in the newest full-suite log on
   master." No committed full-suite log carries durations: `release-0.82.0-full.log` has 0
   `slowest … durations` lines, and none of `workflow/review-output/` does. The harness is undefined
   until R0 makes a durations run, and the spec does not say to make one.
3. **No time box.** Worst case is 3 bugs × (30 base trials + 20 post-fix) runs of 3-8 concurrent
   suites, unattended, with no time box.

**Fix:**
- Pre-register the post-fix N from the base estimate's lower bound: N = ⌈ln 0.05 / ln(1 − p_lo)⌉
  (for example, 3/10 gives p_lo ≈ 0.067, so N = 44). Alternatively, require ≥ 5/10 to call a
  reproducer and keep 20/20.
- Make R0 produce `--durations=25` over the full suite and fix the file list in the summary before
  trial 1.
- Add a wall-clock cap per bug. Exceeding it falls into the `not reproduced` band.
