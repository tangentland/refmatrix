## Findings {#findings}

### MEH m-1: a moved file's derived cut still freezes (the implementer's flag) {#m-1}

**File:** src/refmatrix/memory_index.py:363-374 (`_link_identity`)
**What:** the derived value is looked up only through the link's own path. When the file has moved and the sidecar has no value for it, `cur` is empty and an index `prefix…` wins. `hooks[mid]` then carries the cut to the moved Entry, and `save_hooks` freezes it as if it were curated. Probe `edge_moved.py` (session scratchpad): organised dir, no sidecar, the index line at `feedback_a.md` and the file at `feedback/feedback_a.md`. The sidecar gets a 176-char value ending in `…`, while the derived prose is 419 chars.
**Exposure:** none on live data today. Every dir that a write has touched has a full sidecar. cliquet and viascope have no sidecar, but they have 0 cut index hooks. The exposure opens in the move window of 26.4/26.5 if the organiser moves files in a dir with no sidecar before any render has run.
**Fix:** resolve the derived value by id when the path is gone: build `{id: path}` once from `memory_layout.iter_memory_files(memdir)` inside `load_hooks`, and have `_link_identity` fall back to it. Add `edge_moved.py` as a test. Otherwise the 26.4/26.5 spec names it as an AC.
