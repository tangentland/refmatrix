### SKETCHY: the daemonless re-probe runs on the request path, under the process lock, for up to PROBE_TIMEOUT_S {#s-1}

**File:** `src/refmatrix/recall.py` `_process_embed_client` (the `elif` re-probe branch) and
`reprobe_shared_client`
**What:** The daemon re-probes on its background tick, and its docstring says "never on a
request path". The daemonless copy runs inside the embed call, holding
`_EMBED_CLIENT_LOCK`, with `info(timeout=PROBE_TIMEOUT_S)` (default 45 s).
**Evidence:** Hub restarted then SIGSTOPped (it accepts connections and never answers):
two concurrent calls took **45.0 s and 89.8 s**, because the second waited for the lock and
then probed itself. The next call took 45.0 s again (`bsd-r3-probe-hung.log`, knob 2 s). At
the DEFAULT knob (300 s, probe timeout 3 s) the first two calls each paid the full probe:
3.05 s and 3.0 s (`bsd-r3-probe-hung-default.log`). The cause is
`_EMBED_REPROBE_NEXT.clear()` after a build. That build has just probed, failed and gone
private, and clearing the throttle tells the NEXT call to probe again at once. The comment
says the build "just made its own hub decision", and the code throws that decision away.
With the default 45 s probe, an `rmx mcp` started next to a wedged hub stalls 90 s across
its first two dense calls, and then 45 s per backoff window per serialized caller.
Mutation M11 (delete the clears) survives the S-1 test run alone, so nothing pins this
choice either way.
**Fix:** After a build that returns a private client, SET the throttle
(`next_at = now + base`, `backoff = base`) rather than clearing it. On the request path,
probe with a short bound (or `info(nowait=True)`) and leave the cold-worker 45 s probe to
`new_model_client`. Either way, a concurrent caller must not queue behind someone else's
probe: probe outside the lock behind an in-flight flag, and take the lock only for the swap.
Pin it with a mute-hub test: two concurrent calls each finish in under the probe bound plus
epsilon.
**Pattern match:** YES. imp-fallback-one-way-door: "diff it against the daemon's client
lifecycle". The diff copied the probe and left out the half that kept the probe off the
request path.
