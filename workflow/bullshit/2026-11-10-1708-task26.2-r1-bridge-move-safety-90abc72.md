## Findings {#findings}

### BULLSHIT b-1: the production forget path purges a moved memory's NEW anchors, and the gate then never restores them {#b-1}

**Predicate:** `src/refmatrix/sync.py:203-205`, inside `_sync_paths`:
`if should_ignore(ap, project_root): if s.purge_path(str(ap)) > 0: purged += 1; continue`.
`should_ignore` → `ingest._is_ignored` is True for any path segment starting with "." — `.claude` included.
`purge_path` (`store.py:6334`) deletes every entity in the active partition with `path = abs_path`, memory
anchors included. Post-0.5.0 the memory partition is the project partition (`_memory_partition_default`).

**Why it fires now:**
- `ingest_gmd.py:1451-1456`: in an organised dir, anchors now take `path=resolved_path`, the NEW path.
- `_memory_gate`: the next bridge skips when the hash matches and the stored source_path literally equals
  the path, so the purged anchors are never re-created.

**Production caller:** git post-commit `rmx sync --since HEAD~1` → `_op_sync_since` (`daemon.py:3912`) →
`sync_since` → `_sync_paths`. `git diff --name-only` lists a rename by its new path only.
- Viascope's memdir symlink resolves into its repo
  (`/Users/tholley/at/bdep/viascope/.claude/projects/-Users-tholley-github-atollogy-bdep-viascope/memory`).
- `git ls-files .claude/projects | wc -l` = 147.
- Its `.git/hooks/post-commit` runs exactly that sync.
- The watcher cannot reach a memdir (`watch.is_relevant` drops hidden segments), which is what
  `plan-26-memory-organisation.md:119` relies on. That premise is false for `sync --since`, `-f` and `-i`.

**Failing scenario** (probe on a throwaway mkdtemp store, library calls only, clone src confirmed by
`refmatrix.__file__`; log `26.2-bsd-r1-probe-postcommit.log`). Memdir at `<proj>/.claude/projects/slug/memory`
with marker `{"layout": 1}`, holding `a/x.md` (anchors x#root, x#one, x#two):
1. bridge → anchors at a/x.md
2. move a/x.md → b/x.md; bridge → `moved: 1`, anchors at b/x.md
3. `git add -A && git commit`; `sync_since(s, "HEAD~1", project_root=proj)` → changed = [b/x.md],
   `purged: 1`, anchors []
4. bridge → `skipped_unchanged: 1`, anchors stay [] permanently

- Marker-off twin (HEAD's hash-only gate): anchors stay at the stale a/x.md and survive.
- So 26.2 turns stale-but-alive into purged-forever for a git-tracked organised memdir.
- The edit variant (marker-off: edit, bridge, commit, sync) also ends with anchors [] and a skipping bridge
  (`26.2-bsd-r1-probe-postcommit-edit.log`). That loss is pre-existing and needs its own bug row; the same
  fix covers it.

**What the spec and summary say:** #rd-ac5-defect put "sync of the old path purges the moved memory's anchor
concepts" IN 26.2's scope. AC-5's test (`test_ac5_vacuum_and_sync_after_a_move_keep_the_row_and_its_anchors`)
syncs only the OLD path (`-f old`, `-i old`), with the memdir outside the project tree. Summary
#o-ac5-window calls the rest "not pinned … not built … a follow-up candidate". There is no task spec,
deferral row or AC behind it, which is unanchored under rule 9a. Pattern: imp-flag-needs-an-anchor (26.1 r4)
and the 26.6 r1 "summary hands work" bullet.

**Exposure:** nothing live yet; no git-tracked memdir carries the marker. It opens when plan-27 organises
viascope.

**Fix:**
1. (a) is the primary fix: `purge_path` (or the `should_ignore` and missing-path branches of `_sync_paths`)
   must not delete concept rows the memory bridge owns. Either exclude entities whose `path` equals the
   `memory_content.metadata.source_path` of a kind=memory row in the partition (resolved), or have the
   bridge stamp its anchors (e.g. `meta.memory_anchor = true`) and skip stamped rows. Count and print
   anything skipped, per #no-silent-failures.
2. (b) is optional defence: the path-aware gate re-ingests a file whose anchor rows are missing.
3. Correct plan-26:119, and add a bug_registry row for the pre-existing edit loss.

**Tests wanted:**
- (i) Memdir inside a git project under `.claude/`, organised: bridge, move, bridge, commit,
  `rmx sync --since HEAD~1` through the real CLI on a throwaway daemon. Assert the anchors survive at b/x.md
  and the next bridge still reports `skipped_unchanged`.
- (ii) The same with an edit instead of a move (marker on and marker off).
- (iii) `rmx sync -i <current path>` keeps the anchors.
- Mutation: remove the guard, and (i) and (ii) go RED.
