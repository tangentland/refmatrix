- An exit 2 on a persistent startup failure is a launchd respawn loop.
- The behaviour is no worse than before: the old startup path logged and continued with no reopen at all.
- The Store reconnects lazily on the first op, and `_store_health`'s `slot_bound` stays the surface that reports it.

### Writer close is undrained but serialized under `_store_lock` {#ruling-writer-close}

I agree, with one condition. The ruling holds only while every statement on the writer connection runs under `_store_lock`:
- read ops use their own read-only Stores, which are drained through `_swap_gate`;

A future lock-free op that runs on `d._st()` would reopen the 1.5.2 close-under-use crash for the writer.

## Findings {#findings}

### MEH m-r3-1: a copy2 swap failure leaves the merged catalog live without compacting facts.log {#m-r3-1}

**File:** `src/refmatrix/daemon.py`, the `_op_replica_merge` swap except branch, around :5735-5775.

**What:** the success path calls `d._compact_factslog_if_needed(force=True)`. Its own comment explains why: `merge_slots` writes the union with direct SQL and logs zero events, so facts.log still describes a pre-merge slot. The `installed_a` failure branch now does more than before:
- it reopens the writer on the merged A;
- it re-clones B from A;
- it returns, but it never compacts.

**Why it matters:** the store is fully post-merge but its log is not. A later `rebuild_index_from_log` would drop exactly the rows the merge recovered. This gap has existed since r1's b-2 remedy. r2's m-r2-5 fix makes the post-merge state complete, which makes the missing compaction matter more.

**Fix:** after a successful reopen in the `installed_a` branch, call `d._compact_factslog_if_needed(force=True)`. A failure should be logged and appended to `err`. Extend `test_copy2_swap_failure_reclones_b_and_keeps_the_writer` to assert that facts.log was snapshotted (for example, a compaction marker or the offset reset).

**Pattern match:** YES. A failure exit that skips a step the success path performs is the same shape as r1's b-2.

### MEH m-r3-2: the A1 widening misses a lowercase f-string ATTACH {#m-r3-2}

**File:** `tests/test_bug112_duckdb_reopen.py::test_every_file_attach_goes_through_attach_file`

**What:** the `leading = re.compile(r"^\s*ATTACH\s")` check is case-sensitive, to avoid matching prose. So `con.execute(f"attach {p!r} as x (TYPE SQLITE, READ_ONLY)")` in `migrate.py` passes all 21 tests (mutation A2 survives). DuckDB SQL is case-insensitive. No lowercase attach exists in `src/` today.

**Fix:** match `re.I` on the Constant that is the first value of an `ast.JoinedStr`, since prose is not an f-string head. Alternatively, require `ATTACH` followed by `{` or a quote in any case.

### MEH m-r3-3: two log lines name the wrong event {#m-r3-3}

**Files:** `src/refmatrix/backend.py` (`_close_stale_holders`) and `src/refmatrix/daemon.py` (the merge re-clone except branch).

**What:**
