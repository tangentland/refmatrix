## Answers {#answers}

1. **Write, lock, delete, rename, catalog or socket through the allow.**
   - The allow is checked only for the `open` event, and only when the event proves the open is
     read-only.
   - `_WRITE_FLAGS` covers `O_WRONLY | O_RDWR | O_APPEND | O_CREAT | O_TRUNC | O_EXCL`, and a
     mode containing `w`, `a`, `x` or `+` is refused. Unknown flags count as not read-only.
   - Probe (`probe_allow.log`): `O_RDONLY|O_CREAT`, `O_RDONLY|O_TRUNC`, `O_RDONLY|O_EXCL|O_CREAT`
     and mode `x` are all **denied**. A read of `catalog.A.duckdb` is **denied**.
   - `os.remove`, `rename`, `chmod`, `truncate`, `utime`, `link`, `symlink` and `shutil.copyfile`
     are separate events the allow never consults, so they stay denied (pinned by the RED guards).
   - `fcntl.flock` on a read-only fd of the spec is not audited, but nothing in production locks
     that file.
   - `openat` / `dir_fd`: the `open` audit event carries no `dir_fd`, so a bare `.refmatrix_ignore`
     opened relative to another directory is judged by its abspath. At worst that opens some other
     directory's file of the same name, which is configuration.
   - **One gap:** if the spec is itself a symlink when `build_deny` runs, `_variants` adds its
     `realpath`. The link TARGET then joins `read_allow`, and a direct read of it is allowed. See
     [[#m1]].
2. **Path normalisation.**
   - `_as_path` is `os.path.abspath`, so `..`, `//` and a bytes path all normalise to the spec and
     are allowed. A trailing slash on a file fails with ENOTDIR.
   - A lexically normalised path can resolve elsewhere only through a symlinked component. Inside
     the live `.refmatrix/` that symlink cannot be created (`os.symlink` is denied there). Elsewhere
     it is the sandbox's existing lexical model: the hook is pure and does no I/O, so the deny set
     has the same property for every path.
   - The allow does not widen that class, except through [[#m1]].
   - `/tmp` against `/private/tmp`: both variants are in the allow, through `_variants`.

## Findings {#findings}

### MEH M1: a symlinked spec puts its target into `read_allow` {#m1}

**File:** `tests/sandbox_site/rmx_sandbox.py` `read_allow` → `_variants`, which adds
`os.path.realpath`.

**What:** probe. The checkout's `.refmatrix/.refmatrix_ignore` is made a symlink to
`catalog.A.duckdb`. Then `read_allow` contains `['.refmatrix_ignore', 'catalog.A.duckdb']`, and
`violation("open", (<catalog>, "rb", O_RDONLY))` → **ALLOWED**.

The dev tree's spec is a regular file today (checked), and the live `.refmatrix/` cannot be written
under the sandbox. So this needs a symlinked spec made outside a test, for example a spec shared
across clones by link. The read is read-only.

**Fix (one line):** build the allow only from variants that are the spec itself:
`[v for v in _variants(spec) if os.path.basename(v) == ".refmatrix_ignore"]`. This keeps the
`/private/tmp` variant. Alternatively, return `[]` when `spec.is_symlink()`. Add one guard row:
"a symlinked spec allows no read of its target".

### MEH M2: `O_CREAT` / `O_TRUNC` / `O_EXCL` in `_WRITE_FLAGS` are not pinned {#m2}

**What:** mutation `_WRITE_FLAGS = O_WRONLY | O_RDWR | O_APPEND`, which drops the three flags that
can modify a file opened `O_RDONLY`. Result: **56 passed** across `test_bug230_repo_scope_gate.py`,
`test_sandbox_hardening.py` and `test_sandbox_refusal.py`; it **survived**. Every write-guard row
also carries `O_WRONLY` or `O_RDWR`.

`O_RDONLY|O_CREAT` creates the spec when it is absent, and `O_RDONLY|O_TRUNC` can empty it
(POSIX leaves that combination undefined; BSD-derived kernels truncate): both would be writes
into the live store directory.

**Fix:** add `(None, O_RDONLY|O_CREAT)` and `(None, O_RDONLY|O_TRUNC)` to the
`test_2a_guard_a_write_open_…` parametrize. Both fail under the mutation.
