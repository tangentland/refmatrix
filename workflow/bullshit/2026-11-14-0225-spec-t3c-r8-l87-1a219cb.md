## Findings {#findings}

### MEH: `keep push` and `shrink` can both hold, and no order is stated {#m1}

**File:** `plan-28-handhold-outcome-experiment.md:177-181` (the push table); 28.3 R9; 28.4 R2.

The two conditions overlap:
- `keep push` holds when some lower bound is above 0;
- `shrink` holds when every upper bound is below δ and A costs more.

A small but real benefit, with 0 < lower bound and upper bound < δ, satisfies both. The table
and R9 do not say which wins. An unattended `readings.py` would pick one silently.

**Fix:** State the order in plan-28, 28.3 R9 and 28.4 R2. My recommendation is "rows are read
in order; the first that holds is the reading", with `keep push` first, because push stays when
it measurably helps. Add a row to AC-8 for the overlap case.

### MEH: churn's W = 10 tool calls is the spec writer's own value {#m2}

decision row records it, the spec leaves an open choice for an unattended 28.4 to freeze.
