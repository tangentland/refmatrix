### SKETCHY: the ONE "newest" key uses date-only fields and picks the session STARTED last, not SAVED last {#s3}

**File:** `task-26.1#requirements` AC-1 (`iter_savestates`), `task-26.3#requirements` AC-3
**What:** Newest-first ordering is by frontmatter `updated`, then `created`, then mtime.
**Why:**
- `handoff.py:153-154` writes `created:`/`updated:` as `YYYY-MM-DD`.
- Two save-states updated the same day tie on `updated`, so `created` decides.
- Construct:
  - Session A is created 11-07 and re-saved 11-08 at 23:00.
  - Session B is created and saved 11-08 at 15:00.
  - The new key picks B. HEAD (mtime) picks A, the last save.

  (refmatrix 31 days, cliquedb, thiquet). The ordering is untested, not safe.
- The cliquedb-shape test (an older `updated:`, a newer mtime) passes under either key.

**Fix:**
- Order by `updated`, then mtime. Drop `created` as a tie-breaker.
- Or write `updated:` as a full timestamp (MEMORY-RULES allows it).
- Add the same-day-two-sessions case to 26.3 AC-3, with the mutation "`created` before mtime".

**Pattern match:** YES, `feedback_check_the_sibling_condition`: S2's fix replaced one key and

### SKETCHY: 26.5 AC-7's rollback steps contradict each other, and its own test fails under either reading {#s4}

**File:** `task-26.5-memory-organise-verb.md#requirements` AC-7
**What:**
- Step 1 moves aside every current file whose bytes differ from its archived copy, or that is
  absent from the archive.
- Step 2 then lists same-id pairs and by default "keeps the current file".

**Why:**
- If step 1 is path-keyed, every moved file is "absent from the archive" and goes aside. The
  archive's older top-level save-state is then restored, and recall-state resumes the OLD handoff.
  That is S4 itself.
- If step 1 is id-keyed, the re-saved save-state differs from its archived copy and goes aside.
  Step 2's "keep current" then has nothing to keep, and "do not restore the archive copy" leaves
  NO copy of that id in the memdir.
- The AC's own test ("recall-state still resumes from the re-saved handoff") fails either way.

**Fix:** define the rollback per id.

| current file vs. archive | action |
|---|---|
| same bytes as the archive | move back to the archive path |
| differing bytes | stays at its current path, listed as a conflict; the archive copy goes to the aside dir, unless `--prefer-archive <id>` |
| absent from the archive | stays, and is listed |

The asides stay under `~/.refmatrix/backups/`.

**Pattern match:** NO.
