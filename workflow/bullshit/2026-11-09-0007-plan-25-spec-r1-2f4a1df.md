### SKETCHY S9: several of R1's translation rules disagree with both greps {#s9}

**File:** [[task-25.4-grep-bre-translation#r1]], `#r2`, AC-2.

**Evidence:** BSD and GNU agree on each case below unless noted.
- **Word anchors.** `\<` / `\>` → `\b` is wrong: `\>a` matches nothing in either grep, while
  `\ba` matches `ab`. Use `\b(?=\w)` and `\b(?<=\w)`.
- **Backslash in brackets.** A backslash inside a bracket is literal in POSIX: `[\.]` matches
  `back\slash` and `a\b` in both greps. R1 copies brackets verbatim, so Python reads `[\.]` as dot
  only. `[a\]` raises `re.PatternError: unterminated character set` in Python.
- **Nested-set warnings.** `[[:digit:]]`-style text and any `[` inside a set raise FutureWarning
  (nested set) in Python, and so do `&&`, `--`, `||`, `~~`. These must be escaped.
- **`-o` with alternation.** `-o`, which the stdin leg supports, uses leftmost-longest matching in
  both greps: `echo ab | grep -o 'a\|ab'` prints `ab`. Python prints `a`. `-o` is missing from
  AC-2's flag list.
- **`-w` / `-x` grouping.** The wrapping is ungrouped: the file leg builds `\b{p}\b` and `^{p}$`
  (`cli.py:6450-6453`), and the stdin leg groups only `-x`. A translated `a|b` becomes `^a|b$`.
  This repeats the prior order/grouping findings. R2 must require `(?:…)` on every leg.
- **Missing divergence row.** `a\{,1\}b` (BSD exits 2, GNU matches) is not in AC-2. Say what rmx
  must do there.

**Fix:** Amend R1 and R2 with these rules. Delegate `-o` or colour together with alternation to the
real grep (R3). Add the six cases to AC-2 and AC-7.
