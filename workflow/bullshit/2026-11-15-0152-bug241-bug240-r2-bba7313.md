**`last_ingest_result` as the carrier: sound for its one reader.**
- `_store(write=True)` builds a fresh `_DaemonWriter` per call.
- `_DaemonWriter.ingest_path` assigns the attribute before returning, and `_ingest` reads it on
  the very next line of the same call. The CLI is single-threaded.
- If the RPC raises, `_call` raises `ClickException` before the assignment, so nothing reads a
  stale value.
- A second ingest on the same proxy overwrites it before the next read.
- It is never read by the verb or MCP route, which uses a different op (`ingest_path_start` → a
  job; see [[#m2]]).
- Two nits, not filed:
  - The attribute is not initialised in `__init__`. A read before assignment would fall through
    to `_DaemonWriter.__getattr__` and be forwarded to the reader Store. Set
    `self.last_ingest_result = {}` in `__init__`.
  - The daemon measures the failure as a delta on one long-lived store counter. A second
    `ingest_path` interleaving at a yield could have its failures counted in the first op's
    delta. Concurrent whole-path ingests are not a production pattern.

## Findings {#findings}

### MEH M1: the GMD pass yields on the code passes' cadence (200 docs), not the GMD op's (1 doc), leaving 10–15 s unyielded stretches {#m1}

**File:** `ingest.py` `_ingest_path_inner`, which passes the daemon's `yield_every`
(`RMX_INGEST_YIELD_EVERY_UNITS`, default **200**, tuned for cheap per-file code units) to
`_ingest_markdown_gmd`. The daemon's own GMD op (`_run_ingest_gmd_body`) uses
`RMX_INGEST_YIELD_EVERY`, default **1 doc**. Inside a doc, `ingest_gmd_paths` also ticks every 200
node-ops.

**What:** probe `gap_probe.py`, which runs `ingest_gmd_paths` with a recording yield hook over a
copy of `docs/` and `workflow/plans/` (211 docs, load about 6.4, fresh store per run):

```
yield_every=200: 211 docs, 120.3s, 40 yields,  max gap 15.04s, p95 9.93s
yield_every=  1: 211 docs, 120.6s, 460 yields, max gap  5.44s, p95 1.29s
```

The total time is the same. Per-doc yielding cuts the longest lock hold from 15 s to the single
costliest doc (5.4 s), and the p95 from 9.9 s to 1.3 s. green-216's 40 yields over 96.6 s with a
max stretch of about 12 s is the same pattern. The residual stretches are what remains of r1 S1:
seconds now, where r1 measured a single 17-minute hold.

**Fix (one line):** use the GMD op's cadence for the GMD pass, not the code-unit cadence. For
example, in `_ingest_path_inner` and `_ingest_tree` pass
`yield_every=int(os.environ.get("RMX_INGEST_YIELD_EVERY", "1") or "1")` to `_ingest_markdown_gmd`
(or let it use its own default and stop inheriting). Tighten the S1 test to also assert that at
least one yield falls per doc once the markdown phase starts.

### MEH M2: on the MCP / verb route a failed GMD pass ends the job `done` {#m2}

**File:** `daemon._run_detached_job` (`job["status"] = "done"`, `job["result"] = result`),
reached by `_op_ingest_path_start`, which `verbs.ingest` (`rmx_ingest`) calls.

**What:** S2 made a failed GMD pass an `Error:` with a non-zero exit on both CLI routes. The agent
route runs the same `_op_ingest_path` inside a detached job. The job flips to `done`, with
`gmd_pass_failed` sitting inside `result`. An agent polling `rmx_ingest_status` reads `status: done`
unless it inspects that field.

The live `rmx reingest` uses the blocking CLI route, so the deploy is not exposed.

**Fix:** in `_run_detached_job`, or in a wrapper for the ingest job, set `status = "error"` and an
`error` naming the GMD pass when `result.get("gmd_pass_failed")`. Alternatively keep `done` and
add a top-level `warning`. Either way, a test drives the bad-frontmatter tree through
`rmx_ingest` and `rmx_ingest_status`.
