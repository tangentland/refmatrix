## BULLSHIT {#bullshit}

### b-1: `rules replay` reports a false "hits 0" for any bind on a `tool_input` key the ring never stores {#b-1}

- **File:** `src/refmatrix/instructions.py:996` (`_ring_call`), `:1014` (`replay`), `:1100` (the limits line).
- **What happens:** replay rebuilds `tool_input` from the ring's `detail` field.
  - The ring writer `cli._tool_event_fields` (`cli.py:2386-2393`) keeps only `command` for Bash.
  - For every other tool it drops `content`, `new_string`, `old_string` and `edits`.
  - D1 names `new_string` and `content` as match keys. A unit bound to them can never get a hit, and the limits line doesn't say so.
- **Evidence:** `probe_replay.py` wrote a real `_tool_event_fields` Write event whose content contains `rm -rf`, then replayed a deny that matches `content` against `rm -rf`. Output:
  - `detail: {"file_path": "/x/a.py"}`
  - `scanned 1 tool events; hits 0`
  - a limits line that lists DETAIL_MAX, `who`, `when` and `where`, but nothing about dropped keys.
- **Consequence:** replay is the measurement the lead runs before a deny ships (L234 names "the 30-day replays over live STM rings" as a lead-only step). For Write/Edit-bound units, and for Bash binds on any key other than `command`, it silently reports a zero. That is a skewed measurement the release relies on.
- **Fix:**
  - Per bind, compare its `match` keys with the keys the ring carries for that tool (Bash → `command`; other tools → `tool_input` minus the four dropped keys).
  - Print `unmeasurable: bind[i].match.<key> is not stored in the ring` and leave that bind out of the hit count.
  - Pin it with one replay case: a Write unit bound to `content`.
- **Self-audit question that missed it:** SA-3, the census of every other output of the same data. The ring writer is the other output of `tool_input`.

  - No packaged units exist yet. This becomes live with I1.c.
- **Fix (about 5 lines):**
  - In `load_layers`, refuse a unit whose kind's `KIND_DIR` is not the directory it sits in (for packaged units, the directory under `practices/<name>/`), and add one AC-2 case.

### s-2: the fixture prefilter test uses a different serialization from the dispatcher {#s-2}

- **Where:** `instructions.py:931`.
- **What it does:** it tests containment in `json.dumps(env)`. That uses Python's `", "` / `": "` separators, and runs after `cwd` has been rewritten to the temp directory.
- **The mismatch:** I1.b3 D2 tests the raw stdin bytes in bash. A prefilter that spans JSON structure (for example `"command": "rm`) can pass the fixture and never match live, or the other way round. I found no captured raw envelope in the repo to settle which separators Claude Code sends.
- **Fix:** either refuse prefilters containing `"`, `\` or `:` at compile, or test both compact and spaced forms. If handed to I1.b3, it needs an AC there.

### s-3: a local unit named like a packaged trigger or check is silently dropped {#s-3}

- **Where:** `instructions.py:540`.
- **What happens:**
  - `load_layers` skips any local file whose path equals a packaged path, including triggers and checks, which are never installed.
  - `--apply` exits 0 without compiling the local unit.
  - `--check` then reports drift and says `--apply --force`, which doesn't install triggers. That is a loop with no way out.
- **When it matters:** this is latent until I1.c ships packaged denies.
- **Fix:** skip only when `pf.installs`. Otherwise refuse with "duplicate path with a packaged unit".

### s-4: the `--check` fixture leg has no total bound (known going in; rated) {#s-4}
