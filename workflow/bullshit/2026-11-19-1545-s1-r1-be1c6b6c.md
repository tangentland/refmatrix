## Findings {#findings}

### BULLSHIT: the fragment-file code S1 kept or added has no test; MX4 and MX5 survive {#b-1}

**File:** `src/refmatrix/store.py:4321-4331` (`_unread_fragment_dirs`, new), `:4492`, and
`:1422`/`:1425` with `:2074-2140` (the two kept `_migrate_*` moves)

**What:** GREEN kept the two `_connect` file moves because they are reached on DuckDB. GREEN
also replaced the SQLite repair arm's report with a new `_unread_fragment_dirs`, which changes
DuckDB behaviour: `repair_fragments` / `rmx repair-fragments` used to return `unread_dirs: []`
on DuckDB and now list every `fragments/` subdir (the CLI prints them at `cli.py:4716` and
`:10147`). RED had already deleted the only tests of both paths, because the spec said R3
deletes them:

- `test_v2_features.py::test_legacy_per_concept_bitmaps_migrate_to_fragments`, the only test of
  `_migrate_legacy_bitmaps_if_needed`;
- `test_fragment_repair_audit_r4.py::test_cli_repair_lists_unread_dirs`, the only test of the
  unread-dirs report.

Nobody reconciled the deletions with the keep. The summary's `#kept-moves` does not mention
that the tests went.

**Why it's bullshit:** this is live `src/` code with no test that can fail. MX4 (the report
always empty) and MX5 (neither move runs) each pass 168 tests across every
fragment/partition/repair file. The only remaining reference,
`test_fragment_repair_audit_r4.py:164`, checks that the log line contains the text
`unread_dirs=`, so it passes with `[]`. This fails the large-change gate: every mutation on the
`src/` change must fail a test ([[claude#before-commit]], [[claude#test-discipline]] rules 3
and 7). It also touches the silence question: the report that names data the store is not
serving went from tested (SQLite) to untested (DuckDB).

**Evidence:** `bsd-s1-mx4.log` and `bsd-s1-mx5.log` (168 passed each). The probe
`test_probe_repair_fragments_unread_dirs_on_duckdb` shows the live behaviour: a
`bitmaps/mentions/<cid>.rb` becomes `fragments/proj/mentions.rb64`, the `.rb` file is deleted,
`load_bitmap` returns `[]`, and `unread_dirs` names `fragments/proj`.

**Fix (small):** follow [[#s-1]]. Delete the moves, then add ONE test through
`rmx repair-fragments` on a DuckDB store with a planted `fragments/<p>/x.rb64`, asserting the
dir is named and left in place, so MX4 dies. If the lead keeps the moves instead, re-point the
two deleted tests to DuckDB so MX4 and MX5 die. Confirm-lite: re-run MX4 (and MX5 if kept) on
the lane.

**Pattern match:** NO prior impression. New shape: RED deleted tests because the spec said the
code goes, then GREEN kept the code, and nobody reconciled the two.

### SKETCHY: the two kept `_migrate_*` moves are dead in effect on DuckDB {#s-1}

**File:** `src/refmatrix/store.py:1422`, `:1425`, `:2074-2140`; helpers `_fragment_path`
(`:4217`), `bitmaps_dir`, and the `fragments_dir` arms in `rename_partition` (`:1569`),
`merge_partition` (`:1914`) and `rebuild_index_from_log` (`:8434`)

**What:** GREEN's caller proof is literally true. Both moves run at the end of every writer
`_connect`, on both backends at the base. But the test was the wrong one. Their only product
is `fragments/<partition>/*.rb64` files, and since S1 nothing reads that layout: no load, no
repair, and no converter (`migrate.py` is gone). On DuckDB they turn one unread layout into
another and delete the originals. The base authors called it "SQLite-only legacy migration"
(the deleted test's comment). R3's intent was to delete them. The "one that has a caller stays"
clause was meant to protect real DuckDB consumers, not stat-and-return no-ops. No fleet store
has `bitmaps/` or `fragments/`, and a real legacy store is converted by the 0.84.0 command the
refusal names. That converter reads `fragments/` itself.

**Why sketchy, not bullshit:** it is disclosed (`#kept-moves`, `store.py:1159-1166`) and fits
the letter of R3. Its cost is two `exists()` stats per writer open, plus [[#b-1]].

**Fix (recommended in the fold):** delete both moves, `_fragment_path`, `bitmaps_dir` and the
`fragments/` arms in rename, merge and rebuild. Keep `_unread_fragment_dirs`, which is now the
honest residue: it tells the operator about a dir the store does not serve. This shrinks
[[#b-1]] to one test.
