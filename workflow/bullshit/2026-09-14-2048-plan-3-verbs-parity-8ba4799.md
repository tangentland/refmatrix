**File:** `src/refmatrix/verbs.py:870-905` (`CLI_MAP`), `tests/test_verb_parity.py:76-83`, `src/refmatrix/cli.py`
**What:** Task 3.3 (`task-3.3-plan-3-verbs-parity#files`) specifies "every verb has a CLI command that calls it (mapping table in verbs.CLI_MAP, asserted)". The summary claims "every verb has a CLI twin … and the click path resolves".
**Why it's bullshit:** The only CLI code that calls a verb is `projects` (`cli.py:7464`) and `memory recall` recent/subject modes (`cli.py:9685`). Every other `CLI_MAP` twin implements the capability itself: `memory get` (9072) opens daemon/`_read_store` directly, `locate` (7370) calls `federated_locate`, `ingest-status` (7949) calls `daemon_mod.call`, `recall-state` (10726) builds `Stm` + `handoff` itself, the nine `bus *` commands, `task *`, `hub status`, `context`, `query`, `save-state`, `focus *`, `memory add`, `ingest` — none touch `verbs`. **Evidence:** `RMXGREP_MODE=plain grep -nE "_verbs\.|verbs\.|VERBS\[" src/refmatrix/cli.py` → 3 call sites (7464, 9664, 9685); `git diff 03f46b8..8ba4799 -- src/refmatrix/cli.py` touches only `memory recall` helpers.
**Fix:** Either make the named click commands call `verbs.<name>` and render (the plan's own decision Q1 for recall, generalized), or rename the test/summary to what it proves ("path exists") and file the real wiring as a task with acceptance criteria. Rule 10: interface narrowed from "calls it" to "exists".
