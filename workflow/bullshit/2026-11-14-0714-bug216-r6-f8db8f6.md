## Answers to the lead's points {#answers}

1. **The `re_embed` definition is exact.** `vector_rows` holds only these ids:
   - each move's old id X and new id Z;
   - every A loser's vacated id;
   - every B loser's vacated id. `remap_b`'s keys include the moves' old ids, and UNION dedupes
     them.

   An A loser's id is never a move's old id, because the fresh loop skips ids in `remap_a`. It is
   never a move's new id either, because those lie above `max_entity`. A B name-loser's id is
   never a move's old id, because the loop skips ids in `remap_b`. So
   `vector_rows ids − {X, Z of every move}` is exactly the set of name-loser vacated ids.

## Findings {#findings}

### MEH M1: the purge path deletes nothing and says nothing when `lance` is not installed but the table exists {#m1}

**File:** `src/refmatrix/store.py` `_lance_for_purge` (returns None silently when
`find_spec("lance") is None`), reached by:
- `_drop_lance_for_purge` (single id; its docstring calls this "quiet only when there is nothing to
  delete");
- `_drop_lance_for_purge_batch`, which reads only `deleted` from `_delete_vector_groups`.

Both callers check `path.exists()` first, so whenever this branch is hit there IS a table with
rows to delete.

**What:** probe `probe_purge_no_lance.py`. Three memories with vectors, and `find_spec("lance")`
patched to None:

```
batch returned 0 | single returned False | vector_delete_failures: 0
stderr: ''
rows left in memory.lance: [1, 2, 3]
```

The purged memories' vectors stay behind as orphans, with no print and no count. On a memory path
that is an uncounted skip ([[claude#no-silent-failures]]).

**Why MEH, not higher:**
- It predates bug-216 (it was "quiet" before r4 as well).
- It needs a `.lance` table written by an interpreter that has the `[dense]` extra, then a purge by
  one that does not. Both workstation venvs have `lance` (checked: deploy `True`, dev `True`).
- The orphans are reaped by `rmx embed --gc`, though that also needs `lance`.

**The one-line form that can ride:** in `_lance_for_purge`, before `return None` on the
`find_spec` branch, add

`self._note_vector_delete_failure(kind, n, ModuleNotFoundError("lance is not installed (no [dense] extra) but the vector table exists"))`.

Every caller has already confirmed the table exists, so the note is always true. Every purge path
and the merge then print and count it. The merge also keeps its `errors` entry.

Then correct `_drop_lance_for_purge`'s docstring, and pin it with this probe.
