### MEH M1: AC-10's concurrent resolver calls a function this task rewrites {#m1}

**Where:** `task-bug185-bulk-gmd-ingest.md:747-749`, "through bug-216's per-row
`resolve_pending_refs`".

**Problem:** `[[#files-list]]` rewrites `resolve_pending_refs` onto R8 (b)'s batched shape, so no
per-row resolver survives GREEN.

**Fix:** simulate the other writer with the surviving real APIs, `Store.delete_pending_ref` +
`Store.link` + `Store.add_evidence`. Alternatively, use the rewritten resolver on a second
`GmdBatch`. The mutation, "link every cached row instead of the `RETURNING` set → two evidence
rows", still fails either way.

### MEH M2: the signature is defined in semantic terms, but the entry and AC-15 use storage terms {#m2}

**Where:** `:469` defines the signature as `(linkage, source kind, target kind)`. The pinned entry
(`:471-482`) and AC-15 match on `(linkage, concept kind, entity kind)`.

**Problem:** for `memory_link` today, the semantic source (the memory `m`) sits on the ENTITY side.
That is exactly the confusion that produced r2's wrong `(memory, memory)` entry.

**Fix:** define the signature as `(linkage, concept-side kind, entity-side kind)` at `:469`.

### MEH M3: the bounded census lost its verb condition and excludes only pass 2 {#m3}

**Where:** `:453-458`. The census counts any producer "able to write an edge whose CONCEPT side is
a GMD entity", and the exclusion covers only "this document's own pass-2 write set (steps 5-7)".

**Problem:** read literally, the census catches bug-185's own pass-1 ADR alias link,
`store.link("same_as", doc_eid, slash_eid)` (`b216_ingest_gmd.py:1541`). That link writes no
evidence, so it would be classified no-evidence-in-reach. AC-14 (a) would then give it an evidence
row. That changes `linkage_evidence` on AC-2's shapes fixture (`:563`, "an ADR slash alias")
against HEAD's golden, which is R3 (a).

**Why it cannot collide anyway:** `same_as` can never be a `rel:` verb. `_REL_RE` allows only
`[a-z][a-z0-9-]*` (`b216_ingest_gmd.py:160`), and `_VERB_ALIASES` maps only `related_to`.

**Fix:**
- restore the verb condition: the linkage can be a `rel:` verb (`[a-z][a-z0-9-]*` after
  `_canonical_verb`) or is caller-supplied (`*`);
- widen the exclusion to the document's WHOLE own write set (the pass-1 doc-level writes plus
  steps 5-7).
