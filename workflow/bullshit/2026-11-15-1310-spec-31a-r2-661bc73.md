## Findings {#findings}

### M1 MEH: the AC-0.17 fallback is a release, not a switch, and has no stop row {#m1}

**Evidence:**
- [[task-31.5-scan-prompt-block-measure#ac-0-17]]: if the live p95 misses the band, "the
  cheaper path ships as a follow-up release (A.1)". Release A builds only one path; AC-0.3
  asserts `not_built` only "if the bands select the cheaper path".
- Master `8efaed4` makes that contingency a **major** release, R1.1, "it changes a hook's
  output". The cheaper path does not change the payload: AC-0.4 proves the payload is
  byte-identical.
- Until R1.1 ships, every prompt pays the measured overrun.
- There is no live row for "over 750 ms on the cheaper path".
- **`661bc73` contradicts the POP.** Its `#files-release` says A.1 "is a ninth gate that plan
  does not hold; the lead schedules it". Master `8efaed4` already holds it as the contingent
  R1.1 (`#queue-releases-contingent`). The spec should cite that row.

**Fold:**
1. On an AC-0.17 miss, the lead first creates `injection-capture.off` in this store. That turns
   off the capture only, pauses the window, and keeps telemetry on.
2. Either build both paths in release A behind one setting, so the fallback is a setting
   change; or keep R1.1 and correct the POP's reason for calling it a major.
3. Add the live stop row: if the cheaper path's p95 is still over 750 ms, the capture stays off
   and the lead gets the profile.
4. Point `#files-release` at the POP's R1.1 row instead of saying the plan does not hold it.

### M2 MEH: the cost method does not name the binary that runs the hook's command {#m2}

**Evidence:**
- [[task-31.5-scan-prompt-block-measure#r0-5-method]] step 2 runs "the generated `scan_cmd`'s
  scan-prompt command line". That line is `rmx scan-prompt …` after `HOOK_ENV`, which puts
  `$HOME/bin` first on `PATH` (`hooks.py:61`).
- With `HOME` redirected, `PATH` resolves `rmx` to whatever comes next, which can be the
  deployed build. That build has no capture, so both arms would time the same code.

**Fold:** run `.venv-eval/bin/rmx` with the hook's arguments, never a bare `rmx`. Record
`rmx version -v` from that exact binary in AC-0.13's summary.

### M3 MEH: ".gitignore before its first append" should be "before every write, if absent" {#m3}

**Evidence:** the B1 probe shows that without the inner file, both `capture-*.jsonl` and
`errors.jsonl` show in `git status`. The spec creates the `.gitignore` "before its first
append". A directory that already exists without one would be written into unprotected: for
example after a crash between `mkdir` and the `.gitignore` write, or when `errors.jsonl` is
the first file written.

**Fold:**
- Before every write into the directory, check that `.gitignore` exists and create it if not.
  It costs one `stat`.
- AC-0.15 gains a case: the directory exists without `.gitignore`, then one call is made.
- Mutation M0-10 gains a second step: the guard runs only when the directory is created.

### M4 MEH: the per-item tighten was the plan's own "kept and tightened", not new presentation; record the cut where the plan says it {#m4}

**Evidence:**
- [[task-31.5-scan-prompt-block-measure#actions-removed]] removes two actions as "new
  presentation" sent post-mod. For the **pointer-line render** that is right. The plan never
  asked for it, and dropping it is a scope cut the freeze allows.

  user's "tighten what it injects" ([[plan-31-pre-mod-loose-ends#t5-ask]]).
- My r1 M10 called both "new presentation". That was wrong for the tighten. L133 then adopted
  the report's proposal.
- The cut is allowed: S7 offered "tested or dropped", and the user's ask is still met by the
  member filter and the shrink knobs. But the plan text and the spec now disagree, and the

**Fold:**
- Correct `#actions-removed`: the tighten is dropped because it had no knob or test, not
  because it is presentation.
- Amend the plan's band line to "kept; tightened only by the member filter (R2.0) and the
  shrink knobs".
- The lead records the cut in the L133 row, so the user can see the plan's "kept and tightened"
  became "kept".

### M5 MEH: the gate-tree bypass scan and the declared-file check have one blind spot each {#m5}

**Evidence:**
- [[task-31.3-ledger-anchor-guard#r6-bypass]] scans `tests/*.py` for lines that copy
  `lint-gmd.sh`. It does not look in `tests/**` subdirectories, and it does not catch a
  `copytree` of `scripts/` or `tools/gmd/`.
- AC-9's `test_every_file_the_gate_runs_is_declared` reads only the `"$ROOT/…"` paths the
  wrapper assigns. 31.6's `tools/gmd/resolve.py` is imported by `lint.py`, not named by the
  wrapper, so a missing `gate-file` line for it would pass AC-9. Each copied tree would then

**Fold:**

  `lint.py`'s `import resolve` then has to be declared.
