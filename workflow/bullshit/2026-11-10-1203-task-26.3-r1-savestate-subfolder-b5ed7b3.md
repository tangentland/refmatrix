## Findings {#findings}

### SKETCHY s-1: the pair rule ignores recency, and the code makes the spec's premise impossible {#s-1}

**File:** src/refmatrix/memory_layout.py:89-94 (`is_shadowed_savestate`) and :171-173 (the walk skip);
spec #rd-duplicate.

**What:** the walk ALWAYS skips a top-level `savestate_<x>.md` when `savestates/savestate_<x>.md`
exists, whatever their `updated`/mtime. The spec justifies this with "a crash mid-move". The writer
makes that impossible: `os.replace(legacy, target)` runs before the write (`handoff.py:446`), so a
crash leaves exactly one copy. A pair can only form when something ELSE writes the top-level copy
while the `savestates/` copy exists. That something is an old-code writer, for example an MCP stdio
server not respawned after the deploy (feedback_mcp_server_reload_and_orphans), or a dir whose
marker is gone while `savestates/` remains (flag #flag-flat-shadow). In both shapes the top-level
copy is the FRESH one.

**Evidence:**
- orgshadow.py: in an organised dir, with `savestates/` at updated 2026-11-01 and the top level at
  2026-11-10, the walk yields only `savestates/`, skips the top-level copy, and `iter_savestates`
  reads "STALE".
- flatshadow.py: the same result with no marker.

recall-state, the MEMORY.md pointer and the bridge all take the stale handoff until the next
new-code save of that same id. Nothing tells the user; the only sign is the bridge's skip line,
and nothing reads it.

The 26.5 AC (#inherit-rollback-savestates) closes one producer, rollback. It does not close the
old-writer producer, and it does not make the rule correct.

**Fix:** resolve the pair in the same place (`iter_memory_files`) by the ADR-0005 #newest key. Yield
`sort_savestates([top, sub])[0]`, skip and name the other. The `savestates/` copy is kept only on a
full tie. The next organised save still writes `savestates/` and unlinks the top level. Then amend
#rd-duplicate: its premise is "any writer that put a second copy", not a crash. Add tests for both
probe shapes plus a tie.

**Pattern match:** YES. A reader and a writer disagree on which copy is authoritative
(feedback_check_the_sibling_condition). The flag named one producer, and the fix was pushed to
26.5 instead of the rule.

### MEH m-1: where the 26.2 exemption lives is written two ways, and the combined test is unnamed {#m-1}

**File:** /Volumes/littlebig/refmatrix-plan26-2 src/refmatrix/ingest_gmd.py:1017-1023 (read-only,
uncommitted there) vs this branch's memory_layout.py:131-140.

**What:** 26.2's `split_claims` docstring says the save-state pair's "exemption and its preference
between the two belong HERE". 26.3 puts them in the walk, so `split_claims` never sees the pair.
They compose today: 26.2 judges `collect_gmd_files` output, the pair arrives as one path, and every
other duplicate id is still yielded twice. But whichever task merges second could add a second
exemption, or delete the walk rule to honour that docstring. "Whichever merges second carries the
combined test" (#rd-duplicate-vs-262) names no AC.

**Fix:** make it an AC in 26.2's spec, since 26.2 is still open. On an organised memdir holding the
pair plus one non-save-state duplicate id:
- `duplicate_ids` names only the non-save-state id;
- the save-state is ingested once, from the copy s-1 picks;
- the skip line names the other copy.

Also amend 26.2's docstring to point at `memory_layout.iter_memory_files`.

### MEH m-2: `updated:` is now a timestamp, and MEMORY-RULES says `YYYY-MM-DD` {#m-2}

**File:** src/refmatrix/handoff.py:148-154 (`_ss_updated_stamp`), :175.

**What:** every save-state, flat dirs included, now writes `updated: 2026-11-10T11:57:51-08:00`. The
user's MEMORY-RULES (#frontmatter) specifies `updated: <YYYY-MM-DD>`. `_updated_day` reads both
forms, and GMD lint does not check the format, so nothing in rmx breaks. But a project rule changes
silently for every memory dir that runs save-state, and #flag-updated records only the missing
offset, not the rule conflict.

**Fix:** either amend MEMORY-RULES #frontmatter (`updated` = date or ISO timestamp) in the same
change, or keep the date only and let mtime break ties, as ADR-0005 #newest already does.
