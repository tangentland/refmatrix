### BULLSHIT #b-1-r4: `render_gmd(stats=)` has no production caller, so every real `--gmd` document says "an unrecorded number of memories" {#b-1-r4}

**File:** `src/refmatrix/cli.py:11255` (the only production call), `src/refmatrix/brief.py:533` (the
parameter), `src/refmatrix/brief.py:589` (the fallback)

**What:** `render_gmd` takes `stats: dict | None = None` and renders
`f'{st.get("memories", "an unrecorded number of")} memories.'`. The sole production caller is:

```python
click.echo(brief_mod.render_gmd(
    briefs, names=names, partition=stats.get("partition")))
```

It has `stats` in hand on the line above (`stats = res.get("stats") or {}`) and passes only
`stats["partition"]`.

**Why it's bullshit:** the `stats` parameter is **dead** — no caller in `src/` passes it, and no
test in `tests/` passes it either (`grep "stats=" tests/test_brief_gmd.py` → no matches; the only
`render_gmd` callers are the CLI and seven in-process test calls, none with `stats=`). Its two
effects are both unreachable in production: `st.get("memories")` never resolves, and
`st.get("partition")` is masked because `partition=` is passed explicitly. The honest-fallback
string exists for the case where the count is unknown; on **100% of real invocations** the count is
known and the fallback fires anyway.

This is the exact shape of r2 `#b-2-r2d` — *"the loud-honesty line firing on 100% of the class"* —
one argument over, in the same call, fixed for `names` and missed for `stats`.

**Evidence** — copy of the live read replica, partition `refmatrix`:

```
memory rows: 243
compile_briefs stats: {'memories': 243, 'briefs': 23, 'skipped': 51, ...}
--- GMD headline (no stats passed, as production does) ---
'23 brief(s) over an unrecorded number of memories. ...'
--- GMD headline (stats passed) ---
'23 brief(s) over 243 memories. ...'
```

and through the real daemon, end to end: `2 brief(s) over an unrecorded number of memories.` while
`--json` in the same store returns `"memories": 8` and the plain table footer prints
`2 brief(s) over 8 memories`. **Three surfaces of one command; the GMD one is the only one that
cannot say the number, and it is the one that becomes a node in the graph.**

**Fix:** `stats=stats` in the `render_gmd` call. Then assert the count **through the CLI** —
`_fake_brief_payload` already returns `"memories"`-less stats, so add it there and assert
`"over 5 memories" in res.output`, or the next fake omits the field again
([[bsd-impressions#imp-fake-omits-the-new-field]], one round old).

**Pattern match:** YES — `impression_bsd_unread_diagnostic_field` inverted (a field produced,
carried, and then not *read* by its only consumer) and `{#imp-my-fix-needs-measuring}`.
