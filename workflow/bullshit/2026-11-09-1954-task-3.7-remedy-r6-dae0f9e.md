### B-1 readiness signal: robustness notes (not counted) {#b-1-notes}

- **The signal is sound.** `wait_models_warm` reads only this launch's lines (it captures the byte offset before `Popen`). It treats `warmup failed` as an error, a dead daemon as an error, and the monotonic deadline as an error. `"embedder warm in"` is logged only after `self._embedder()` returns, and that call blocks on the model load (the r6 probe measured 7.4 s cold; this run measured 2.4 s).
- **Log-text coupling.** The test pins `"reranker warm in"` on the src side (`test_rerank_budget_real_clients.py:934`). Nothing pins `"embedder warm in"`. If someone rewords that line, every AC-11 setup fails *loudly*, with a 180 s "models not warm" SETUP error that names the lines it did see. That is fragile but not masking. The cheap hardening is to make the strings shared constants in `daemon.py` that the helper imports.
- **W1 survives.** Mutation W1 skips `wait_models_warm` entirely, and the file still passes 13/13 with one warning (`needed 2 attempts … [skipped_budget 5002]`), because the 60 s retry deadline also covers the cold window. The readiness wait is therefore an efficiency guard and not the only guard. A regression in it degrades into the warned retry path, which is visible in the warnings summary and is never a silent pass. This is acceptable.

## Findings {#findings}

### MEH: the streak's "any other miss ends the run" rule is unpinned {#m-1}

**File:** `src/refmatrix/recall.py` (`reprobe_shared_client`: `else: backoff.pop(key, None)`)

**Mutations** (`bsd-r7-mutations.log`, run against the r2–r6 + readoption set, 71 tests):
- **S3, survives.** A refused or absent socket no longer ends the cold run. The docstring promises that a hub which dies and comes back cold starts a new run at base. Under S3 the sequence cold → refused → cold re-arms at `2 × (doubled backoff)` instead of base. For example, at base 300 the correct wait is 300 s and S3 gives 1200 s, so a restarted hub is adopted 15 minutes late. That is exactly the r5 #m-3 cost, reached through a different order.
- **S5, survives.** The streak counter is pinned at 1. This changes only the "N consecutive header timeouts" count in the log line.
- **S1 and S2, equivalent today.** S1 drops the success-path pop and S2 drops `hold_reprobe`'s pop. In both cases `backoff[role]` is also popped or reset, and no current caller can reach `hold_reprobe` with a live streak: the request path `.clear()`s or builds from empty. These pops are defensive. Keep them.

**Fix:** add one test of the sequence mute → refused (or `_StubHub` closed) → mute that asserts the third probe re-arms at base. A log-text assertion on the count kills S5 as well.
