## The two GREEN decisions {#decisions}

- **The empty index hook never erases a curated sidecar hook.** This holds for its purpose: a
  line that renders without its hook no longer erases the curated text. It costs the index-only
  way to clear a hook (see [[#m-1]]), and it leaves the sibling path open (see [[#s-1]]).
- **Refuse only when the carried prose blocks the fit.** Both branches run as specified. The
  refuse branch freezes the index until a human moves prose out, which is the same trade as the
  25% rule. The `STILL OVER` branch does not say how much of the overflow the prose causes.
  Both are accepted as decided.

## Findings {#findings}

### SKETCHY: a truncated index hook still overwrites the full sidecar hook, the sibling of the empty-hook rule {#s-1}

**File:** `src/refmatrix/memory_index.py:354-356` (`load_hooks`), `:202-230` (`Entry.line`)
**What:** The new rule protects the sidecar against an EMPTY index hook only. A listed entry whose
hook is cut renders `prefix…`. On the next render, `parse_hooks` reads `prefix…`, which is not
empty, so it wins. `save_hooks` then writes it to the sidecar, and the full curated text is gone
from both places.
**Evidence** (`bsd-26.1-r2-hooks.log`; fixture, both layouts, 61b3bde and 7b5ea2f alike): a 246-char
hand-written hook is in the sidecar after render 1. From render 2 on it is 171 chars and its end
is gone. On real copies:
- live refmatrix's sidecar already holds 30 cut hooks whose text is not derived from the file,
  so that curated text is lost;
- cliquedb's first render after the deploy turns 1 full sidecar hook into `…`, the entry
  unfolded by the shorter lines;
- 3 sidecar values across the copies are the bare garbage hook `…` (cliquedb 2, refmatrix 1).
  These come from HEAD cuts that ended `.md)…`, and the empty-hook rule now keeps them for good.

This predates 26.1 (bug-050's sidecar), so it is not a regression. It is the same failure AC-5's
precedence decision was made for. Pattern match: feedback_check_the_sibling_condition and the
post-deploy audit, where both prescriptions were narrower than the defect.
**Fix (small):** in `load_hooks`, an index hook that ends in `…` and is a prefix of the sidecar
value does not replace it. Treat a bare `…` as empty. Add a bug row and a test with a long
curated hook rendered 3 times.

### MEH: no index-only way to clear a curated hook, and a marker-off change that was not stated {#m-1}

**File:** `src/refmatrix/memory_index.py:354-356`
**What:** At HEAD, deleting a hook from a `MEMORY.md` line made the entry fall back to its derived
first-prose line. At 7b5ea2f the sidecar brings the old hook back, in both marker-off and
organised dirs (`bsd-26.1-r2-hooks.log`, step 2). The only way to clear it now is to edit the
dotfile `.memory_hooks.json`. That is a marker-off behaviour change, but ADR-0005 `#marker` and
AC-8/9 still say marker-off output is "byte-identical" to HEAD. None of the 4 real copies hit it.
**Fix:** EITHER apply the protection only when the line could not carry the hook (link-overflow
lines), which keeps HEAD's clear-to-derive path, OR record the change in ADR-0005 `#marker` and
MEMORY-RULES ("to drop a curated hook, edit `.memory_hooks.json`").

### MEH: s-3 leftovers: dead structured skip fields, a wait path that drops the skip line, and an uncounted `- [` prose drop {#m-2}

**Files:**
- `src/refmatrix/cli.py:10441-10442`, `:10491-10492` (`st["skipped"]` and `st["skipped_paths"]`);
- `:10544` (`_bridge_stats`);
- `:10608-10612` (`_bridge_wait_for_active_job`);
- `memory_index.py:432-434`.

**What:**
- `_ingest_gmd_sync` adds `skipped` and `skipped_paths` to its stats, but its only stats
  consumer, `_bridge_stats`, never copies them. The fields have no reader, so the structured
  `sync` dict that save-state and MCP return has no skip count. That is plan-5 #m-7's "no report
  scraping" rule.
- When save-state waits on a covering SessionStart job, it takes `res["report"]`.
  `_run_ingest_gmd_body` never appends the skip line to that report; it puts `skipped_paths`
  only at the top level of the result. So that save-state prints no skip. The line was already
  printed once, in the SessionStart start reply.
- On the organised path, `_prose_lines` now drops every line that starts with `- [`. A
  hand-written `- [ ] todo` would be dropped without being counted. Across all 19 fleet indexes
  there are 0 such lines.

**Fix:** copy `skipped`/`skipped_paths` in `_bridge_stats`, and read the job's top-level
`skipped_paths` on the wait path. Count dropped `- [` lines that name no memory in the write report.
