## Findings {#findings}

### MEH: the guard's fixed point is pinned by nothing — the two-level plant defines its inner wrapper first, so a one-pass loop still catches it; five new evasion shapes pass (none present in src) {#m-1}

**File:** `tests/transport_guard.py:123-131` (the `while changed` loop); the
`tests/test_task3_6_r9_remedy.py:284-296` plant `two_level_wrapper` (defines
`_memory_daemon_call` BEFORE `_subject_upsert`).

**What:** mutant Q5 drops `changed = True`, which turns the fixed point into a single pass. It
**survives all 53 tests**, because a single pass in source order still sees the inner wrapper
first. I checked by hand under Q5: an outer-defined-first two-level plant is **not flagged**, and
at head it is. The live layout that hid r11 #s-1 is exactly outer-first (`_subject_upsert` at
`cli.py:1667`, `_memory_daemon_call` at `:11202`).

Five shapes the new guard still passes:

1. a message string prepared in the function before the `try`;
2. a local alias `dial = daemon_mod.call`;
3. a module-level `lambda` helper;
4. an exception class whose `__str__` carries the words;
5. `functools.partial(daemon_mod.call)`.

A live-src scan (`scan12.py`, plus rg for alias/partial/lambda assignments) finds **no
instance** of any of them.

**Fix:** reverse the plant's definition order, or add an outer-first twin. That kills Q5. Add
plants for shapes 1 and 2, the two most likely to appear in real code.

### MEH: two transport handlers render the raw exception without the classifier, which a word list cannot see {#m-2}

**File:** `src/refmatrix/verbs.py:533` (`global_recall_rows`:
`except Exception as e: raise VerbError(f"global store {op} failed: {e}")`) and
`src/refmatrix/cli.py:1439-1442` (`_file_under_active_subject`'s second handler:
`except Exception` → "the daemon **refused** the subject filing … {e}").

**What:** `probe_r12_recall.py` ran the global recall leg (budgeted, `retries=0`, which is the
hooks' global leg) against a real global store:

| global store | result |
|---|---|
| up | `[]` |
| held (SIGSTOP) | `VerbError: global store memory_search failed: timed out` (3.00 s) |
| stopped | `VerbError: global store memory_search failed: [Errno 2] No such file or directory` |
| refused socket | `VerbError: global store memory_search failed: [Errno 61] Connection refused` |

These are all one type with a raw errno. They surface as `global rows omitted: …` warnings. This
is r8 #s-2's raw-errno shape on the last global leg. It predates plan-3 r8, nothing regressed, the
text is not false, and no caller makes an in-process decision on the type.

`cli.py:1439` is a separate case. A transport failure that is not an `OSError` (the empty-reply
`JSONDecodeError` of a daemon dying mid-request, which `classify_transport_error` calls busy) is
labelled a daemon "refusal". It is reachable only in a race.

**Fix:**

- Route `global_recall_rows`'s handler through `classify_transport_error(e, op=op, root=groot,
  timeout=timeout)` and re-raise its type. `memory_recall` already treats `VerbBusyError`
  separately.
- Narrow `cli.py:1439` to the `RuntimeError` that `_subject_upsert` / `_subject_link` raise for
  `ok:false`.
- Optionally, extend the guard: a handler around a dial that renders `{e}` and does not classify
  it is a second classifier even with neutral words. `scan12b.py` lists the 17 such sites today,
  most of them honest status displays ("unknown ({e})"), so this needs a curated allowlist rather
  than a hard rule.
