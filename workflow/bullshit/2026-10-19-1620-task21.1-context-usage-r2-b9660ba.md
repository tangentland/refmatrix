### SKETCHY s2-r2: the live-log guard fails on any concurrent use of the main tree; file a bug row {#s2-r2}

**File:** `tests/task21_1_support.py:43-69` (`live_snapshot` / `assert_live_logs_unchanged`),
used as an autouse teardown in 4 task-21.1 test files
**What:** the guard compares only `(st_ino, st_size)` of six live logs (the checkout's, the main
dev tree's, and the real home's `query.log` / `recall-events.jsonl`). The main tree's
`query.log` is appended by every hook and agent `rmx` call of whichever Claude session is
working there, which during a 27-minute suite run is close to always. The final full run's ERROR
is exactly this: +379 B on the main-tree `query.log`, same inode, from concurrent live use.
**Why it matters:** a guard that is red for reasons unrelated to the test gets explained away
("expected"), and the next real leak gets read the same way
(`feedback_never_explain_away_a_failing_guard`). It cannot tell the difference between a test
writing to a live log and the user typing.
**Fix:** attribute the moved bytes. Read the appended range `[before_size, after_size)` and fail
only on a row whose `cwd`/`root` lies under `$RMX_SANDBOX_ROOT` / the test's tmp, or that carries
a session id or body the test minted. Fail on an inode change (truncation or rotation is never
the user's). Record it in `workflow/bug_registry.md` (test isolation, task 21.1 / 23.0), with
the final-log ERROR as the symptom.
