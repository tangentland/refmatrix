## Findings {#findings}

### BULLSHIT B1: the per-document `denotes` tail does not reproduce HEAD's link set, and the spec's proof claims it does {#b1}

**File:** `workflow/plans/task-bug185-bulk-gmd-ingest.md:203-204`, `:283-285` and `:902-903`.

**What:** R2 step 8(b) runs `link_denotes` for "this document's id and the concept names this
document's pass 2 minted (tags, title tokens, mention concepts)". The ruling's proof
(`:902-903`) says: "A concept that a later document D2 mints, naming D, is in D2's minted set, so
it is linked at D2's step. The `denotes` link set is the same once the batch ends." R7 (`:283-285`)
repeats this as fact.

**Why it's bullshit:**
- **How `link_denotes(names)` works.** It treats `names` as the names of TARGET docs and memories
  (`b216_store.py:6035`: `kind IN ('doc','memory') AND name IN (…)`). Only then does it look up the
  path-less concepts that spell those targets (`_concept_variants`: underscore canonical, plus
  the space and dash forms, `b216_store.py:248-270`).
- **What HEAD does.** It calls `link_denotes` once, after every pass 2
  (`b216_ingest_gmd.py:1915`), with every batch doc id in `denotes_names` (`:1602`). By then every
  concept the batch minted exists, from any producer and in any spelling.
- **What the per-document tail misses.** It links a concept minted by D2 to target D only if
  either:
  - the concept already exists at D's step; or
  - D2's own name list contains D's exact id.

  Body terms (`b216_ingest_gmd.py:1680`, ON by default, `:793-794`) and aliases mint concepts but
  are never added to `denotes_names`. Variant spellings are not matched either: D2 minting `d1 id`
  passes `d1 id`, and no doc has that name.
- **The reachable case: memory ids.** `_BODY_TOKEN_RE` keeps underscores
  (`b216_ingest_gmd.py:172`), and memory ids are underscored. So a memory `m_one` followed later
  in the same bridge batch by a memory whose body says `m_one` gets the link at HEAD, but not
  under option 1, because neither step's name list contains `m_one` once that concept exists.
- **Nothing tests it.** AC-2's bug-216 shapes fixture (`:469-470`) and AC-13 (`:663`) use only a
  title that spells the id exactly. AC-9 (`:592`) has "one `denotes` name". The golden passes,
  and the build ships a silent loss of `denotes` edges compared with HEAD, on the memory path.
  R3 (a) (`:212`) is the contract this breaks.

**Evidence:** `b216_ingest_gmd.py:1655-1680` (concept_specs: tags and title tokens go into
`denotes_names`, aliases and body terms do not); `:1872` (mention names); `:1914-1915` (the batch
tail).

**Fix:** In R2 step 8(b), widen the name set:
- this document's HEAD contributions;
- plus every batch doc or memory id (`GmdBatch` holds them all after pass 1) whose
  `_concept_variants` spellings intersect any concept name this document's pass 2 wrote
  (step 1 specs, step 4 anchor specs, mention names, and their variants).

This is a set intersection in Python, so it adds no statement. AC-2 gains an `--as-memory`
fixture, `[m_one, citer]` in that order, where the citer's body names `m_one` and no concept
`m_one` exists beforehand. The mutation "names = HEAD's per-document contributions only" then
FAILS against the golden. Strike the false sentence at `:902-903` and the matching clause in R7.

**Pattern match:** YES. "A prescription narrower than the defect" (bsd post-deploy 0916), and
"a clean corpus hides a dead gate": the equivalence golden never sees the shape that breaks it.

### SKETCHY S1: the "stamp before tail" mutation cannot fail where the specs put it {#s1}

**Files:** `task-bug185-bulk-gmd-ingest.md:666-667`, `:675` and `:679-681`;
`task-23.3-sync-between-file-yield.md:298-302`.

**What:**
- **bug-185.** AC-13 runs `gmd_pass2_document` "each in its own transaction" but says "This AC
  runs in the direct context". Its mutation is "the stamp written before the per-document tail…
  A stop injected between them leaves `d1` stamped".
- **23.3.** AC-4b's round-8 mutation says "A `cancel` injected between them leaves a stamped
  document whose tail did not commit".

**Why:**
- **Inside one transaction, the order cannot be observed.** A stop raised between two writes of
  one `store.transaction()` rolls back both, so the correct code and the mutant leave the same
  state.
- **23.3 cannot stop between them at all.** It is one transaction per step (23.3 R1,
  `task-23.3…:135`), and `cancel()` is "checked before each hold" (23.1 R2,
  `task-23.1…:733`). So 23.3 has no point between a step's tail and its stamp.
- **Where the order does matter:** only the job path with no transaction, where each write
  auto-commits. R2 step 9's "in the same transaction" (`:205`) is also false there.

**Fix:**
- **AC-13:** run the mutant case with NO enclosing transaction, and raise from the tail's first
  write (for example a patched `pending_refs_for`). With the correct code `d1` is unstamped. With
  the mutant, `d1` is stamped and its row stays pending after the re-run.
- **23.3 AC-4b:** replace the mutation with "the per-document tail moved into the `gmd_finish`
  step; a `cancel` before `gmd_finish` leaves a stamped document's pending row unresolved", or
  delete it.
- **R2 step 9:** reword to "after the tail; in the same transaction when one is open".

**Pattern match:** YES (mutation that cannot fail; IMPRESSIONS, the clean-corpus family).

### SKETCHY S2: R10's unlink point and "states" are open, and both readings break something {#s2}

**File:** `task-bug185-bulk-gmd-ingest.md:369-372` and `:641-642`.

**What:** "After the document's step 5 … every old key that the new text does not state is
unlinked". AC-11's mutation: "unlink by 'source is a node of `a`' … (a `part-of` hierarchy edge
from `a`'s node is removed)".

**Why:** The `part-of` hierarchy and `imports` edges are written in step 6's `link_batch`
(`b216_ingest_gmd.py:1736-1740`, `:1881`), after step 5. This gives two readings, and neither is
safe:
- **The unlink runs between steps 5 and 6.** The by-source mutation removes the hierarchy edge,
  and step 6 writes it back, so the catalog and the replay end equal and the mutation survives.
- **The unlink runs after step 6.** An old `rel: part-of -> [[#parent]]` key that equals the
  hierarchy edge has no evidence row once the line is dropped, so R10 unlinks a hierarchy edge
  the document still writes. That is a lost edge until the next re-ingest.

The spec decides neither the position nor what "states" covers (only `rel:` lines, or every edge
the document writes).

**Fix:**
- Pin the unlink after step 7.
- Define "states" as the document's whole write set: the keys of steps 5-7 plus the tail.
- Give AC-11's by-source mutation an edge that no step re-writes: a `Store.link("part-of", a#cite,
  ext)` from another producer, with no evidence row.
- Add a collision case: a `rel: part-of -> [[#parent]]` line is dropped, and the hierarchy edge
  survives.
