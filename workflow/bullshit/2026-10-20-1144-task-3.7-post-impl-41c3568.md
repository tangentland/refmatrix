## Findings {#findings}

### BULLSHIT: the prompt hook drains spool entries nobody was shown {#b-1}

**File:** `src/refmatrix/cli.py:9077`, `src/refmatrix/hooks.py:184,245`

**What:** `rmx curator status --drain` runs on every prompt and every SessionStart. It reads up
to 500 entries, prints 10 paths and "+N more", then drains the whole token.

**Why it's bullshit:** the spool redesign exists so that nothing is drained unread
(#fam-refine-drain). Its most frequent production path breaks that. The run below printed
`+5 more` and then emptied the spool.

The template's crash-safe flow (`status --json` → work → `drain --token`) can never run. The
next prompt hook has drained the files before the gmd-curator is even spawned, so "keep the
queue so the next run picks up the remainder" is false.

**Evidence:** `workflow/review-output/task-3.7/bsd-hook-drain.log` (15 paths written, hook
run, spool empty).

**Fix:** the generated hooks run `curator status --quiet-when-empty` without `--drain`, so the
only drain is the agent's token drain. Otherwise, `--drain` must pass `max_entries=limit` so
it drains only what it printed. Add a RED test of `+N more` followed by a non-empty spool.

**Pattern match:** YES. This is r1 B3's "hooks drain every prompt", kept by the spec's own
hook clause.

### BULLSHIT: `focus composite` drops the CLI `-p` (documented as a "known limit") {#b-2}

**File:** `src/refmatrix/verbs.py:1439` (`partition=project_partition(root)`)

**What:** the base CLI read through `_replica_store()`, which uses `_resolve_partition()`: the
`-p` flag, then `RMX_PARTITION`, then `.refmatrix/partition`. The verb reads `$RMX_PARTITION`
or the store name. `-p` is a module global and is never exported, so
`rmx -p X focus composite` now reads the wrong partition.

**Why it's bullshit:** this is a regression against C2 ("Existing CLI options keep their
meaning") and C7. The summary's #limits section narrows the interface ("the PAIRING row
forbids one") instead of adding the parameter. That is a cheap fix (rule 10).

**Fix:** give `rmx_focus` a `partition: str | None = None` parameter used by `composite`,
update the PAIRING row, and have the CLI pass `_resolve_partition()`. Add a RED test with `-p`.

**Related:** `project_partition`'s docstring (`verbs.py:452`) claims the `_resolve_partition`
order but skips `.refmatrix/partition`. Every MCP call with no `partition` therefore diverges
from its CLI twin in a tree bound by a partition file.

### SKETCHY: `link` / `canon link` cannot see a concept added a moment earlier {#s-1}

**File:** `src/refmatrix/verbs.py:2514` (`_matrix_write` resolve), `:2472` (canon link)

**What:** the link ends are resolved from `catalog.read.duckdb` before the write op is sent.
The snapshot lags by at least the 250 ms debounce. With a real daemon, `add_concept fresh1`
followed straight away by `link fresh1 freshdoc1` fails with "no concept named 'fresh1' —
`rmx add concept fresh1` first". `canon link` fails the same way.

**Evidence:** `workflow/review-output/task-3.7/bsd-read-your-writes.log` (2/2 fail).

**Note:** base `_DaemonWriter` also resolved through the replica, so this is not new. It is
now an MCP surface, and its error tells the agent to repeat a write that succeeded. The
CLAUDE briefing teaches exactly add-then-link.

**Fix:** send the names and resolve them under the writer inside `_op_link` / `_op_unlink` /
`_op_link_canon`. At minimum, on a snapshot miss re-check through a daemon op before refusing.

### SKETCHY: the two "missing partition reads EMPTY" guards survive mutation {#s-2}

**File:** `src/refmatrix/verbs.py:520`, `src/refmatrix/store.py:1998`

**What:** M11 removed snapshot_read's `-1` override and M18 changed store `else -1` to `else 1`.
M11 survived 378 tests. M18 survived those plus 189 more (the derive / 21.1 / 3.6 suites).

**Why:** without these guards, a read-only Store with an unknown partition answers from
partition id 1 (`Store._connect` falls back to 1). An MCP `rmx_graph(partition="typo")`
would return another partition's graph. The guards are load-bearing and untested.

**Fix:** add one test per guard (`snapshot_read` and `with_partition` on a read-only store,
with an unknown partition) that asserts empty rows while partition 1 has data.
