### MEH: a malformed `RMX_SHARED_REPROBE_S` brings back bug-173's per-call load with a healthy private worker {#m-2}

**File:** `src/refmatrix/recall.py` (`_reprobe_window`, `hold_reprobe`,
`_load_process_inproc_standin(None, …)`)
**Evidence:** `bsd-r5-probe-badenv.log`. The private worker was HEALTHY, there was no hub,
and the operator typo was `RMX_SHARED_REPROBE_S=300s`. With `RMX_SHARED_MODELS=1` (the
default), 4 calls gave **4 uncached in-process loads**: models
`[in-process x4]`, with the WARNING `ValueError("could not convert string to float: '300s'")`
on every call. With `RMX_SHARED_MODELS=0`, call 1 loaded in-process (`hold_reprobe` parses
the env even when no hub is possible) and calls 2-4 used the private worker. Here is the
sequence. The build assigns `_EMBED_CLIENT`, and then `hold_reprobe` raises. Every later call
re-probes, and `_reprobe_window` raises again. `shared_embedder`'s generic `except` then
reaches the `client is None` branch, which is the "UNCACHED in-process model for this call"
path. r3 already did this from call 2 (the re-probe parsed the env). r4's `hold_reprobe`
extends it to call 1 and to `RMX_SHARED_MODELS=0`. It is loud (WARNING on every call), so it
is not silent. But a 6-33 s, ~610 MB load per call is the exact cost bug-173 was fixed to
stop.
**Fix:** Have `_reprobe_window` fall back to the defaults with one named WARNING when the env
does not parse, as an operator typo should behave. Skip `hold_reprobe` when
`not modelsrv.shared_enabled()`. Pin it with the badenv probe's shape: loads == 0 with a
healthy private worker.

### MEH: a cold hub worker costs one DOUBLED window, which the knob comment does not say {#m-3}

**File:** `src/refmatrix/modelsrv.py` (`REQUEST_PROBE_TIMEOUT_S` comment), `recall.py`
(`reprobe_shared_client` backoff)
**Evidence:** `bsd-r5-probe-coldhub.log`. A real stub hub was started with a worker that
sleeps 3 s before its first `info`, beside a healthy private worker. With
`RMX_SHARED_REPROBE_S=2` the process adopted 6.2 s after the hub came up, and with `=5` it
took 15.0 s. That is base + 2×base. The first probe took 1.01 s, missed, and the backoff
went from base to 2×base. The comment says "the next re-probe (one backoff window later)
finds it warm". That is true, but the window that follows has doubled. With the defaults
that is up to 300 + 600 s with a duplicate ~610 MB private worker beside the hub's warm one.
The hub's `_start_models` calls `srv.warm()`, so the miss only happens when a probe lands
within the 6-33 s warm window after a hub (re)start. It is rare but real, which is why this
is MEH.
**Fix:** Do not double the backoff when the socket connected and only the header timed out
(the hub is alive and its worker is warming). Re-arm at `base`, or at a short fixed retry.
Alternatively, correct the comment to "one doubled window later".

## Behaviour changes the implementer flagged {#flagged}

- **(a) In-process for life after a transient private spawn failure.** This is accepted. It
  matches the daemon: `Daemon._embedder`'s `on_fallback` drops the private worker and keeps
  `_embedder_inst` until `_maybe_adopt_shared` re-adopts. Memory is the same whether the
  model lives in-process or in a worker. The hub path still recovers (cycle probe). Under
  `RMX_SHARED_MODELS=0` it stays in-process, as a daemon does.
- **(b) Cold worker vs the 1.0 s probe.** Measured and filed as [[#m-3]].
- **(c) A second in-process load per hub-death period.** This is bounded. Real model, real
  HF cache (`bsd-r5-probe-rss.log`): load 1 took 561 MB, the drop freed the object
  (weakref dead) but RSS only fell to 477 MB, load 2 took 582 MB, and load 3 took 590 MB.
  Each extra cycle costs about 10-20 MB of retained RSS, not another 610 MB.

## Threading {#threading}

Lock order: `_load_process_inproc_standin` takes `_EMBED_INPROC_LOCK` and then
`_EMBED_CLIENT_LOCK`. `_process_embed_client` takes only `_EMBED_CLIENT_LOCK` and never
`_EMBED_INPROC_LOCK`. `_process_inproc_standin` takes no lock. There is no inversion. The flag
is cleared in `finally`. F1 (flag never cleared) is killed, and F2 (clear not
exception-safe) survives: see [[#m-1]]. Swap race (`bsd-r5-probe-swaprace*.log`): a caller
that arrives during another caller's probe gets the cached private client and finishes in
0.06 s, so it does not queue. If that caller holds its embedder across the swap (1.5 s hold
in the probe), it gets `WorkerError('embed worker retired …')`. This is the same r12
retire-refusal the daemon has, and r3 had the same window. r4 widens it by at most the 1.0 s
probe, so it is not filed.
