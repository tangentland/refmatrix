### BULLSHIT: the `·held` marker is ruled in 10.2 but left open in 25.1b, and 10.5's gate needs it before 10.2 exists {#b1}

**Files:** the 25.1b spec, at `:92` (`#k2`, `ff1d453`, unchanged at `c9d4487`), and the 10.2, 10.5
and plan-10 specs (`369e0b5`; 10.2 R3's sentence is at head `:136-138`).

**What:**
- **25.1b `#k2`** still reads: "whether held members carry a marker is 10.2 `#open-held-mark`, for
  the lead".
- **The lead ruled it** (L52: "held names on the shared line carry a short marker"). 10.2 h16
  (`:76`) folds the ruling: "Each held member on the line carries the suffix `·held`, rendered by
  25.1b's one line renderer". 10.2 AC-14 (`:281-282`): "The marker literal `·held` likewise appears
  only in that renderer."
- **10.2 R3 contradicts h16** (`:133-134`): "10.2 changes nothing in `hook_budget`, the budgets, the
  ladder, the line's format, the spill page …".

**Why it's bullshit:** this is the one shared contract the lead asked to be byte-for-byte, and it
is not:
- **Neither spec builds the marker.** 25.1b treats it as undecided. 10.2 forbids itself any change
  to the line's format, yet requires the marker literal to live only in 25.1b's renderer.
- **The queue order breaks.** 10.5 runs BEFORE 10.2 (queue item 6: 10.5 probe → 10.6 → 10.4 →
  10.2; 10.5 R4b: "after 25.1b merges and before 10.2's RED"). Yet 10.5 R1b (`:81-82`) says "the
  line's bytes include h16's `·held` marker". Part 2 R1 (`:101-102`) renders X "by 25.1b's line
  renderer exactly as 10.2 will print it".
- **So 10.2's gate cannot run as specced.** 10.5 GO is the precondition for building 10.2. An
  unattended builder either hand-rolls the marker in the replay (then the line is no longer "25.1b's
  renderer") or stalls.

**Fix:**
- 25.1b `#k2` adopts h16: the renderer takes held members and prints `<name>·held`, the bytes
  counted inside the line's reservation, with over-budget members unmarked.
- Add an AC row with a held set injected through the renderer's held slot, with mutations "marker
  missing" and "marker on an over-budget member".
- Strike "the line's format" from 10.2 R3's list, or restate it as "10.2 supplies held members
  only".

**Pattern match:** YES. It is the cross-spec "sibling AC" shape in
`impression_bsd_handoff_without_sibling_ac` (26.4 r1): one side rules, and the other side's text
keeps the old open item.

### SKETCHY: the ladder's tier shapes and payload layout are not defined against 25.1 R3's "every hook line before any body" {#s1}

**Files:** 25.1b R13 (`:138-150`), `#amend-r3` (`:200-203`), AC-17 (`:234-237`) and AC-20
(`:251-256`); 25.1 on its branch, R3 (`:188-192`); 10.6 R1 (`:80-86`).

**What:**
- **25.1 R3 fixes a layout:** "one hook line per named hit, ALL before any body". Rev 7 J5 pins it
  with the test `test_ac9_session_start_carries_bodies_after_all_hook_lines`, and d3 says a
  per-prompt pack is "12 hook lines at 250-370 B".
- **25.1b gives tiers per item and leaves the layout open.** It defines tier 1 = "the full body",
  tier 2 = excerpt, and tier 3 = "a one-line pointer (name, scope-correct fetch command)", which
  drops 25.1's `— <title> — <hook>`. `#amend-r3` says only that "bodies that fit are still whole",
  so the layout question is silent.
- **10.6 R1 assumes a third shape.** It labels "the full body's hook line, the excerpt, the
  pointer", which assumes tier-1 items keep a hook line.

**Why it matters:** an unattended build has to pick a shape. Several outcomes hang on that pick:
- **Spans.** AC-20 asks for "a span that slices exactly its rendering". That is ill-defined for a
  tier-1 item split between the hook-line block and the body block.
- **"Every item visible".** AC-17 holds only if tier-3 lines are short. At 25.1's 250-370 B hook
  lines, 40 pointers need 10-15 KB, more than the 9,000 B budget.
- **The curated-hook lookup.** 25.1 R4's lookup, which D-Q2's 26.7 AC exists to protect, renders
  nowhere if tier 3 has no hook text.
- **Downstream figures.** 10.5 v3's baseline bytes and 10.2 R8's parity figure both move with the
  pick.

**Fix:**
- 25.1b states each tier's exact line shape: tier 3 = 25.1's hook line, or not.
- It states whether the "hook lines first, bodies after" layout survives.
- It states how a split rendering's span is defined.
- `#amend-r3` names the change.
