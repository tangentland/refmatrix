## Findings {#findings}

### MEH: leg (c2) never takes the re-wrap path that the live CLI call takes {#m1}

**What (c2) does.** It calls `verbs.memory_recall(root, query=…, timeout=1e-6, pack=True)` with
NO `partition`. The verb's first `_left` is in the partition probe:
`memory_partition(root, timeout=_left(10.0) …)` at `:1413`. Its `except VerbBusyError: raise`
(`:1415-1416`) propagates the error BEFORE the main `try` (`:1419`). So the re-wrap
(`:1522-1526`) never runs in (c2).

**How the live call differs.** The live CLI call always passes `partition=` (`cli.py:12759`, and
`_dense_partition` at `:12865`), so live, the deadline fires inside the main `try` and goes
through the re-wrap.

**Consequence.** The mutation "the re-wrap drops the subclass" is killed only by (c2)'s
structural check, never by its type check on the live path's shape.

**Fix:** run (c2) with `partition=` passed, as the CLI does. The first `_left` then fires inside
the main `try`, and the type check covers the re-wrap behaviourally. Keep the structural check as
well.
