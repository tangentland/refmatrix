## Findings {#findings}

### SKETCHY s1: a pending key left by a crash is terminal, and nothing ever clears it {#s1}

d10 fsyncs `pending` BEFORE the write runs. After a restart, a key that is still `pending`
answers `NotConfirmed` forever and is never re-run. The ledger is a separate file from the
store's commit, so it cannot tell two cases apart.

- (a) **Lost update.** The crash came between the fsync and the op's commit (or the op never left
  `bg_pool`'s queue). The write never happened, and the design forbids running it.
- (b) **Stuck.** The write landed but `done` was not appended. The key reads "may have completed"
  until LRU eviction (7 days or 10,000 keys) forgets it. After that, an outbox entry that still
  carries the key, or a model re-submit, would run the write a second time.

Nothing in 24.5 says what the outbox does with `NotConfirmed` (503). d10 "stops at the first
busy", so if `NotConfirmed` reads as busy, the FIFO head is retried forever and every later STM
event waits behind it until overflow drops it.

**Fix:**
- Settle the key atomically with the effect:
  - a DuckDB-backed write records the key in the same transaction (an idempotency table), so
    after a crash, present means landed and absent means safe to re-run;
  - a ring / JSONL write dedupes on a natural key it stores (the `row_uuid` / `tool_use_id` path
    24.2a R3 already has), declared on `@verb(idempotent_by=…)`, so a re-run is harmless.
- Keep `NotConfirmed` only for writes that can do neither, and make it terminal for the outbox:
  drop the entry with a toast and a transcript line, never retry it.
- Cap outbox entry age below the ledger's retention.
- Add ACs:
  - crash between the fsync and the commit, then the write re-runs exactly once;
  - an outbox head answered `NotConfirmed` does not block the entries behind it.

  ([[feedback_no_raw_prompts_in_public_repo]]).
- **m2: three meanings share 503.** 24.2 R6 uses 503 for `NotConfirmed`, `VerbBusyError` and the
  full wait lane. 24.4 AC-2 says "each status maps to its class". Map by `error.type`, and test
  503 with each type.
- **m3: the AST gate misses helper defaults.** 24.2a R13's gate scans verb BODIES only. The
  default bounds in helper signatures stay outside it:
  - `_call` 60 s;
  - `session_memories` 60 s (verbs.py:2150);
  - 30 s and 120 s helpers at verbs.py:629 and :697.

  Modes computed from `timeouts` can then undercount. Extend the gate to helpers a verb calls, or
  declare those bounds as keys.
- **m4: stale wording in 24.2.** d12 says "a third pool" (there are five lanes now). AC-15 says
  the save-state job "starts at once on the write lane"; it means the job-write lane.
