## Findings {#findings}

### SKETCHY S1: "named identifier" accepts plain English, both in scan's tier 1 and in the composite's grounded filter {#s1}

**File:** `scan.py` `_is_named_identifier` (and the JSON path's copy), which uses
`_token_shape_score(name) > 0.0`. `composite.py` `_has_grounded_member` uses
`"." in m.strip(".") or _token_shape_score(m) > 0.0`.

**What:** `_token_shape_score` gives:
- +0.5 to any token of 12 or more characters;
- +1.0 to any token containing `-` or `.`.

So "> 0" admits ordinary prose. Probe `probe_named.py`, prompt "Please review the implementation
and architecture of widget_registry; follow-up on daemon measurements and relationships":

```
shape: widget_registry 1.5, implementation 0.5, architecture 0.5, measurements 0.5, relationships 0.5
tier 1 header: "context for prompt-mentioned symbols: implementation, relationships, measurements, architecture"
```

Four plain words outrank the content section, which is the inverse of the user's ask (1): plain
words belong in tier 3. In the composite filter, any member of 12 or more characters, or any
dotted fragment (`e.g`, and tool-ref junk such as `t.repla`, `p.read`), makes a plain-word topic
"grounded".

**Fix:** one shared predicate requiring a STRUCTURAL signal, used by both sites:
- underscore, `::`, a path `/`, CamelCase, an acronym, or a digit together with a separator
  (`bug-241`, `task-29.5`);
- a dot only between identifier segments of 2 or more characters;
- never the length bonus alone, and never a hyphen between two plain alphabetic words.

RED: the four long words land in tier 3, and a topic of `implementation, e.g, architecture` is
not emitted.

### SKETCHY S2: the reorder happens after the PPR rerank and the `max_concepts=5` cut, so a named identifier can be cut before it is ordered {#s2}

**File:** `scan.py` `scan_prompt`, which computes `matches = _dedup_twin_concepts(_ppr_rerank(...))[:max_concepts]`
before `first` / `rest`.

**What:** probe `probe_matches.py`, on the throwaway repo-copy store with the real hook prompt:

```
matched (salience): finish, scan-prompt, drop, fix, bundles, marker, things, composite, named, check, also, ordering, like
after ppr + max_concepts=5: finish, bundles, like, check, drop
identifier-shaped matched but cut: ['scan-prompt']
```

On the REAL hook run at the tip, tier 1 was therefore **empty**. The prompt named `scan-prompt`
(and `_finish`, matched as the plain concept `finish`, which then fails the named test), yet the
five sections are `finish, bundles, like, check, drop`. The new order can only reorder what
survived a cut that prefers PageRank-central plain words.

**Fix:** reserve the slots. Named identifiers (S1's predicate, against the prompt's candidates)
go first and bypass the cut: `first = named[:max_concepts]`, then
`rest = ppr_rerank(others)[:max_concepts - len(first)]`. Match an underscore-prefixed candidate
(`_finish`) by its stripped form for the named test. RED: the real-hook prompt keeps
`scan-prompt` in tier 1.

### SKETCHY S3: the composite is marked "sent" when rendered, not when delivered; a composite the byte budget drops is then suppressed as unchanged {#s3}

**File:** `composite.py` `build_topic_composite` writes `stm/<session>.composite.last` whenever
`_render_gmd` returns text. `scan.py` `_finish` appends the composite as the LAST block, and
`fit_blocks` drops it whenever the sections fill the budget.

**What:** probe `probe_composite_marker.py`:

```
unbounded: composite present: True
max_bytes=2029 (room for all but the composite): composite delivered: False | marker written: True
next prompt, NO byte cap: composite delivered: False
```

With sections now reaching about 8 kB of the 9 kB budget, the composite is the block most often
dropped. Once dropped, it is never re-sent while the topics are stable. That contradicts the
user's ask (3), "keep the mechanism", and the module's own "fail-open: … the composite is sent,
never lost".

**Fix:** mark on delivery.
- `build_topic_composite` returns the signature, or takes `record=False`.
- `scan._finish` writes the marker only when the composite block is within `fitted.kept`.
- Callers without a fit (the CLI composite verb) mark as before.

RED: the probe above; the second prompt must carry the composite.

### MEH M1: the marker survives compaction, so after `/compact` an unchanged composite is never re-sent {#m1}

**File:** `composite.py` marker `stm/<session>.composite.last`. Nothing else references it (grep).

**What:** compaction keeps the session id, so the marker still says "sent" after the model lost
that context. It stays suppressed until the topic member sets change. Member sets churn with
focus, which is why this is MEH.

Pre-existing side note: the scan path passes no session, so the composite and its marker follow
`latest_session(root)`, the most recently written ring.

**Fix:** remove the session's marker in the PreCompact hook, or on SessionStart `compact|clear`.

### MEH M2: stale "0.9" text in `hook_budget` {#m2}

the comment above `CHANNEL_BUDGET_BYTES` ("at or under the 9,000 B command budget").

**Fix:** say 0.95 and 9,500.
