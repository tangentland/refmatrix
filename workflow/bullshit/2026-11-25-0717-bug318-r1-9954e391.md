(`_git_call_repo`, docstring "`cd X && git ...` is not followed"), used at :2420 and :2469.

commit/merge commands across the session's transcripts. Probes through the hook entry point

no git event; `cd B && <failed commit>` while A moved records `commit c019ddc lead: unrelated` plus

WHY. Fix: resolve the repo per git call by following `cd`/`pushd` within the chain/subshell (or a
per-candidate reflog window); a test with envelope cwd != repo. Self-audit: "did you run the new
capture on the motivating real data?" {#b1}

**B2: only the first ref-moving call in a command counts.** `cli.py:2149-2158` (`c[0]`).

session (one is `0f913155`). Fix: evaluate every (verb, repo) pair; label by the strongest content
verb that moved; harvest per moved repo. Self-audit: "does the rule hold for every call, or only
the first?" {#b2}
