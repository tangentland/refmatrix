### Q2: the checkout test, exit 2 from `get-url`, and the cost {#q2}

**`rev-parse --show-toplevel` must name the path.** This is right, and it is stricter than the
first draft's `.git` test. It correctly rejects:
- the empty `.git` marker roots of the bug-179/216/230 fixtures;
- a plain dir inside another repository (`it lies inside the checkout …`);
- `<path>/.git` given as a root (`fatal: this operation must be run in a work tree`).

Every rejection carries git's first line into the note.

**Exit 2 from `remote get-url`.**
- `git-remote(1)`, as installed, has an EXIT STATUS section: "can't find the remote … exit
  status is 2"; "any other error … any other non-zero value".
- Measured: `/usr/bin/git` 2.50.1 (Apple Git-155) and `/opt/local/bin/git` 2.54.0 both exit 2
  with `error: No such remote 'origin'`, and 128 for a non-repository.
- Older gits died on a missing remote (exit 128). The resolver would then raise, and the gate
  would exit 2 with the message. That is loud and not silent. It cannot happen on this
  machine: macOS has shipped git ≥ 2.39 since Xcode 14. The exact release that moved this to 2
  is from memory and was not verified here, so no finding is filed.

**Spawns.**
- When the own-slug dir is populated (the main tree), there are none.
- Otherwise there are `2N+1` for N hops followed: one `rev-parse` on the root, then for each
  hop one `get-url` on the current checkout and one `rev-parse` on the next.
- Measured through a shim:
  - main tree: 0;
  - `t01-green` (1 hop): 3;
  - review clone and `t01-cofc` (2 hops): 5.

**Wall time** (median of 20, `PYTHONDONTWRITEBYTECODE=1`):

| main tree | 5.4 ms | 25.1 ms |
