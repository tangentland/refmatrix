## Findings {#findings}

### BULLSHIT B1: the walker output rows of G22's R2 table are unreachable, and AC-5 asserts the impossible {#b1}

**File:** `task-dq1-operational-content-out-of-graph.md`:
- R2 table rows `ppr.py:229, :301`, `net.py:195`, `enrich.py:163` and `scan.py:825` ("ranked last (today: dropped)");
- the row `pagerank.build_adjacency(exclude_operational=True)` ("excluded from the adjacency (nodes and edges)");
- AC-5 ("`ppr` / `net` / `enrich` results for `alpha` contain `p.md`, ranked after every non-operational entry"; "scan-prompt's PPR expansion keeps a non-seed `p#a` after every non-operational candidate"; mutations "the output sites keep dropping" and "scan's PPR filter is called by name only").

The same wording appears in ADR-0003 `#d-2026-11-14-dq1` and in the appendix memory.

**What:** every walker builds its graph from `build_adjacency` with the default `exclude_operational=True`:
- `ppr.py:211` and `:269`;
- `net.py:139`;
- `enrich.py:126`;
- `context.py:637-643` through `pagerank.cached_adjacency`.

Under R2, `build_adjacency` drops every `operational_ids` member, both its nodes and its edges. A walk can therefore never reach `p.md`, `p#a`, a save-state or a digest.

The consequences:
- The "rank last" code at all five walker sites is dead code.
- AC-5's walker assertions fail on correct code.
- The two mutations above cannot fail, because the output is the same with or without them.
- Seeds go too: `rank_related_for_prompt` keeps only `present = [sid for sid in seed_ids if sid in adj]`. A prompt that names an operational entity loses it as a PPR seed, so the table's "seeds exempt" at `scan.py:825` and R3's exemption cannot hold on any walk.
- The walk legs (`context.py:671`, scan expansion, `rmx net`, enrich) newly REMOVE `workflow/` docs, which contradicts "Output sites never remove an entry".

**Origin:** L61 S3 ruled both "derivation sites (pagerank …) exclude operational ids from their inputs" and "output sites (ppr, net, enrich, scan …) never remove, only rank last". The walkers are downstream of the pagerank adjacency, so the two halves of that ruling conflict. My r3 S3 asked for a per-site table without naming this coupling.

**Fix (lead ruling needed; it amends L61 S3):** recommended option (a): walkers inherit the derivation exclusion.
- The ppr, net, enrich, scan-PPR and context-walk rows read "unreachable: excluded by the adjacency; the site's check is deleted", not "ranked last".
- AC-5 asserts that walk outputs never contain an operational id. Mutation: `build_adjacency(exclude_operational=False)`, and `p.md` appears.
- State R3's exemption as applying to the name-matched legs only: the `content_rank` hit lists, scan's matched-concept injection, and the recall pack. A named operational entity never seeds PPR. Add an AC that scan-prompt naming `p` still injects `p.md` through the match leg.
- Option (b), keeping operational nodes in the adjacency and ranking them last at output, would put them back into the `pagerank` derivation and reverse D-Q1.
- Fix ADR-0003 `#d-2026-11-14-dq1` and the appendix memory text to match.

**Pattern match:** YES. This is `imp-widening-fold-breaks-identity-clauses` again: a ruling's two clauses interact through a shared input, and the reviewer prompted the split.

### SKETCHY S1: the memdir copy's slug still resolves to the live project store {#s1}

**File:** G22 R4 recipe, "The memory dir is a COPY of this project's memdir under the sandbox. The bridge is pointed at the copy … so it can only resolve to the sandbox store". ADR-0005 `#store-resolution` (`docs/adr/0005-memory-dir-layout.md:151-165`).

**What:** ADR-0005 resolves a memdir's store from its unresolved path `~/.claude/projects/<slug>/memory` via `_root_from_projects_slug`, never from the cwd. A copy keeps this project's slug, which decodes to `/Users/tholley/claude_tools/refmatrix`, the live project root with a live `.refmatrix/`. So a redirected `$HOME` alone does not make the bridge resolve to W or N. At best the 23.0 sandbox guard refuses and the build fails. At worst the bridge targets the live store's daemon. One memdir also resolves to exactly one store, so W and N cannot share a copy.

**Fix:** state per build that W's copy lives at `$SANDBOX_HOME/.claude/projects/<slug of W's unpacked root>/memory`, and N's at N's slug. `eval/dq1/build.py` prints each bridge run's resolved store root and asserts it equals W's or N's root. Add an AC or a recipe check: a mis-slugged copy makes `build.py` exit non-zero before any write.

### MEH M1: the on-disk adjacency cache has no predicate version {#m1}

`pagerank.cached_adjacency` (`pagerank.py:172-215`) serves one-shot processes from `.refmatrix/adjacency.cache.npz`. Its key is `(partition, link_weight, exclude_operational, mentions mode, facts.log size)`. After the deploy, the CLI context walk and the scan-prompt hook keep reading an adjacency built with the OLD regex (save-states, digests and `workflow/` included) until that store's `facts.log` grows. On a quiet fleet store that can take a long time. R1/AC-6 cover `_operational_ids_cache` only.

**Fix:** add the predicate's identity to the disk key (for example a `memory_layout.OPERATIONAL_RULES_VERSION` constant or a hash of the module), plus an AC: a cache file written under the old key is rebuilt.
