## Check 2: does the batch-id intersection reproduce HEAD's links and never over-link? {#intersection}

**It reproduces HEAD's links in both orders.** HEAD's final link set is: for every batch id T,
every path-less concept that exists at batch end and is either a spelling of T or reached from one
over `same_as` (`b216_store.py:6029-6086`). Every such concept is linked by one of two paths:
- **It existed before the batch.** It is linked at T's own step. If T was admitted, T's tail passes
  T's id; if T was skipped, `gmd_finish` passes it.
- **A batch document D wrote it.** D's write set holds that name, or one of its variant rows
  (`_bulk_add_concepts` writes the canonical name plus its variants). That name is in
  `spellings(T)`, so the intersection hands T to D's step.

Only the variant expansion writes same-batch `same_as` edges, and those link spellings of one
canonical name.

**It cannot over-link.** Concepts and `same_as` edges only grow inside a batch. So a per-step
`link_denotes(T)` sees a subset of what the batch-end call sees, and every link it writes is one
HEAD writes too.

**`denotes_added` is not double-counted.** `bulk_link` writes through: it is not buffered by
`deferred_links` (`b216_store.py:4972-5050`). So a later step's `have` read sees an earlier step's
links.

**The premise holds.** The bare-id root node mints no concept (`b216_ingest_gmd.py:1550-1559`), so
a body-term concept `m_one` is path-less and `link_denotes` can see it.

### SKETCHY S1: "`gmd_prepare` does no store I/O" contradicts 26.2's walk-wide memory gate {#s1}

**File:** `task-bug185-bulk-gmd-ingest.md:287-289`.

**What:** `gmd_prepare` "does no store I/O, so it runs OFF the lock … The resume gate's stored-hash
read stays in `gmd_pass1_document`".

**Why:** On the `--as-memory` path, HEAD reads the store for the whole walk BEFORE the pass-1 loop
(`b216_ingest_gmd.py:1352-1357`): `mem_rows` (one `_memory_row` per document), `walk_eids`, and
`_SourcePathIndex(store, None)`. Every `_memory_gate(…, walk_eids=walk_eids)` call needs every
document's id row. The spec leaves three readings open, and none is safe:
- Moving the reads into each `gmd_pass1_document` call changes 26.2's gate.
- Keeping them in `gmd_prepare` breaks the contract the spec states.
- Doing them in the first pass-1 step is never said.

AC-2's `as_memory` golden would catch a wrong choice, but the spec still leaves the decision to an
unattended builder.

**Fix:** State the placement. Recommended:
- the walk-wide `as_memory` gate inputs are read once, in the FIRST `gmd_pass1_document` call,
  under its hold, as a constant number of statements, and kept in `GmdBatch`;
- with `as_memory=False` (23.3's sync path) `gmd_prepare` reads nothing.

### SKETCHY S2: "sync purges first, so R10 is a no-op there" is false for GMD documents named by id {#s2}

**Files:** `task-bug185-bulk-gmd-ingest.md`:
- `:429-431` (R10): "On the sync path `purge_path` has already removed the doc's node entities …
  a no-op there";
- `:551` (AC-2): "sync (`purge_path` first: the old node rows and their links are gone)";
- `:730` (AC-11): "The replace is a no-op there".

**Why:** `_sync_one` purges a GMD path only if a `doc` named by its RELPATH exists (`sync.py:216-218`
at `1cf3b9f`, unchanged on bug-216). A GMD document's `doc` is named by its GMD id. On a fresh
fixture store:
- nothing is purged on sync;
- R10 does real work there;
- stale node rows persist at HEAD, just as on the job path.

The purge fires only for documents carrying a legacy relpath `doc` row, such as the r1 probe's
live `IMPRESSIONS.md` (`_gmd_route_pending`).

**The risk:** a builder writes AC-11's sync leg as "no unlinks", or AC-2's sync v1 → v2 as "old node
rows gone". That test then fails against correct code. The cheap ways out are adding a purge to
sync or bending the assertion.

**Fix:**
- State the real rule: a relpath-named `doc` row triggers the purge; otherwise R10 acts on sync as
  it does on the job path.
- AC-11's sync leg asserts the equality it already names, not a no-op.
- AC-2's sync expectation is HEAD's golden, with no prose claim.
- The R10 census covers the sync path too.

### SKETCHY S3: the evidence-producer rule (`c8deca7`) is unbounded and cannot express its own example {#s3}

**File:** `task-bug185-bulk-gmd-ingest.md:433-454` and AC-14/AC-15 `:791-826`.

**(a) The census scope is the whole codebase, including bug-185's own writes.** It walks every
caller "whose linkage can equal a GMD `rel:` verb, literal or computed". GMD verbs are an open set
(custom verbs are legal), so every linkage qualifies. That includes the GMD ingest's own step-6/7
writes: hierarchy `part-of`, `imports`, `mentions`. Read literally, "in reach: fixed here" gives
them evidence rows. That changes `linkage_evidence` in AC-2's dump against HEAD's golden (R3 (a)),
and it adds one evidence row for every heading edge in every store.
- **Why the own writes need no evidence:** R10 can only unlink a key that the OLD text's `rel:`
  evidence named and the doc's own write set no longer states. So "stated" already protects the
  doc's own writes.
- **The real collision class:** another producer writing an edge whose CONCEPT side is a GMD
  doc, memory or node entity.

**(b) The signature cannot list the spec's own example.** The signature is
`(linkage, source kind, target kind)`, and the spec's example is `memory_link`. But `memory_link`'s
linkage is caller-supplied (`daemon.py:5426`, `:5434` at `1cf3b9f`: `link(linkage, cid,
m["id"])`), so no concrete linkage covers it. The spec defines no wildcard.

**(c) AC-15 contradicts the production list.** AC-15 expects `rel_unlink_skipped_unowned == 0`
and says "the fixture's signature is not in `UNOWNED_REL_PRODUCERS`". But R10 says `memory_link`
IS entered until bug-218 lands, and bug-218 lands after bug-185 (`#queue` 9 vs 5). If `c` is a
memory and the shipped list matches `(reinforces, memory, memory)` or a wildcard, AC-15's edge is
skipped (count 1). AC-15 never pins `c`'s kind or the state of the list.

**Fix:**
- Scope the census to producers that can write an edge whose concept side is a GMD
  doc/memory/node entity, and exclude this document's own pass-2 write set (protected by
  "stated").
- Allow a `*` linkage in a signature for computed-linkage producers, and pin `memory_link`'s
  pre-bug-218 entry exactly.
- AC-15: state `c`'s kind and run it against the list as shipped, with its expected count (or
  pin a doc target so the signatures differ).
