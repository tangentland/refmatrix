## Findings {#findings}

### BULLSHIT b1-r1: the recall-row channel fallback exists only for the test fixture, and it misclassifies {#b1-r1}

**File:** `src/refmatrix/telemetry.py:1230` (`_recall_flags_of`)
**What:** a `kind=recall` row without `session_start`/`stdin_json`/`recent` is classified by a
heuristic: a `hook` row with a body counts as `stdin_json`, and a `hook` row without one counts
as `recent`.
**Why it's bullshit:** no production row lacks the flags. No `kind=recall` row existed before
this task (`git grep 'kind="recall"' b335856 -- src` is empty), and both writers set the flags
on every row (`cli._RecallCall.close_row` runs in `finally`; `verbs.memory_recall` sets
`t.extra`). The only flagless rows are the ones `tests/test_task21_1_recall_skip.py::_row` writes.
That test's own docstring says "if GREEN needs a field to recompute it (e.g. the argv flags),
this fixture row must carry it". The heuristic is also wrong: a flagless query-less hook row
(the shape of a SessionStart recall) classifies as `precompact` (probe4:
`flagless hook, no body -> precompact`).
**Fix:** delete the heuristic and have the fixture row carry `stdin_json: true`. A row that
lacks the flags should be counted as such (`unflagged=<n>`), not guessed. Effort: about 5 lines.
**Pattern match:** YES. The test was RIGHT, and src was bent to a fixture shape (rule 10).

### BULLSHIT b2-r1: `record_miss` gate in src that resolves a spec contradiction to suit a test, with a false rationale {#b2-r1}

**File:** `src/refmatrix/verbs.py:538`, `:584`; `src/refmatrix/telemetry.py:439`
**What:** `resolve_session_source(..., record_miss=True)` gains a parameter, and
`resolve_event_session` passes `record_miss = invocation in (hook, mcp, agent)`. For an
`unknown` / `interactive` / `internal` call, an event-purpose miss is no longer recorded.
**Why it's bullshit:** R9 says "In all three, a miss is recorded exactly as bug-109 records it".
The docstring's reason ("recording a miss … would put a row in the log for every piped `rmx` a
human runs") is false. In a plain terminal there is no owner and no `$CLAUDE_PID`, so bug-109's
rule already records nothing. Under Claude Code `CLAUDECODE` makes every call `agent`/`hook`/`mcp`.
The gate changes behaviour in exactly one shape: `$CLAUDE_PID` set with no invocation hint. That
is how AC-4b (xiii)'s test runs (`rmx(..)` with `CLAUDE_PID=ME`), while AC-4 runs the generated
hook (`RMX_INVOCATION_SOURCE=hook`). The real problem is a spec contradiction: the AC-4b
preamble puts `CLAUDE_PID` on every child, and (xiii) says "adds no row". It was settled
silently in src. A side effect is that `internal` eval harnesses now drop their misses as well.
**Fix:** remove `record_miss`. Amend AC-4b (xiii) so it asserts that no `envelope-*` row is added
(the intent of "prose is not an error"), or run it without `CLAUDE_PID`, and record the decision
in the spec's revision table.
**Pattern match:** YES (rule 10, test-shaped branch).

### BULLSHIT b3-r1: unanchored deferral; delivered events with no spans in the default recall output {#b3-r1}

**File:** `src/refmatrix/cli.py:12637` (`rec.delivered = table_rows  # table output: delivered,
spans not captured`)
**What:** the default (table) output of `rmx memory recall <q>`, which is the agent's `recall`
channel, emits `delivered` events with `offset_bytes`/`bytes`/`payload_bytes`/`block_sha` all
null (`_RecallCall.emit` with `payload=None`).
**Why it's bullshit:** R10 makes those fields the definition of `delivered`, and 19.5 R2 derives
`seen` from them. The comment defers the gap to no plan and no task (rule 9a). 19.1's `--pack`
replaces the JSON renderer on the hook argv, not the table.
**Fix:** render the table to a string (`Console(record=True)` / `console.export_text`), echo it
through `rec.echo`, and span by name. The other option is to emit no `delivered` for table mode
and file a covering task.

### SKETCHY s1-r1: `context_by_name` excludes every context-channel delivery; R11's "exactly once" is broken {#s1-r1}

**File:** `src/refmatrix/telemetry.py:1513` (`context_used_keys`), `:1415-1431`
(`emit_context_call`)
**What:** a key counts as used only if a non-`context` surface delivered it. The real problem was
that the call's own just-emitted delivery was being found by its own lookup. The right fix
excludes this `query_id`, or looks up the delivered set before emitting. As written, the
exclusion also drops earlier context calls' deliveries (`rmx context A` attaches memory M, then
`rmx context M` = no use). That deviation is undocumented. `emit_context_call` also calls
`emit_recall_events` twice per call (delivered, then used). That breaks R11's "EXACTLY ONCE per
call" and contradicts `used_events`' own docstring ("in its one `emit_recall_events` call").
**Fix:** compute the used keys before emission with `query_id != this call's`, and append the
`used` events to the same single `emit_recall_events` call.

### SKETCHY s2-r1: 10 of 11 `record_pointer_error` call sites drop a failed write silently {#s2-r1}

**File:** `src/refmatrix/cli.py:1999`, `:2077`; `src/refmatrix/stm.py:621`, `:644`, `:651`,
`:654`, `:1845`, `:1851`; `src/refmatrix/verbs.py:586`, `:589`; also `stm.py:801`
(prune `except (OSError, ValueError): continue`, uncounted) and `drop_legacy_pointers_migration`
(`except OSError: continue`, uncounted)
**What:** D8 says "A failure to take the lock or to write is returned as `False` and, at every
call site that has a stderr, printed once". Only the `write-failed` site checks the return.
**Evidence:** probe3 fed the input hook an envelope with no `session_id` and no global root. Its
only output was `hook envelope carries no session_id`, and no `.refmatrix/` was created, so the
row was lost without a trace. In the generated hook stderr goes to `2>/dev/null`, so nothing at
all survives. This breaks the project's CRITICAL no-silent-failures rule on a memory path.
**Fix:** one `_record_or_say(reason, **kw)` wrapper that prints `rmx: pointer-error row not
recorded (<reason>)` on `False`, used at all 11 sites. Count the skipped prune and unlink files
in the `pruned=` line.

### SKETCHY s3-r1: the error-log scope key is not canonical; one store gets two scopes {#s3-r1}

**File:** `src/refmatrix/stm.py:545`, `:902` (writer `os.path.abspath(root)`); readers compare
`str(root)` raw (`_row_in_scope`, `_root_watermark_path` hash, `handoff.session_pointer_anomalies`)
**Evidence:** probe1 wrote a row scoped `/tmp/…/proj/.refmatrix`.
`session_pointer_anomalies(/private/tmp/…/proj/.refmatrix)` returned `[]` and the `/tmp`
spelling returned the row. `cli._root()` resolves the cwd walk, but returns `REFMATRIX_ROOT`
unresolved, and `mcp._resolve_root` keeps `args["root"]` as given. The writer and the reader of
one store can therefore disagree. `telemetry._norm_tmp` exists for exactly this case and
the sibling did not get it.
**Fix:** one `stm.scope_key(root) = os.path.realpath(root)`, used by the writer and every reader,
including the per-root watermark hash.
