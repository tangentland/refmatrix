## bug-198 on the production path {#bug-198}

- **Verb.** `verbs.memory(..., compile_scope: Literal["memory","pattern"] | None)` is validated
  before any daemon call: the MCP path's `Verb.run` does not enforce the Literal, so the body
  does. `_memory_payload("brief")` sends it under the wire key `scope` and no longer forwards
  recall's `scope`.
- **Schema** (generated, read live). `compile_scope` is
  `{"type":"string","enum":["memory","pattern"],"description":"brief only — …"}`. `scope` is
  described as "recall only — project|global|both … Ignored by every other action". The MCP
  `TOOLS["rmx_memory"]` schema carries `compile_scope`.
- **CLI.** `memory brief --scope` (`Choice(consolidate.SCOPES)`, default `memory`) maps to
  `compile_scope`, and `--compile` plans the same scope. The parity row `("memory","brief")`
  asserts `compile_scope="pattern", scope=None`.
- **End-to-end probe** (real daemon, merged tree, `bsd-bug197-198-r1-probe.log`):
  - `memory brief --json` gives orphans `{mem_only}`, scope memory, 5 memories.
  - `--scope pattern` gives `{imp_only}`, scope pattern, 4 memories.
  - `--compile --scope pattern` gives `{imp_only}`: the real plan's `scope` key agrees with the
    op's refusal check.
  - MCP `compile_scope=pattern` gives `{imp_only}`.
  - MCP with the old key `scope=pattern` gives `{mem_only}`, scope memory. See [[#m-1]].
- **Other callers.** Searched src (hooks.py, search_hooks.py, hub.py, mcp.py, handoff.py,
  templates/), eval/, scripts/, docs/ and workflow/plans. None passes a scope to `rmx_memory`
  brief or to the `memory_brief` op. Plan-24 task 24.6 calls `rmx_memory(action=brief)` with no
  scope, which is unaffected. Direct op callers exist only in tests.

**File:** `src/refmatrix/verbs.py` `memory` / `_memory_payload("brief")`;
`workflow/implementation_summaries/task-26.6-compile-subject-hygiene.md:184,231-233`
**What:**
