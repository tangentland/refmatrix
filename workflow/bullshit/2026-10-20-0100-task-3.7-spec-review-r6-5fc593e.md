## Findings {#findings}

### SKETCHY: curator `limit` means two different things {#s-1}

**File:** spec #fam-refine-drain; cli.py:9105 (`curator status --limit`, default 10)
**What:** The spec gives `status(limit=500)` a PAIRING row against the click option.
**Why:** The click `--limit` is the number of sample PATHS printed in the hook's context line.
The verb's `limit=500` is the ENTRIES read. The pairing either fails the defaults test, or it
makes the hook print up to 500 paths each prompt.
**Fix:** Give the verb parameter its own name (`max_entries`, with its own CLI option). The
click `--limit` stays a CLI-only render option, like `--out`.

### MEH: the curation verb's parameter name contradicts C9 {#m-1}

**File:** spec lines 255/262 vs #c9
**What:** The curation section writes `rmx_curate(name=…)` and "no `name` / `like`".
**Why:** C9 says params mirror the CLI 1:1, and the CLI parameter is `names` (nargs=-1). C9
itself cites `name` → `names` as its example.
**Fix:** Use `names` throughout.

### MEH: AC-family still says C1-C8 {#m-2}

**File:** spec line 420
**What:** AC-family 1 says "meet C1-C8".
**Fix:** Change it to "C1-C9 (incl. C4a)", so C4a and C9 carry an acceptance gate.

### MEH: the taxonomy lock target is unspecified {#m-3}

**File:** spec #fam-taxonomy-admin
**What:** The spec says "temp + rename under an `fcntl` lock".
**Why:** If the lock is on `taxonomy.json` itself, the rename swaps the inode, and the next
writer locks a different file. That is the same orphan shape r3/r4 hit.
**Fix:** Lock a sidecar file, `taxonomy.json.lock`, that is never deleted.
