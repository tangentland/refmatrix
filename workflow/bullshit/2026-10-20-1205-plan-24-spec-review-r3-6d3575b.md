## Findings {#findings}

### SKETCHY s1: `rmx_job` long-polls on the read lane, and the job lane is unfenced {#s1}

`rmx_job` is a read verb, so each poll holds a `verb_read_pool` worker (default 4) for up to
20 s. Two pending jobs plus one `prompt.submit` (scan, recall and curator status) is enough for
reads to time out with 504. 24.3 d8 gave the hub's long-poll its own pool for exactly this
reason.

Two more gaps:
- `verb_job_pool` (2 workers) is one FIFO for 180 s graph reads and for `rmx_save_state`. 24.6
  R11 bounds the pre-compact save-state at 30 s, but 24.5 R3 makes that save-state a submitted
  job.
- 24.2 R10 drains "both verb lanes"; the job lane is not mentioned.

**Fix:**
- Give `rmx_job` a wait lane of its own, or make it a no-wait poll.
- Split read jobs from write jobs, or reserve a write slot.
- Say how 24.6 R11's 30 s applies to a job.
- Add the job lane to R10.

### SKETCHY s2: a submitted write lost to a restart cannot be confirmed {#s2}

Jobs live in memory, so after a fast-exit `rmx_job` answers `unknown job`. Only outbox entries
carry an idempotency key (24.5 d10), so a model-tool write job has no key. That covers memory
promote / dedup / bulk_forget, save_state and curate forget / purge. The model sees a plain error,
retries, and the write can happen twice.

**Fix:**
- Every submitted write carries a key.
- `unknown job` on a keyed write re-submits with the same key, and the ledger answers
  `replayed`.
- The unconfirmed case uses the "not confirmed … may still complete" wording.
- Add an AC that kills the daemon mid-job.

### SKETCHY s3: the mode rule cannot be computed where it says {#s3}

24.5 d16 has `modgen` derive each mode "from the verb's defaults and `ACTION_DEFAULTS`". In 3.7,
`ACTION_DEFAULTS` holds only `rmx_focus` rows (verbs.py:1334). The long timeouts are literals
inside function bodies:
- curate: `float(timeout) if timeout is not None else 600.0` (verbs.py:2045);
- memory: `_left(180.0)` (verbs.py:1196) and `_left(120.0)` (verbs.py:1243).

AC-14's "computed equals the table" can therefore only pass if someone hand-copies the table.

24.4 also lacks the pieces the rule needs:
- `ROUTES` has no `modes` field (R1, AC-2);
- `client.ts` handles neither `mode: "submit"`, a 202, nor `rmx_job` polling.

**Fix:**
- Declare the per-action timeouts on `@verb`. They join the schema hash, the bodies read them,
  and a parity test checks no literal remains.
- Add `modes` and submit / poll to 24.4 R1 and AC-2.

### SKETCHY s4: the hub has no job lane {#s4}

24.5 R3 routes a tier-`both` verb to the hub when `scope=global`, and lists `rmx_memory` write
actions (120 s) as submit-then-poll. 24.3 has no R13 equivalent, and `rmx_job` is store-tier.

**Fix:** 24.3 reuses `httpsock`'s job lane and adds a hub-tier `rmx_job`, or `scope=global` long
writes are specified another way.

### SKETCHY s5: 409 now means two things {#s5}

24.2 d10 / R8 answer `InFlight` with 409, which R6's table already uses for a schema mismatch.
Neither R6 nor 24.4's `errors.ts` has an `InFlight` row.

A generated client that maps 409 to `SchemaMismatch` would treat an in-flight replay as a schema
mismatch (and might drop the outbox entry). 24.5 intends to retry it as busy.

**Fix:** give `InFlight` a distinct status or `type`, add it to R6 and `errors.ts`, and add a
24.5 AC that an outbox replay meeting `InFlight` is retried.

### SKETCHY s6: the /clear re-seed can unregister every tool {#s6}

24.5 R11 passes `next(e)` for names not in "the session's registered set". R16 resets "per-session
module state" when the id changes.

The tools stay registered in the engine. With that set reset, every model tool call after
`/clear` falls through to `next(e)` with no MCP server below, and "a call no hook answers fails"
(types).

R16 also says "re-key the outbox". Rewriting the session of a queued entry would attribute the old
session's STM events to the new one.

**Fix:**
- The registered set is process-scoped; only the collision path empties it.
- Outbox entries keep their original session.
- Add both to AC-12.

### SKETCHY s7: 24.6 d9 and AC-5 contradict each other {#s7}

the guard, so the AC pins the old rule.

**Fix:** align AC-5 with d9.
