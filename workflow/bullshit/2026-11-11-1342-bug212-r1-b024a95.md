## Findings {#findings}

### BULLSHIT: the store gate trusts file presence, and the repos it names track their catalog files {#b-1}

**File:** src/refmatrix/hooks.py:61-73 (`_store_gate`), src/refmatrix/store.py:39-52 (`WRITER_CATALOG_FILES`), tests/test_bug212_hooks_in_worktrees.py (fixture `repo`)

**What:** the gate is "exit 0 unless one of `catalog.A.duckdb`, `catalog.B.duckdb`, `catalog.duckdb` or `catalog.db` exists under `$ROOT/.refmatrix/`". The `_store_gate` docstring says it fixes "Fleet repos (cliquet, atldb, viascope) [that] TRACK `.refmatrix/CLAUDE.md`".

**Why it's bullshit:** two of those three repos track their **catalog files**, not just `CLAUDE.md`. In their worktrees and clones the gate passes and the incident repeats.
- cliquet tracks catalog.A/B/duckdb (21.8 / 4.7 / 7.4 MB) on both HEAD and `main`. It also tracks `active`, `rmxd.pid`, `daemon.lock` and `read_only.duckdb`.
- atldb tracks all three catalog files on its checked-out branch `cycle_query_5.0`.
- prep_prolific tracks `catalog.duckdb` on `master`.

The RED fixture *asserts* `tracked == [".refmatrix/CLAUDE.md"]`, so the suite can only prove the layout viascope has. Nobody checked the fleet.

**Evidence:** a throwaway repo that tracks `.refmatrix/catalog.duckdb`, with the generated hooks installed:
- `git worktree add` is silent, because the null-sha skip works.
- A commit in the worktree runs `rmx sync --since HEAD~1` there. With no daemon in the worktree it goes in-process and **writes into the git-tracked catalog**: `git status` shows ` M .refmatrix/catalog.duckdb`.
- A plain `git worktree remove` then refuses: `fatal: '…/wt2' contains modified or untracked files, use --force`.
- With `--force` during the backgrounded post-commit, the terminal prints `Error: the working directory no longer exists (…/wt)…` and then `refmatrix: post-commit rmx sync FAILED (exit 1); its error is above`.
- In a fleet cleanup done with `commit -a`, the mutated catalog binary gets committed into cliquet's history.

**Fix:** a gate that the tracked layout cannot pass:
- `[ -S "$ROOT/.refmatrix/rmxd.sock" ]` (git cannot track a socket), **or** a writer catalog file exists **and** `git -C "$ROOT" ls-files -- <those names>` prints nothing.
- Render it from `WRITER_CATALOG_FILES`, as now.
- Optionally also `[ "$(git rev-parse --git-dir)" = "$(git rev-parse --git-common-dir)" ] || exit 0` for linked worktrees.
- RED cases: a tracked-catalog fixture (with `active` tracked) in a worktree and in a clone, for all four hooks. Keep the main-checkout guard.
- Separately, log a registry row: cliquet, atldb and prep_prolific track live store files. A branch switch in their main checkouts rewrites a catalog under a running daemon. Untracking them (`git rm --cached` plus a `.gitignore`) touches fleet repos and needs the user's decision.

**Pattern match:** YES — imp-registry-fix-vs-spec-acs. The registry Fix column said "a store (`.refmatrix/catalog*.duckdb` **or the daemon socket**)"; the socket half was dropped. Also imp-fleet-trunk-tree: check each repo's real tracked tree, not a model of it.

### SKETCHY: a vanished cwd is still a raw traceback once REFMATRIX_ROOT is set, which is the fix the new error message tells you to apply {#s-1}

**File:** src/refmatrix/cli.py:98-113 (`_cwd`), src/refmatrix/discovery.py:100,269 (`Path.cwd()`), src/refmatrix/sync.py:163,283, src/refmatrix/mcp.py:63, src/refmatrix/cctree.py:1297…, src/refmatrix/cli.py:7109 (`_os.getcwd()`)

**What:** `_cwd()` guards the 7 `Path.cwd()` sites in cli.py. With `REFMATRIX_ROOT` unset, `_root()` reaches it first, so every command I tried fails cleanly: grep, context, memory list, query, daemon status, recall-state, stats, sync.

**Why:** contract 4 says "a vanished working directory is never a traceback", and the error text says "cd to a project, **or set REFMATRIX_ROOT**". With `REFMATRIX_ROOT` set, `rmx sync --since HEAD~1`, `rmx stats`, `rmx grep …` and `rmx context foo` from a deleted cwd all exit 1 with `FileNotFoundError` raised at `discovery.partition_marker:269` (via `_resolve_partition`); `version` and `memory list` exit 0. The contract-4 tests strip `REFMATRIX_ROOT`, so they cannot see this. The docstring's claim "Every cwd read in this module goes through here" is also false: cli.py:7109 `_cwd = _os.getcwd()` remains in `_grep_rg_fallback`, and its replica caller passes `project_root=root.parent`, not the cwd.

**Fix:** one shared cwd helper (for example a `CwdGone(RuntimeError)` in a small module) used by `discovery`, `sync`, `mcp`, `cctree` and cli.py:7109, converted to the same `Error:` line in `main`. Add the contract-4 parametrization with `REFMATRIX_ROOT=<a tmp store>`.

**Pattern match:** YES — imp-loudness-is-a-census-of-entry-points: the guard covers the module the test touched, not every cwd read.

### SKETCHY: the 0.83.0 fleet re-install has no verifier, and the 0.82.0 one already missed two repos {#s-2}

### MEH: post-commit on a root commit is a loud "failure" and indexes nothing {#m-3}

**File:** src/refmatrix/hooks.py (post-commit body, `rmx sync --since HEAD~1`)

**What and why:** in a fresh repo with a store, the first commit prints `Error: sync --since HEAD~1 failed: git diff exited 128: fatal: ambiguous argument 'HEAD~1': unknown revision…` and then `post-commit rmx sync FAILED (exit 1)`. sync.log is never written, so the root commit's files never index. This is the sibling of the null-sha skip: the initial checkout was handled, the initial commit was not. Under 0.82.0 the same case was a traceback.

**Fix:** `git rev-parse -q --verify HEAD~1 >/dev/null && SINCE=HEAD~1 || SINCE=4b825dc642cb6eb9a060e54bf8d69288fbee4904` (the empty tree), so a root commit is synced rather than skipped, plus a test.

**Pattern match:** YES — feedback_check_the_sibling_condition.
