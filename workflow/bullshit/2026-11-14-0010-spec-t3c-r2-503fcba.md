## Findings {#findings}

### SKETCHY: the as-of filter reads an env var that never reaches the processes holding the store; C's partial env is undefined {#r2-s1}

**File:** `task-28.1-session-arms-and-push-switch.md:70` (a7), `:102-113` (R3, R4); `task-28.2-paired-reentry-runner.md:52-54` (R0 a), `:106-108`.

**What:** R4 applies `as_of_admit` "at the point where memory rows leave the store", gated on
`RMX_HANDHOLD_AS_OF`. The env is exported into the `claude` process. R0 (a) proves only that it
reaches the hooks, the MCP server and Bash calls: the clients.

**Why it's sketchy:** The rows leave the store in other processes.
- The global leg is `verbs.global_recall_rows` → the hub's global store, a launchd process that
  never sees the env. That leg is the leak S1 named (`cli.py:12228`, `--scope both` in every
  generated recall hook).
- The clone's project rows come from its daemon, which may have been started before the env.

A filter placed where rows leave the store therefore reads no env on exactly the path it exists
for. A builder who follows R4 literally builds a filter that is off in the hub.

There is a second gap. R3 says `paired_override` reads three names, and that a bad cell falls
back with `arm_error`. Yet C runs with `RUN` + `AS_OF` and **no** `CELL` (28.2:106). R3 never
says whether a partial set still yields the as-of. If "all three or None", C gets no filter, and
the unequal leak returns with its direction reversed.

**Fix:**
- Put the admit at the client, after rows return to the process that holds the env (the verb and
  CLI/MCP render), or pass `as_of` as an explicit op argument to the daemon and the hub.
- Have R0 (a) probe the global leg end to end: a global row written after the as-of is absent
  from a paired run's recall.
- Define `paired_override` for `CELL` unset with `AS_OF` set: as-of on, no cell. Add an AC-7
  case run under C's exact env.

**Pattern match:** NO.

### SKETCHY: 28.1 AC-6's run id fails 28.1 R3's own validation {#r2-s2}

**File:** `task-28.1:105` (R3: a run id must match `^[a-z0-9-]{8,64}$`) vs `:180-181` (AC-6:
`RMX_HANDHOLD_RUN=r-0001`, expecting arm file `B`, source `paired`, run `r-0001`).

**What:** `r-0001` is 6 characters. Under R3 it gives `arm_error` and `A+dedupe`, so AC-6 cannot
pass as written. An unattended builder must edit either the spec's regex or its AC.

- Add an AC-6 case that a 6-character id is refused with `arm_error`. This is the mutation:
  the length bound dropped.
- Name the runner's id format in 28.2 R2, so the clone path and the env agree.

**Pattern match:** NO.
