## Findings {#findings}

### SKETCHY: the documented agent drain cannot carry the token {#s-1}

**File:** templates/agents/gmd-curator.md:136-150, :692 (and the installed copy)
**What:** The template has the agent run `rmx curator status > /tmp/snap.txt` and later
`rmx curator drain` with no token.
**Why:** Under the new spec, a drain with no token is a `VerbArgsError`, so the gmd-curator
agent's documented step fails.
**Fix:**
- `curator status --json` emits the token.
- `curator drain --token <names…|@file>` passes it back.
- Rewrite both template copies to that flow, and give the CLI twins' PAIRING rows the `token`
  parameter.

### SKETCHY: "an OSError is raised" collides with a concurrent drain {#s-2}

**File:** spec #fam-refine-drain
**What:** The hook's `status --drain` and the agent's `status` can run at the same time.
**Why:**
- A file that is listed and then unlinked by the other drain before it is opened raises
  ENOENT.
- The second caller's legacy `os.rename` also raises ENOENT.
**Fix:** ENOENT while reading or renaming means "taken by a concurrent drain". Skip the file,
keep it out of the token, and list it in `missing`. Every other `OSError` is still raised.

### MEH: tmp leftovers and ordering are unspecified {#m-1}

- A crash between the write and the rename leaves a `.tmp` file. The no-unlink rule forbids
  cleaning it, so it leaks forever.
- Readers must glob `*.jsonl` only.
- The daemon may delete its own `*.tmp` files at startup; this is the one other allowed
  deleter, and the grep test should allow it.
- The name prefix is a fixed-width, zero-padded `time_ns` so that names sort oldest-first.

### MEH: spool growth and hook cost {#m-2}

**What:** A store with no Claude session never drains its spool.
**Why:** The spool grows by one file per flush. `status --drain` on the next prompt then reads
every file, inside the hook's budget.
**Fix:** Set an entry limit on status, so a drain removes only the files it read. Report the
spool's file count and size in `status`.
