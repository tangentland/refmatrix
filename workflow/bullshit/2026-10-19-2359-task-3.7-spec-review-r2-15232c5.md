## Findings {#findings}

### BULLSHIT: the curator design's ONE implementation parses a format the watcher never writes, and the scheduler drains outside the lock {#b-1}

**File:** gmd_curator.py:29-46, 79, 111; daemon.py:3127; tests/test_onboard_huballd_curator.py:56; cli.py:9123-9131
**What:** The spec makes `gmd_curator` the one curator implementation.
**Why:**
- `read_queue` treats each line as a raw path. The watcher writes JSON objects
  (`{"ts","path","reason"}`).
- Its test fixture feeds raw paths, so the test passes against a format the watcher never
  produces.
- The scheduled `curator scan` therefore finds zero files, then `scan_and_enqueue(drain=True)`
  unlinks the queue. The scheduler silently destroys the queue and bypasses the new token and
  lock.
- `curator status` drops undecodable lines with `continue` and returns on `OSError`, both
  silently (C8).
**Fix:**
- One JSON-lines parser for status, scan and drain; count undecodable lines as `warnings`.
- `scan_and_enqueue` drains only through `drain(token)` under the same lock.
- The fixture uses the watcher's format.
- Log a bug row.

### SKETCHY: the drain token has no file identity, and the lock target is unspecified {#s-1}

**File:** spec #fam-refine-drain; hooks.py:181/241 (`status --drain` every prompt)
**What:** The token is a bare byte length.
**Why:**
- The hooks unlink and recreate the queue on every prompt. A token taken from file A, applied
  to a recreated file B of at least N bytes, deletes B's unrelated prefix.
- If the lock is a flock on the queue file and drain rewrites by rename, the watcher can lock
  the old inode and append to an orphaned file.
**Fix:**
- token = `(st_dev, st_ino, size)`; a mismatch is a `VerbError` "queue changed since status".
- Lock a sidecar `curator.queue.lock`, which the watcher's append and every drain take.
- Drain truncates in place, or rewrites the tail, under that lock.

### SKETCHY: the absent-daemon policy is undecided outside snapshot_read; a stale snapshot is read as current {#s-2}

**File:** spec #c3/#c5/#budgets/#fam-session (line 263); verbs.py:263-275; tests/test_describe.py:149-188; tests/test_subject.py:11/134
**What:** With no daemon, `_call` raises `VerbAbsentError`.
**Why:**
- That covers describe, subjects, recall, dense, the session reads, and every matrix, curate
  and canon-link write.
- Today's CLI serves all of these in-process with no daemon, and the suite relies on it
  ("All daemon-down (in-proc)"). That invites bending the tests.
- `snapshot_read` with no daemon but an existing snapshot reads a dead daemon's stale copy.
  A write made in-process then disappears from the next read.
**Fix:**
- Per family, either absent ⇒ in-process (reads via `snapshot_read`'s in-process branch;
  writes via a `_memory_write`-style `local()`), or record the decision to require a daemon
  and rewrite the tests openly.
- `snapshot_read`: no daemon ⇒ in-process even when a snapshot exists, or label the result
  `stale: true`.
- Reconcile line 263 with the budget table.
