- 2026-11-09 (plan-25 spec r3, 2f64edb): **COUNT A PRE-REGISTERED BAND'S DENOMINATOR BEFORE ACCEPTING THE BAND.** 25.5's 1% / 5% bands read the path-less leg of `query.log`: 35 rows in refmatrix, 0 in cliquedb, no flags logged, so one call moves 2.9 points and the "pre-registered" outcome is decided by one or two calls. A band needs a named source, a named denominator, a minimum n, and a default for below-minimum. {#imp-count-the-band-denominator}
- 2026-11-09 (plan-25 confirm r4-lite, cdd6720): **A CITED PRECEDENT INCLUDES THE BRANCH IT RUNS IN, AND A PRESCRIBED JOIN NEEDS ITS KEY ON BOTH SIDES.** d10 copied 3.7's `shared_embedder` "exactly as its graph verbs do" but dropped their `except VerbAbsentError:` condition, so daemon-up/hub-down would spawn private workers. My own r3 fix joined logs "by pid and ts" when `query.log` has 0 pid on 7,788 rows. Read the caller's condition and both schemas before writing the fix. {#imp-precedent-carries-its-branch}
- 2026-11-09 (bug-179 spec r1, c5f91e4): **A PARITY TEST PROVES TWO PARSERS AGREE, NOT THAT THE CORPUS IS CLEAN; AND A CANONICAL-TOOLING GATE HAS CONSUMERS OUTSIDE THE REPO UNDER REVIEW.** Once the fix makes both sides ignore a construct, re-introducing it leaves the parity sets equal (AC-7(d) could not fail); pair a parity test with a zero-occurrence assertion. And census the fleet before tightening upstream lint: viascope calls `~/claude_tools/gmd/lint.py` directly and carries the incident's own 6-id packed line. The report's first draft reproduced the double-backtick bug it described — quote risky syntax in tests, not prose. {#imp-parity-is-not-cleanliness}
- 2026-11-09 (plan-23 23.1+23.2 confirm, 1c0b66a): **A QUEUE ADDED BESIDE A SYNCHRONOUS WRITER OF THE SAME KEY NEEDS A CROSS-PATH ORDER, NOT ONLY AN IN-QUEUE MERGE.** R11's last-wins-by-name coalesced the queue, but the Stop hook's direct dial writes the same digest name every turn; a 30 s tick lets a queued older digest land after a newer direct one. Whenever a fold adds a deferred path, ask which writer wins when both reach the row, and demand a guard (ts vs updated_at) plus an AC that runs both. {#imp-queue-beside-sync-writer}
- 2026-11-09 (plan-23 fold additions, a9147d5): **AN ORDERING KEY HAS TO BE CARRIED THROUGH EVERY STAGE THAT ORDERS.** The fold made `add_memory` compare authoring times, but the in-window merge still keeps the last-APPENDED line, and the facts.log event and both replay paths drop the time and restamp it. The guard is right where it was written and bypassed both before it (merge) and after it (replay). When a fold adds an order key, list every stage that orders or rewrites the row (coalesce, apply, log, compaction, replay, merge_slots) and check each one carries the key. {#imp-order-key-every-stage}
- 2026-11-09 (plan-23 23.3+23.5 freshness, 62a2465): **THE PROCESS THAT REPORTS THE LONG LATENCY IS USUALLY THE WAITER; FIND THE ONE SYNC IN THE WINDOW THAT DID WORK.** 9bcf464 blamed 30-94 s agent `sync --since` runs; sync.log showed them `touched=0`, and the one sync per window with `touched>=1` was a 40 s per-row GMD re-ingest of this ledger's own IMPRESSIONS.md, which 23.3 kept as one step. Before routing a holder to a task, profile the step that holds it on a snapshot clone. {#imp-waiter-is-not-the-holder}
- 2026-11-09 (bug-185 spec r1, da67220): **AN EQUIVALENCE GOLDEN INHERITS ITS BASELINE'S CALL CONTEXT AND ITS LOG DEFECTS; A COMMIT MUTATION IS ONLY A MUTATION WHERE COMMIT IS REAL.** `ingest_gmd_paths` links per-row on the direct path but buffered/first-wins under `_sync_paths`' `deferred_links`, and HEAD's facts.log replay already drops tf weights, so "replay digest equals HEAD's" fails a correct rewrite; `DuckDBConnection.commit()` is `pass`, so a no-early-commit AC on DuckDB passes at HEAD and its mutation cannot fail. Record goldens per caller context, gate replay against the new code's own catalog, and run transaction ACs on SQLite. {#imp-golden-inherits-call-context}
- 2026-11-08 (task-3.7 remedy r1, 2a4096c): **A CACHE THAT FIXES A LEAK MUST ALSO FORGET A DEAD ENTRY.** R-H1 turned "a new worker every call" into "one client forever"; the degrade branch never drops it, so a hub outage pins the MCP process to in-process model loads. When a fix replaces per-call construction with a cache, probe the cached object's death. Credit: all six prior findings closed under runtime probes, and both previously surviving guards now die. {#imp-cache-must-forget-dead}
- 2026-11-08 (task-3.7 remedy r1): run the GENERATED hook string, not the CLI behind it: a bash -c of the rendered segment is cheap and is the only proof the hook itself stopped draining. Templates shipped to agents still describe the old hook — protocol changes keep missing the agent docs. {#imp-run-the-rendered-hook}
- 2026-11-08 (task-3.7 remedy r2, 3281c53): **A FALLBACK THAT NEVER RE-PROBES IS A ONE-WAY DOOR.** R2-S1 rebuilds a dead hub client into a private worker and then never looks back; the daemon solved exactly this (bug-024, `_maybe_adopt_shared`) and the daemonless path re-learned none of it. When a new path gains a cache over a model client, diff it against the daemon's client lifecycle. Also: a test that injects `log=` hides that the production logger drops INFO -- probe with the default. {#imp-fallback-one-way-door}
- 2026-11-09 (task 3.7 remedy r4 re-audit, e4faf32) — TWO GUARDS ON ONE INVARIANT HIDE EACH OTHER FROM SINGLE MUTATION. The stand-in's key check (F7) and its drop-on-swap (F8) each survived alone; only the F7+F8 double mutant died, and F8 alone left the model referenced after re-adoption. When two lines protect one promise, mutate each alone AND the pair, and probe the alone-survivor's side effect (retention, zombie), not just the test count. {#imp-redundant-guard-pair}
- 2026-11-09 (task 3.7 remedy r5 final, e285c1c) — A RETRY COUNT IS NOT A READINESS WAIT, AND "UNDER LOAD" WAS A STORY. bug-184's fix allowed 3 attempts and was recorded fixed from narrower runs; the full suite failed 4 setups, every attempt `skipped_budget`. An idle 8-call probe showed the first call misses on branch AND master: each fresh sandbox daemon spawns private embed (7.4 s) + rerank (5 s) workers. Measure one idle call before blaming load; a setup waits on the signal, never on a count. Same round: a classifier added to stop over-backing-off (cold hub) removed the backoff for a wedged hub, so test the case the new branch also captures. {#imp-retry-count-is-not-readiness}
- 2026-11-09 (task 3.7 remedy r6 re-audit, dae0f9e) — A RUN COUNTER NEEDS A TEST FOR HOW THE RUN ENDS, AND A MODULE-WIDE CLAIM NEEDS A GREP. The mute-hub streak fix is right and pinned at its start (first miss at base) and growth (doubling), but the reset on a refused/absent miss survives mutation; and `daemon.py` now says every numeric knob goes through env_float while eight float reads do not, and the master bug row that inventories leftovers skips daemon.py because it trusted the comment. Credit: bug-184 closed for real -- a readiness signal, a full suite at the gate, zero retries. {#imp-pin-the-run-end}
- 2026-11-09 (task-3.7 remedy r3, b0cc89b): **SHARING A PROBE IS NOT SHARING ITS PLACEMENT.** r3 correctly moved the daemon's re-probe into one function, but the daemon calls it from a background tick and the daemonless path calls it inside the request, under the process lock, with the 45 s cold-worker bound. A mute hub cost 45 s and 89.8 s on two concurrent calls. When one implementation gets a second holder, check WHERE that holder calls it (tick vs request, which lock, what bound) before crediting the convergence. Also: "out of scope" on a gap the task's own earlier test forbids is still an unanchored deferral (bug-173). {#imp-shared-probe-placement}
- 2026-11-09 (bug-178 r1) — A CONVERGENCE FIX TESTS THE SITES AND NOT THE HELPER. Thirteen call sites moved onto one `bulk_write`, each pinned by a HEAD golden, and every mutation of a site died. The helper's own promises survived: `finally: unregister` removed, the executemany fence raised to 10^12, and the dup-key `updated_at` touch disabled all left 31/31 green. When a diff converges N copies into one function, mutate that function's invariants (cleanup, fence, the one column the goldens exclude) before the sites. {#imp-convergence-tests-sites-not-helper}
- 2026-11-09 (bug-178 r2) — A TEST'S OWN CLEANUP CAN ERASE THE INVARIANT IT SHOULD CHECK. `store_scores` gained `rollback(); raise`, and the RED test asserted the raise and then ran `finally: if con.in_transaction: con.rollback()`. The test did the rollback itself, so deleting the production rollback left 64/64 green, even though without it every later write on that SQLite connection fails. When a fix adds cleanup, look for teardown in the test that repeats it, and assert the state BEFORE the teardown runs. {#imp-test-cleanup-masks-the-fix}
- 2026-11-09 (bug-179 post-impl, 9a5cd78): **A NEW "CANNOT START" EXIT IN A GATE TURNS EVERY TEST THAT ONLY GREPS ITS OUTPUT INTO A PASS.** lint-gmd.sh's missing-interpreter exit 2 prints no ": error" line, so bug-155's repo-scope test went green in every clone; check each caller of a gate (tests, CI) for a return-code assertion when the gate gains a precondition. {#imp-gate-precondition-vacuous-pass}
- 2026-11-09 (task 26.1, 8337368) — A CLASSIFIER OF HAND-WRITTEN TEXT MUST BE RUN OVER ITS OWN OUTPUT, ON REAL DATA. `_prose_lines` called anything without `](` prose; `Entry.line` (HEAD) cuts the link off long titles, so every organised render re-carried its own truncated entries: cliquedb +8 lines/render, frozen at 40 KB by render 12. - 2026-11-09 (task 26.1, 8337368) — A COMPARATOR WITH FALLBACK BRANCHES IS NOT A KEY. `_cmp_newer` compares datetimes in one branch and mtimes in another; three same-day save-states form a cycle and `newest` follows scandir order. Two-item spec cases cannot expose intransitivity — probe every permutation of three. {#imp-fallback-comparator-cycles}
- 2026-11-09 (task 26.1 r2, 7b5ea2f) — A PRECEDENCE RULE FOR ONE BAD READ MUST NAME ITS SIBLINGS. The remedy made an EMPTY index hook lose to the curated sidecar hook; a CUT hook (`prefix…`) is the same lossy read and still wins, so a long curated hook survives exactly one render (30 already truncated in live refmatrix). - 2026-11-09 (task 26.1 r2) — COUNT A DEFECT'S SHAPE ON THE REAL FILE, NOT ITS FIRST SYMPTOM. bug-192 was logged as 8 link-less lines; the same cut also left 11 lines whose link points at no file and 1 ending `.md)…` — 19 unreachable, and the fix's first render reports the 11 as 'dropped'. Grep every byte form the defect produces before writing the count. {#imp-count-the-defect-shape}
- 2026-11-10 (task 26.1 follow-up r3, c9a035e) — EACH REWRITE OF A HELPER ORPHANS ITS PREDECESSOR. The precedence fix is real on live data (cliquedb 83/83 cut hooks kept), but rewriting `load_hooks` on `_index_hook_records` left `parse_hooks` with a test as its only caller. - 2026-11-10 (task 26.1 follow-up r3) — A PRECEDENCE RULE IS A MATRIX, NOT A LIST OF CASES. Empty (r1), cut (r2), then a hand-shortened prefix and the derived/no-sidecar case (r3): test the rule as (curated/derived/none) x (room/no room) x (edit/cut). {#imp-precedence-is-a-matrix}

- 2026-11-10 (bug-195 r1, 39777c6) — AN AUDITOR'S RECOUNT IS EVIDENCE TOO, AND IT CAN BE LOOSE. r3's "prefix anywhere in the body" heuristic called 2 short curated cuts derived (37/29 vs the tool's 35/30).
