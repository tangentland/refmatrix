- 2026-11-09 (plan-26/27 spec r1, 96feccd): **A NEW PLAN CAN RE-SPECIFY AN APPROVED ONE WITHOUT A SINGLE EDGE.** 26.6/26.7 rebuilt 19.4 R5 (stale subjects) and 19.3 (subject-grouped index) under new field names; plan-22's audit keys on the old name, so the "removal waits for plan-22" deferral pointed at nothing. Before reviewing any plan, grep the approved plans' task titles for the same nouns.
- 2026-11-09 (plan-26/27 spec r1): **A VERB THAT TAKES A PATH BUT WRITES THROUGH A CWD RESOLVER WRITES TO THE WRONG STORE.** `organise <MEMDIR>` → `_sync_memory_dir` → `_root()`; and a "same code path" claim (26.9 scoped compile) hid a partition-wide prune. Trace the store and the prune scope, not the function name.
- 2026-11-09 (plan-25 spec r1, 2f4a1df): **A SPEC THAT SAYS "THE VERB" MUST BE CHECKED AGAINST THE PATH THE HOOK ACTUALLY TAKES.** 25.1 cited `cli.py:12446` as the dense leg; the per-prompt argv takes the CLI-only hybrid path (replica-first + direct RPC) and never touches `verbs.memory_recall`, so the byte-parity AC holds only in a sandbox that has no shared workers. Read the branch the argv selects (`--stdin-json` + query), not the nearest verb call. {#imp-spec-verb-vs-argv-path}
- 2026-11-09 (plan-25 spec r1): **A GATE THRESHOLD NEEDS ITS FALSE-POSITIVE POPULATION, NOT ONLY ITS TARGETS.** Simulating the thin-prompt rule over real rings found half the gated prompts were single-topic commands (push, deploy, #44) — exactly where guardrail memories fire — and the AC table listed none. Also: telemetry already written by an earlier plan (21.1 payload_bytes) beat the spec's one-shot measurement; check for it first. {#imp-gate-false-positive-population}
- 2026-11-09 (plan-25 spec r1): **A MUTATION LISTED IN A SPEC CAN BE MASKED BY ANOTHER RULE IN THE SAME SPEC.** Every `_PATH_RE` truncation in 25.3's ACs is also dropped by the short-head rule or the -c body rule, so removing the boundary changes no outcome. For each listed mutation, ask which OTHER rule would still produce the asserted result. {#imp-mutation-masked-by-sibling-rule}
- 2026-11-09 (plan-26/27 spec r2, 8af766a): **A FOLD THAT DEFINES "ONE ORDERING" MUST BE CHECKED AT THE FIELD'S GRANULARITY.** S2's fix made `updated → created → mtime` the one "newest" key; both fields are date-only (`handoff.py:153`), so same-day re-saves tie and `created` picks the session STARTED last. When a fix promotes a field to a sort key, read how the writer formats it. Also: a rollback that "asides every differing file" and then "keeps the current file" cannot do both — run the spec's own test through each step. {#imp-sort-key-granularity}
- 2026-11-09 (plan-26/27 spec r2): **A PLAN THAT SHIPS RENDERER CHANGES TO THE DEPLOYED BINARY EDITS EVERY PROJECT THAT RUNS IT.** plan-26 said "no edits to other projects' memory dirs" while its save-state writer, index renderer and sidecar writer run in every project at the first post-deploy save-state, before plan-27's backups. And an AC that "measures before deploy" with a field of the deployed command cannot. Ask "which processes run this code the moment it deploys?" for every fleet-scoped non-goal. {#imp-deploy-reaches-fleet}
- 2026-11-09 (plan-26/27 spec r2): **MEASURE THE CONDITION BEFORE ACCEPTING "IF".** 27.2 said "if the carried prose would exceed the budget, refuse"; viascope's prose is 22,643/24,000 chars, so the refusal is certain and the next step (prose into memories) had no task. Same with 26.9's window: 45 pointer bullets + 14,450 chars broke both caps on the very ledger the AC names. {#imp-measure-the-if}
- 2026-11-09 (plan-26/27 spec r3, 696c3cb): **A GATE THAT PROMISES "EXACTLY HEAD" MUST BE RUN AGAINST HEAD BEFORE ITS TEST IS WRITTEN.** The marker fold said un-organised dirs render "exactly as at HEAD" and its test asserted "no sidecar created"; one probe showed HEAD's `write` always creates `.memory_hooks.json`. For every "keeps HEAD behaviour" clause, list HEAD's side effects (files created, lines appended) first, and enumerate EVERY writer the gate must cover — the walk found 13, one (compile R3) ungated. {#imp-exactly-head-run-head}
- 2026-11-09 (plan-26/27 spec r3): **A MEASUREMENT ON A COPY MEASURES THE COPY WHEN THE METRIC IS PATH-KEYED.** `refresh_pending` counts rows whose stored path disagrees with the file's path; a memdir copied under mkdtemp disagrees on every row. When a "safe" sandbox measurement is prescribed, ask which input the metric keys on and keep THAT input live (read-only) while the written side is copied. Also: a "lossless checker" with no file path and no planted-loss case is a promise, not a checker. {#imp-copy-measures-the-copy}
- 2026-11-09 (plan-25 spec r2, 5b8ed15): **MOVING A LEG INTO A SHARED VERB CHANGES EVERY OTHER CALLER OF THAT VERB.** S1's fix put the hook's replica-first leg into `verbs.memory_recall`, which MCP also runs; the fold named the hook and not MCP, and the leg moved carries CWD globals (`_reader_store`, `_resolve_partition`) into a root-taking verb. When a fold says "move X into the verb", list the verb's callers and check X's free variables.
- 2026-11-09 (plan-25 spec r2): **A BUDGET SPLIT MUST BE KEYED BY THE UNIT THE CAP APPLIES TO.** EVENT_SPLIT was per producer, but two producers share one hook command, so "each producer 0.9 x cap" doubles a single hook. Check the generated hook strings, not the producer list.
- 2026-11-09 (plan-25 spec r2): **A TRANSLATION RULE NEEDS A DEFINED OUTCOME FOR ITS OWN COMPILE FAILURE.** Second round on 25.4: the fixed rows were right, and the new ones (`-w` edges, stacked quantifiers, `^*`, locale classes) all came from running the oracles on inputs the spec did not list.
- 2026-11-09 (plan-26/27 spec r4, f89e640): **PROBE THE REAL DIRS, NOT ONLY THE FIXTURE, BEFORE ACCEPTING "UN-ORGANISED = HEAD".** viascope has no marker but is already in type folders (142 nested files), so an ungated `collect` change and an "exactly HEAD" clause build different indexes there and the flat fixture cannot tell. Also: my own `find` probe returned 0 twice because `~/.claude` is a dot-dir (`-path '*/.*'` matched everything) and a `-Users-…` slug parsed as a `cd` option — a probe that finds nothing must be shown to find something. {#imp-probe-real-dirs-not-fixture}
- 2026-11-09 (plan-26/27 spec r4): **A BEFORE/AFTER COUNT MUST HAVE THE SAME TERMS ON BOTH SIDES.** 26.8 AC-2 compared a pre-move dry-run count with the post-move apply bridge (+290 moves); missed for two rounds because each round checked the measurement, not the comparison. {#imp-before-after-same-terms}
- 2026-11-09 (plan-26/27 spec r5, 3ded49e): **A PER-FILE REFRESH COUNT CANNOT SEE ROWS THAT NO FILE MAPS TO.** refmatrix's store holds 19 legacy `memory_sync_disk` rows (keyed by `name:`) beside the id rows for the same files; the id-keyed bridge never touches them, so a move leaves them dead-path while every per-file term reads 0. Query the store by path prefix, not only the files by id. {#imp-per-file-count-misses-orphan-rows}
- 2026-11-09 (plan-26/27 spec r5): **A FOLD THAT WIDENS ONE BEHAVIOUR BREAKS OLDER "BYTE-IDENTICAL" CLAUSES ELSEWHERE.** r4 s1's ungated collect was right, but it falsified 26.8 AC-0 spot-check (b) and re-broke r1 m1's impressions-pointer wording. After a scope change, grep every "byte-identical"/"exactly HEAD" clause. {#imp-widening-fold-breaks-identity-clauses}
