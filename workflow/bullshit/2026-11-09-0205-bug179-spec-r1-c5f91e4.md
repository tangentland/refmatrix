**What:** d1 justifies the error with "zero legitimate multi-anchor lines anywhere in the corpus

dead in rmx). Both vendor lint and break on their next re-vendor. The spec has no requirement
that names these consumers, and no migration step for them.

`§{#x}` citations. **Memory dirs need nothing:** all 981 files across the 19 non-empty dirs are
clean, so plan-27 needs no migration note.
**Pattern match:** YES. See IMPRESSIONS r2 "a plan that ships renderer changes to the deployed
binary edits every project that runs it". Canonical tooling has the same blast radius.

### MEH m3: R2's trigger must match the ingester's {#m3}

Lint keys `rel:` on `line.startswith("rel:")`. The ingester skips the anchor scan only when
`_REL_RE` matches, so a malformed `rel:` line carrying `{#id}` falls into the body branch and
registers the id. Fix: R2 applies to any `rel:`-prefixed line, and the ingester skips anchors on
`line.startswith("rel:")`. The alternative is to state that malformed-rel is already a lint error
and so never reaches parity.

### MEH m7: the double-backtick inline-code bug is unrecorded; decision is to fold it in {#m7}

Both tools strip inline code with the single-run regex `` `[^`\n]*` ``. A span opened by TWO
backticks is read as two empty spans, so an anchor-shaped token quoted inside a double-backtick
span is exposed as a real anchor, and a quoted wikilink as a link. This report proved it on
itself: its first draft quoted such an example here, and lint registered a bogus `x` anchor and
then reported an unclosed fence. They agree, so parity holds, but both are wrong.

**Decision (as the user would): fold it in as R3b.** It is the same regex in the same three files
R1-R3 already edit (`lint.py:84`, `ingest_gmd.py:156`, `slice.py:35`). R3 makes inline-code
stripping load-bearing for heading parity. A separate row would mean a second upstream commit and
a second re-vendor. The measured blast radius is 0 GMD lines fleet-wide [[#p-dbl]]. Replace all
three with one CommonMark backtick-run matcher. Add an AC: a list item holding a double-backtick
span that quotes anchor `x`, followed by the real anchor `y`, registers only `y` in both tools.
Put the fixture in the test file, not in prose. A mutation that reverts one side must fail
AC-5's synthetic fixture.
