## Findings {#findings}

### SKETCHY: 19 legacy `memory_sync_disk` rows in refmatrix's store keep the pre-move `source_path` after apply, and nothing counts them {#s1}

**File:** `task-26.2` AC-1/AC-3; `task-26.5` AC-8 (`--check`); `task-26.8` AC-2/AC-5;
`task-27.1` AC-6.

**What:** The bridge refreshes "the row", keyed by id. `refresh_pending` is computed per FILE.
`organise --check` is clean when `refresh_pending` is 0.

**Why:**
- Probe of a copy of refmatrix's read snapshot: there are 376 memory rows whose
  `source_path` is under the memdir, for 357 files. **19 files have two rows each.** One row
  is `source: ingest_gmd_as_memory`, named by `id` (`project_daemon_arch`). The other is a
  legacy `source: memory_sync_disk` row, named by the frontmatter `name:`
  (`refmatrix-daemon-architecture`). It has older content, and its `noise` and `protected`
  flags are both 0, so recall still serves it.
- HEAD's bridge only WRITES `source_path` (`ingest_gmd.py:948`). It never looks a row up by
  path. `sync-disk` is now an alias of `ingest-gmd --as-memory` (`cli.py:13141`), so nothing
  writes or refreshes the legacy rows any more.
- After 26.8's apply moves ~290 files, those 19 rows point at top-level paths that no longer
  exist. The per-file dry-run cannot see them because no file maps to them. So `--check`
  reports clean, and 26.8 AC-2's terms balance, with 19 dead-provenance rows in the store.
  The same happens in every plan-27 store that predates the alias, and 27.1 does not count
  them.
- This is created by the plan's own moves, on a memory path, and it goes uncounted (CLAUDE.md
  `#no-silent-failures`). It predates the r4 fold; I missed it in r1-r4.

**Fix (AC text only, no user decision):**
- 26.2: on a move, refresh `source_path` on EVERY row in the partition whose stored
  `source_path` equals the moved file's old path, not just the id row. Report the extra rows
  as a fourth term, `moved_legacy`. Add a RED fixture: a second row with a different name and
  the same `source_path`. At HEAD it keeps the old path.
- Alternatively: count rows under the memdir prefix whose `source_path` has no file
  (`orphaned_rows`) in the dry-run and in `--check`, and make `--check` non-zero when that
  count is above 0.
- Either way, 27.1 records the count per store, and 26.8 AC-2 expects `moved_legacy` = 19
  for refmatrix, exact. Merging or forgetting the legacy duplicates is a separate question
  (`feedback_decay_never_loses_knowledge`). It is not needed here.

**Pattern match:** YES, `imp-exactly-head-run-head`: run the claim on the real store, not
only a fixture.

### MEH: the refresh terms are defined two ways, and an overlapping row has no precedence {#m3}

- 26.2 AC-3's pre-registered `refresh_pending` = missing + symlink-form + "moved since last
  ingest".
- `stale_before` = missing + symlink-form only. Yet 26.8 AC-2 compares `stale_before` with
  the whole of AC-0's `refresh_pending`.
- A row that is both stale-before and moved by apply has no stated term. With `moved` set to
  "exact", that matters.
- Probe on refmatrix's snapshot copy: every one of the 357 files has a matching
  `source_path` row. Missing, symlink-form and stale are all 0, so 26.8 passes either way.
- State the precedence (by the stored path's shape: missing or symlink-form → `stale_before`,
  else `moved`). Compare `stale_before` with AC-0's first two terms. This may ride as an
  implementation note.

### MEH: "23.0's sandbox connect recorder" does not record sandbox sockets {#m4}

23.0 replaced the 2026-10-07 record-only recorder with a refusal of LIVE sockets
(`rmx_sandbox.violation`, `socket.connect` against the deny set; `tests/conftest.py:176`). A
connect to a sandbox daemon socket is neither refused nor recorded. The "ZERO connects to any
daemon or hub socket" assertion therefore needs a test-local `sys.addaudithook` on
`socket.connect`, which is trivial. Name it in the test. This may ride as an implementation
note.

### MEH: rollback's restore branch can restore an index with a dead link {#m5}

`task-26.5` AC-7 says that when `MEMORY.md` is unchanged since apply, the archive copy is
restored. Editing a feedback memory does not touch `MEMORY.md`, but it keeps that file at
`feedback/x.md`, while the restored pre-apply index links `x.md`. Take the restore branch only
when no file was kept at a moved path; otherwise regenerate. This may ride as an
implementation note.
