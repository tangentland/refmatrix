## Findings {#findings}

### MEH: the migrate check matches by catalog name, not by the file it replaces {#m-1}

**File:** src/refmatrix/cli.py:4097. The call is `_refuse_tracked_catalog_open(dst.parent.resolve(), dst.resolve())`, which asks git about `WRITER_CATALOG_FILES` names in dst's folder.

**Evidence (bsd-r6-probe-names.log):**
- `--out <repoB>/x.duckdb`, where x.duckdb is committed: exit 0, and repo B shows ` M x.duckdb`.
- `--out <repoB>/.refmatrix/foo.duckdb`, next to a tracked catalog.duckdb: refused, although foo.duckdb is untracked and nothing committed changes.

**Rating:** MEH. It is a legacy one-shot command, and both edges need an unusual `--out`.

**Fix:** the right question is "does git track dst itself". Writing next to a tracked catalog changes no committed file, so asking about every writer-catalog name in dst.parent is the wrong question.
- Give `git_tracked_catalogs` / `refuse_tracked_catalog_open` a `names=WRITER_CATALOG_FILES` parameter.
- Call `_refuse_tracked_catalog_open(dst.parent.resolve(), dst.resolve(), names=(dst.name,))`.
- The default dst (`<root>/catalog.duckdb`) keeps today's refusal.
- Pin both probes.

### MEH: the sync-disk deferral warning has no test (M3 survives) {#m-2}

**File:** src/refmatrix/cli.py:13530-13534 (`memory_sync_disk`, the `elif out.get("deferred")` branch).

**What:** L98 requires both save-state and `rmx memory sync-disk` to warn on stderr when the bridge is deferred. M3 replaces the sync-disk warning with `pass`, and all 30 tests in r6_red + test_memory_bridge still pass. A deferred sync-disk would then print nothing at all (no report, no warning) and exit 0.

**Fix:** one test that runs `rmx memory sync-disk` behind a running ingest job with RMX_BRIDGE_WAIT_S=0.2, and asserts one stderr `warning: memory bridge deferred:` line naming the job, and exit 0.
