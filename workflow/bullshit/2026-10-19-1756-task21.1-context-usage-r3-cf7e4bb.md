  uses `render_*_spans` + `click.echo(_out)` and spans `_out + "\n"`. The daemon op uses the same
  renderer. scan-prompt text uses `render_text_spans` per section, and `_compose` only APPENDS the
  composite, so offsets hold. MCP/verbs use JSON `name_spans`. Inside `_memory_recall_impl`, the
  only other prints are the empty `[]`, the empty-rows GMD and the yellow "no hits" / "skipped"
  lines, which print no items. Nothing prints delivered items around the capture.
- **One-line cells.** `_one_line` only touches the TEXT table's cells. The JSON (`rec.echo(json,
  json_mode=True)`) and GMD (a blockquote keeps the newlines) paths are untouched, and no hook
  consumes the table (the generated recall hooks use `--json`). Nothing downstream needs the
  newline. The rule is load-bearing, though. With it removed, a multi-line content cell shifts
  every later row, so every later row goes unspanned: probe `p1-no_one_line.log`, 1 of 6 rows
  spanned. No test holds it, see [[#s1-r3]].
- **GMD heading spans.** Probed with multibyte, `[`-bearing, `│`-bearing and trailing-backslash
  names and multi-line content. Every span is exact (`b[off:off+n] == name`), and a nameless row
  gets None. The behaviour is correct but unguarded, see [[#s1-r3]].
- **`norm_path` cache.** Only `realpath` of an already-absolute string is cached

  risk is a symlink changed during a long daemon life, which is negligible. Accepted.

### MEH m1-r3: the table renderer still rewrites some names, and the layout check accepts a prefix {#m1-r3}

**File:** `src/refmatrix/cli.py:12679` (cells as rich markup through `rich_escape`),
`:12701` (`line[len(prefix):].startswith(name)`), `:12719` (`Console(...)`, emoji on)
**Evidence (probe `p1.log`, the production `_echo_recall_table`):** a name `fix:smile:now`
prints as `fix😄now`, so the agent sees a name that does not exist, and the row is unspanned.
A name `trail\` prints as `trail\\` (`rich_escape` appends a backslash and the cell renders it),
yet it is spanned as delivering `trail\` because the check is `startswith`, not "name then
padding". Both cases already existed on the query route (`rich_escape` + emoji). Reach is low,
since memory names are slugs.
**Fix:** add cells as `rich.text.Text(c)` (no markup parse, no escape, no emoji) or render with
`Console(emoji=False, markup=False)`. Then require the byte after the name to be `" "` (padding)
or `" [global]"`. 3-4 lines.

### MEH m2-r3: "one table path", but the `[global]` label is still the query caller's job {#m2-r3}

**File:** `src/refmatrix/cli.py:12422-12425` (recent/subject cells use `m["name"]`) vs `:12646`
