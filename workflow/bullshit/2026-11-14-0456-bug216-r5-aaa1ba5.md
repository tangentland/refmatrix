## Findings {#findings}

### SKETCHY S1: an id vacated by a B name-loser keeps a possibly stale vector, silently, with its new holder never re-queued {#s1}

**File:** `src/refmatrix/replica_merge.py` `_merge_into`: the `vector_rows` query and the
`vectors_updated_at = NULL` update. Both cover fresh moves and `remap_a` losers, but not `remap_b`
name-losers.

**What:** this is r2's B2e shape. B's `shared` (id Y) loses to A's newer `shared` (id C), and A holds
a DIFFERENT memory, `x-only-a`, at Y. Both slots write one `vectors/` dir, so the Lance row at Y is
whichever slot embedded last. If that was B, it is B-`shared`'s vector, now filed under `x-only-a`.

Probe `probe_b_loser_vector.py`, through the real `_op_replica_merge`, with every entity marked
embedded first:

```
remap {'a_loser_count': 0, 'b_loser_count': 1, ...}  fresh_moved []  vector_rows []
id 2 now held by: x-only-a
Lance row at 2 (written by B's `shared`, last embedder) survives: True
x-only-a re-queued: False | pending: []
```

**Why sketchy:** unlike the fresh-move window, nothing names these ids. `x-only-a`'s
`vectors_updated_at` still looks current, so `rmx embed` never rewrites the row. A dense recall on
B-`shared`'s text returns `x-only-a` until `x-only-a`'s own content changes. It is the same class as
the lead's A-loser extension, mirrored to B. It stays below BULLSHIT only because replica merge is a
rare operator recovery op.

**Fix: the one-line extension, tried and verified** (`tip/.../bsd216r5/extension.diff`):
- Add `OR id IN (SELECT loser_id FROM remap_b)` to the `vectors_updated_at = NULL` update.
- Add two UNION branches to `vector_rows`:

  ```
  UNION SELECT be.partition_id, be.kind, r.loser_id FROM remap_b r JOIN b.entities be ON be.id = r.loser_id
  UNION SELECT te.partition_id, te.kind, r.loser_id FROM remap_b r JOIN entities te ON te.id = r.loser_id
  ```

  `remap_b` already contains the fresh moves; UNION dedupes them.

With it, the probe gives `vector_rows [['proj','memory',2]]`, the row is deleted and `x-only-a` is
re-queued. The r2–r4 remedy, bug-113 and bug-178 files pass (83).

Two more parts belong with it:
- The daemon's `re_embed` text names `_vacated` only from `a_losers`. Name the B name-losers'
  vacated ids too.
- Pin it: the probe as a test (fails at `aaa1ba5`), plus the mutation "drop the two `remap_b`
  branches".

**Pattern match:** YES — `imp-remap-composition`: each round fixes the side of the map its RED
names; the mirrored side is next.
