## Findings {#findings}

### SKETCHY: migrate-to-duckdb checks the source store, not the file it replaces {#s-1}

**File:** src/refmatrix/cli.py:4092-4094.

**What:** `_refuse_tracked_catalog_open(root.resolve(), dst.resolve())` asks git about the store root, but the file `migrate_catalog` unlinks and rebuilds is `dst`.

**Evidence (bsd-r5-probe.log):**
- From an ignored store, `--out <repoB>/.refmatrix/catalog.duckdb --overwrite` exits 0 and repo B shows ` M .refmatrix/catalog.duckdb`.
- From a tracked store, `--out /tmp/.../elsewhere/x.duckdb` is refused although nothing committed would be touched. This is green's flag 4.

**Rating:** the over-strictness alone would be MEH. The same mis-aim also lets through the one write the check exists to stop, so SKETCHY. Realism is low (a legacy one-shot pointed at another repo), so it does not block the merge.

**Fix:** `_refuse_tracked_catalog_open(dst.parent.resolve(), dst.resolve())`, plus a RED test. The default dst is `<root>/catalog.duckdb`, so default runs keep today's refusal.

### MEH: MCP rmx_save_state's isError reply drops e.result {#m-1}

**File:** mcp.py:87-97 (`_verb_tool`: `except VerbError: return {"error": str(e)}`).

**Evidence (probe, both layouts):** the reply is isError with a body that is only the message. remove_failed, lint, filed_subject_error, embed, bridge counts and events are gone. The /save-state template tells agents to act on remove_failed "in the MCP result". With bug-225 merged, trunk_error is lost on this path too.

**Fix:** catch SaveStateIncompleteError and return `{**e.result, "error": str(e)}`. That is still isError. Add a test assertion that the reply carries target.

### MEH: a bridge that is only deferred now fails save-state {#m-2}

**No production caller breaks:**

- The PreCompact hook runs `rmx save-state --no-promote --no-sync`. compose_save_state sets promoted only when promote is on, and finalize_save_state sets sync only when sync is on, so that hook cannot raise. A busy daemon at PreCompact still exits 0.

**Needs a ruling:** `_bridge_wait_for_active_job`'s message "ingest job <jid> still running after 120s … will be bridged by the next save-state / SessionStart" describes a self-healing deferral, but it now exits 1 / isError. Either keep it, or make it a stderr warning with exit 0 and a `sync.deferred` field. Pin whichever you choose.
