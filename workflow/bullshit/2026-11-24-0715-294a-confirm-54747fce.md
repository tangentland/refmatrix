### Note for the lead: under L207 a carried failure can only come from a seed {#n-1}

This is not a finding. A gate passes only when it has no NEW failure. So a passed gate's
`failures.jsonl` holds only failures it carried, and the first passed gate holds none. By
induction, `seen` is always empty in production unless someone seeds a passed gate by hand.
P6 and RED's carry-over test both seed one; RED's docstring says "a fresh tree has no such gate".

The gate therefore already behaves as #r7 describes for after stage 5: any failure fails it.
Before stage 5, an already-open failure in the gate's set (devtree, `ALWAYS_FILES`, touched
files) on the dev tree blocks every merge, and nothing seeds it from an open registry row. If
that is the intent of L207, nothing is needed beyond a sentence in #r7. If not, the seed source
is the open rows in `workflow/bug_registry.md`.
