### SKETCHY: the outcomes keep session-leg units that degenerate in a one-prompt run {#s2}

**Files:** plan-28 #outcomes (2)-(7); 28.3 R3, R8, AC-2; 28.4 R2 (P-4's W).

A paired run gets ONE user prompt after its trigger, the resume prompt (28.2 R2), and it stops
at the orientation endpoint. Yet:
- outcomes (2)-(4) and (6) are "per 100 prompts";
- churn's window is "W = 3 prompts" (P-4);
- 10.2's nested outcome is "bytes per prompt" and "used per 100 prompts".

That has these consequences:
- "per 100 prompts" is the run's count × 100;
- W never binds, so churn becomes "never edited or cited by run end", yet 28.4 still freezes a
  vacuous W;
- each run feeds exactly one per-prompt push;
- 28.3 AC-2 tests W on multi-prompt synthetic transcripts that a real run cannot produce.

**Fix:**
- Measure (2)-(4) and (6) per run (the orientation window) or per 100 main-loop tool calls.
- Express W in tool calls or assistant turns.
- Measure (7) per run.
- Re-cut AC-2 and P-4 to match.
- Record in 28.4 that push acts once per run, at re-entry.

**Pattern match:** NO.

### SKETCHY: the push reading's minimum n has no rule, and an underpowered test reads `shrink` {#s3}

**Files:** 28.4 R2 (the push reading's minimum has no value and no rule; R1 only "reports" its
n); plan-28 #bands; 28.3 R9.

**What:**
- The push reading is `shrink` "when A is better on none of (2)-(4)". "Better" is Holm at
  family-wise α 0.05 over a paired bootstrap of perhaps 10-20 tasks, and the labelled
  outcomes (3) and (4) will be sparse.
- So a test with no power reads `shrink`: absence of evidence is read as evidence of absence.
- The push minimum has no rule, so an unattended 28.4 picks one, and that pick decides whether
  `shrink` fires on noise.

**Related:** `15bc71a` says 10.2's nested minimum is "computed like the others, from R1's
`A+dedupe` vs `A+full` calibration". But R1's computation is for outcome (1), the 30% vs 10%
cut in orientation cost. The nested bands read outcome (7), bytes and used, so that minimum
powers the wrong outcome.

**Fix:**
- Derive each secondary minimum from the calibration variance of the outcomes that reading
  actually uses, at a stated effect and power: (2)-(4) for push, (7) for nested. Below it, the
  reading is `underpowered`.
- Or make `shrink` require a pre-registered non-inferiority result (each of (2)-(4) within δ of
  B, CI excluding worse than δ), not merely a failure to reject.

**Pattern match:** NO. This was latent in r1-r3, when the session leg's n was large. L83's
small paired n makes it bind.
