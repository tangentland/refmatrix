## Findings {#findings}

### MEH: `_ss_origin_head`'s new "exit 1 with stderr is a failure" rule is unpinned; the mutation survives 37/37 {#m-1}

**File:** `src/refmatrix/handoff.py:124` (`if rc == 1 and not err: return "", ""`)
**What:** green extended L100's rule to the `symbolic-ref` read. The extension is right. Under
`--quiet`, unset origin/HEAD exits 1 with an empty stderr (probed in a clean repo and in one with
unrelated broken refs), so exit 1 with stderr can only be a failure. It is the same rule as the
candidate verify, and without it a failure there would silently read as "unset", which is the
r2 S1 shape at the first step of the walk. But nothing pins it. The mutation
`if rc == 1 and not err:` → `if rc == 1:` at line 124 leaves `test_bug225_handoff_trunk.py` at
**37 passed** (`workflow/review-output/bsd225-r3-mutOH.log`). The `git_shim` modes fail only
`rev-parse`/`cat-file` (verify) and `log`/`rev-list` ranges (ahead), never `symbolic-ref`.
**Fix:** a shim mode (say `"origin-head"`) that fails `symbolic-ref` with `rc=1, stderr=True`.
One test then asserts that `trunk_error` names `` `git symbolic-ref --quiet --short
refs/remotes/origin/HEAD` exited 1: b225-shim … `` and that the list still decides. One mode
and one test.
**Pattern match:** YES: [[bsd-impressions#imp-exit-allowlist-needs-a-probe]] (an exit-code rule
that no mutation could break). It stays MEH: the loud side is coded correctly, and only the pin
is missing.
