## Findings {#findings}

### SKETCHY S1: `context._is_session_card` is a FILTER at three sites, not just a sort key; G22 does not say what replaces it {#s1}

**File:** G22 `#facts-gates` (`:64-65`, "sorts session cards after docs in `_rank_entries`"),
R1 convergence (`:92-96`), R3 (`:113-119`, "Nothing is removed"). Code: `context.py:360`,
`:671`, `:834` (`if not include_sessions and _is_session_card(...): continue`), `:1265` (the
sort).

**What:** today the predicate HIDES `session-` cards from `rmx context` unless
`--include-sessions` is passed. The sort at `:1265` only orders the cards that were opted back in.
G22 removes the function, and "`context` calls the predicate". Either literal reading regresses:
- **The filters call `is_operational`.** `workflow/` docs, save-states and digests are hidden from
  default `rmx context`. USEFUL by name, anchor and BM25 fails, and R3's "Nothing is removed" is
  broken.
- **The filters become R3's last-place partition.** Session cards, hidden today, reappear in
  default output. No AC checks session cards.

**Fix:** keep the `include_sessions` filter scoped exactly to session cards. Add a named facet in
`memory_layout`, for example `is_session_card(name)` or `is_operational(..., facet="session-card")`,
so that it still lives in the one module. Correct `#facts-gates`. Add an AC-5 row: a `session-`
card is absent by default and present with `--include-sessions`, while a `workflow/` doc is present
and ranked last. Mutation: "the filter uses full `is_operational`" (the `workflow/` doc
disappears).

**Pattern match:** YES (`feedback_check_the_sibling_condition`: one function, two roles).

### SKETCHY S2: the `denotes` clause makes ordinary term concepts operational {#s2}

**File:** G22 R1 (`:87-88`, "or the entity is a concept that `denotes` one (bug-216 R7)"), R2
`build_adjacency` (`:98-100`, "drops every `operational_ids` member, its nodes and its edges").

**What:** bug-216 R7 links every path-less concept named after an ingested doc id (and its
spelling variants) to that doc with `denotes` (`link_denotes`, bug-216 branch `store.py:5998-6020`).
Several `workflow/` docs have common-word ids:
- `workflow/templates/exploration.md` is `id: exploration`;
- `workflow/CONSTITUTION.md` is `id: constitution`;
- `workflow/PATTERNS.md` is `id: PATTERNS`.

The concept `exploration` is also the term concept every `docs/` and `src/` file that says
"exploration" mentions. Under R1 it becomes operational. `build_adjacency` then drops that node and
every `mentions` edge into it, and the `ppr`/`net`/`enrich` filters drop it from their output. That
is a skew on code/doc terms, which is exactly the user's condition. An 80-query random draw is
unlikely to contain one of these terms, so DOESN'T SKEW would probably not see it.

**Fix (recommended):** drop the `denotes` clause. The doc and its anchors are operational; a
same-named term concept is not. If the clause has to stay, restrict it to concepts that no
non-operational entity `mentions`.

AC-1 adds a concept `exploration`, mentioned by `d.md` and `denotes`-linked to a
`workflow/templates/exploration.md`, which stays out of `operational_ids`. Mutation: "every
`denotes` concept joins" (`exploration` joins, and `build_adjacency` loses `d.md`'s edge).

**Pattern match:** NO.

### SKETCHY S3: the spec does not say which form of the predicate each call site uses, or whether its output filter widens {#s3}

**File:** G22 R1 (`:79-96`), R2 (`:97-112`), AC-3 (`:232-236`). Code sites:
- `ppr.py:111-112, :229, :301`
- `net.py:195`
- `enrich.py:163`
- `scan.py:825`
- `brief.py:323, :406`
- `consolidate.py:130, :210`

**What:** `is_operational(*, name, mtype=None, path=None, project_root=None,
workflow_docs=frozenset())` catches `workflow/` content only when the caller passes `path` +
`project_root` or the `workflow_docs` set. Every site listed above holds only a `name` (and a
`kind`). Called by name, the predicate covers only the name and mtype rules, so `workflow/` anchors
(large co-mention hubs) still pass scan-prompt's PPR filter, which R3 says "keeps dropping
operational members". If instead those sites switch to `operational_ids`, the `ppr`/`net`/`enrich`
OUTPUT filters newly remove `workflow/` entities from `rmx net`, enrich and PPR results. R2 does not
name that removal, and R3 says "Nothing is removed". AC-3 accepts either form.

**Fix:** a per-site table that says which form each site uses (`operational_ids` membership vs a
name-only call) and what each site does with a member (drop, rank last, or exclude from a weight).
Add one AC row per behaviour class. Example mutation: "scan's PPR filter called by name only" lets a
`workflow/` anchor into the expansion.

### SKETCHY S5: the gate's measuring code is never shown to fail, and its Jaccard is not defined {#s5}

**File:** G22 R4 DOESN'T SKEW (`:153-157`); AC-6 (`:253-259`); Files `eval/dq1/measure.py`.

**What:**
- "A `workflow/` or other operational entity in `W`'s top-k counts as a mismatch" does not say
  what that does to the Jaccard: drop it from the intersection only, or also count it in the union.
  Save-states exist in both W and N (both bridge the memdir), so the rule also decides whether a
  shared save-state counts against W.
- AC-6 checks only that the report exists and that bands are not edited. Nothing proves
  `measure.py` FAILS on must-fail input. An off-by-one in `k`, a top-k taken from N's list twice,
  or a skipped mismatch rule would report a pass. This is `feedback_clean_corpus_hides_a_dead_gate`.

**Can SKEW fail?** Yes, in principle. R3 orders operational hits last, so W's top-k differs from
N's mainly through BM25 corpus statistics (N, avgdl and df include `workflow/` in W), which is
what the pre-registered re-tune targets. The mismatch rule rarely fires, because R3 already places
operational hits last. The gate is meaningful only if the code that computes it is proven.

**Fix:**
- Write the formula: `J = |top_k(W) ∩ top_k(N) − OP| / |top_k(W) ∪ top_k(N)|`, with `OP` the
  operational names.
- Add an AC with a fixture pair whose W list carries an operational entry and a reordered tail; it
  must read below 0.60 on that query.
- Mutations: "mismatch rule off", "`k` from W's list", "Jaccard against BEFORE".

### SKETCHY S6: the USEFUL re-tune cannot change the result it targets {#s6}

**File:** G22 R4 sets (`:147-150`, "10 three-word phrases from plan titles") and the USEFUL re-tune
row (`:173`, "the exemption also matches a query equal (case-folded) to a workflow doc's title").

**What:** the BM25 queries are three-word phrases. Plan titles are much longer. For example,
plan-16's is "Invisible grep shim: the real tool always answers, the graph learns in the
background" and plan-22's is "Plan 22: one audited path for every repair and removal — …". A
three-word phrase never equals such a title, so the re-tune exempts no query, and a 6/10 or 7/10
result goes to report unchanged. The pre-registered remedy is a dead branch for the set it serves.

**Fix:**
- Change the re-tune so it matches a query whose terms all occur in one `workflow/` doc's title
  (still names-only, still the named doc only).
- Alternatively, draw the phrase set as full titles of at most N words.

Freeze whichever is chosen with the rest.

**What `e4dc31b` changes, and how it reads:**
- **DOESN'T SKEW bands: sound.** The three rows now partition the outcomes cleanly:
  - pass: every mean ≥ 0.90 and every query ≥ 0.60;
  - re-tune: every mean ≥ 0.80 and every query ≥ 0.45, but not a pass;
  - report: anything lower, or still failing after the re-tune.

  corpus document frequencies, which are statistics, not a ranking. One side effect: a rare-term
  phrase scores high under BM25 and has few non-operational hits to compete with, so the BM25
  channel became easier to pass. L60 chose this, and it does not make the draw dishonest.

  - anchor queries are `<id>#<anchor>` refs;
  - `rel:` queries are `rmx neighbors <id>` calls;
  - BM25 queries are now three-word rare-term phrases from section bodies, not even from titles.

  The re-tune therefore cannot change any USEFUL outcome. Every miss ends in report. On the way it
  ships an R3 code change (title-equal exemption) that no query exercises. Revision 3's line "a
  name, anchor or `rel:` miss is a defect, not a band" is also gone, so a resolution defect now
  waits behind a re-tune that cannot touch it.

  **Fix (S6, restated):** pick a re-tune that can reach the channel it is attached to. Either:
  - restrict the re-tune to the BM25 channel and define it over phrases, for example "the exemption
    matches a query whose terms all occur in one `workflow/` doc's title or one of its section
    headings", while name/anchor/`rel:` misses go straight to report as defects (revision 3's
    rule); or
  - drop the USEFUL re-tune.

  Add an AC on `measure.py` showing that the re-tune changes at least one fixture query's outcome,
  so it is not a no-op.
