## Findings {#findings}

### BULLSHIT: the in-place truncate defeats the dev/ino token; the r1 B3 data loss comes back {#b-1}

**File:** spec #fam-refine-drain; hooks.py:181/241
**What:** Drain rewrites the remainder in place.
**Why:** An in-place rewrite keeps the inode. So:
- the agent runs `status` and gets token (dev, ino, N);
- a hook's `status --drain` empties the same inode;
- the watcher appends at least N new bytes;
- the agent's `drain(token)` passes the dev/ino and size check and deletes the new, unprocessed
  entries.
**Fix:** The token must identify the CONTENT, not the file. Use `sha256` of the first `size`
bytes (checked under the lock), or a generation counter that every drain bumps (kept in
`curator.queue.lock`). Test: status → hook drain → append → drain(token) must raise
"queue changed".

### SKETCHY: `stats` with `stale=True` is routed to the snapshot {#s-1}

**File:** cli.py:7681-7720
**What:** The spec routes `rmx_graph.stats` through `snapshot_read`, `stale` included.
**Why:** The CLI says `--stale` needs the live writer's `tracked_files`, because the replica's
copy "isn't refreshed". It forbids `--via-replica --stale`, and with a daemon up it uses the
`stats` op with `include_stale`. A snapshot read would report a wrong stale list as current.
**Fix:** `stale=False` → `snapshot_read`. `stale=True` → the daemon `stats` op (10 s); with no
daemon, in-process (C4a).

### MEH: an MCP-reachable file write via `focus export --out` {#m-1}

**File:** cli.py:1225-1248
**What:** C9 ("params mirror the CLI 1:1") would make `-o/--out` a verb parameter.
**Fix:** The verb returns the text or events. `out` stays a CLI-only rendering option, declared
as a no-twin parameter.

### MEH: the watcher's lock wait is unbounded {#m-2}

**What:** A hung drainer (a stopped CLI) blocks the flush thread forever.
**Fix:** The watcher takes the lock with `LOCK_NB` and a bounded retry. On timeout it keeps the
entries in memory for the next flush and logs a counted line. It never drops them.

### MEH: one call may hold a read handle while it opens the writer {#m-3}

**What:** A call whose fn reads and then writes in-process could still hold the read-only
attach when `local_write` opens the writer. That is the bug-135 `rmx_ro` StaleDuckDBInstance
shape.
**Fix:** `local_write`'s fn does its reads on its own handle, and a test pins read-then-write
in one call.
