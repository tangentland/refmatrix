## BULLSHIT {#bullshit}

### R1: Q8's recommended option (b) claims save-states stay reachable through `rmx memory recall` and `session recall`. Under b they are not, and b's cost is left out {#r1}

- **Side A: Q8 as asked.** `workflow/open-questions.md`, Open, Q8:
  - "b: ingest-excluded (viascope's rule as written): `workflow/` and save-states never enter the
    store's graph; still reachable by grep floor, files, and **`rmx memory recall`/`session
    recall` for save-states**; `rmx context` stops finding plans/specs/bsd reports"
  - "a: … needs new derive code (G22)".
- **Side B: the code.**
  1. Save-states reach the store only through the memory bridge. `src/refmatrix/ingest_gmd.py:555`
     stores a save-state path "as `session/recall-state`".
     - `rmx memory recall` returns those rows today. `cli.py:12419-12425` shows that only the hook
       modes exclude `session/*` by default.
     - If save-states "never enter the store", memory recall cannot return them.
     - `rmx session recall` (`cli.py:14379-14383`) is "BM25-style search over session cards", not
       save-state files.
     - Under b, only `rmx recall-state`, which reads files (`handoff.py:587-596`
       `iter_savestates`), and grep reach them.
  2. "Viascope's rule as written" is the `.refmatrix_ignore` file. It is loaded from
     `<project_root>/.refmatrix/.refmatrix_ignore` (`ingest.py:117`) and matched against
     project-relative paths. Save-states live in `~/.claude/projects/<slug>/memory/savestates/` and
     come in through the bridge, which that file does not govern.
     - So b needs new bridge code too. It also reverses the bridging that 26.3/26.4 built and that
       25.1 rev 7 re-asserts on the packed path.
     - Q8 attributes "needs new code" to a only.
  3. Adopting the ignore rule on a store that already holds `workflow/` triggers `_sync_paths`. It
     "purges a path that BECAME ignored so the graph self-cleans"
     (`feedback_operational_content_not_in_graph.md:33-35`). That removal runs outside plan-22's
     audited path, against plan-22 d-1 ("one removal path", user 2026-10-07). D-Q1 still says
     "Live purges go through plan-22's audited path".
     - Under b, the `rel:` edges from `docs/` into `workflow/` ids (plans, task specs, this review)
       lose their targets.
- **Why BULLSHIT:** this is a live user question, answerable at any moment. Its recommended option
  rests on a false reachability claim. Its cost comparison puts the new-code burden on one side
  only and omits b's removal path and dangling edges. A "b" answer given on this text would be
  given on false premises, which is the same failure N0 was about.
- **Fix:** restate Q8 before the user answers.
  - b's reachability: only `rmx recall-state` (file read) and grep reach save-states;
    `memory recall` and `session recall` do not.
  - b's code: a bridge exclusion for `savestates/` / `session/recall-state`, reversing the
    26.3/26.4 bridging.
  - b's removal: `_sync_paths` purges outside plan-22 unless it is routed through 22.2 with a
    manifest.
  - b's edges: `docs/` → `workflow/` `rel:` edges dangle.
  - a's cost: new derive code (G22), plus the X2-measured co-mention pollution stays until G22
    lands.
  - A middle option is legitimate: `workflow/` ingest-excluded, save-states bridged but excluded
    from co-mention.
  - Keep the recommendation first, with its reason.
