## Findings {#findings}

### SKETCHY: R-H1's process-wide embed client is never dropped, so a hub outage pins a daemonless process to in-process model loads {#s-1}

**File:** `src/refmatrix/recall.py:343-354` (`_process_embed_client`), `:377`, `:387`

**What:** `_process_embed_client` caches the first client `new_model_client("embed")` returns, for the life of the process. That is the hub-shared `SharedWorkerClient` whenever the hub is up. When a later call fails, `shared_embedder` degrades to the in-process `Embedder()`, but the dead cached client is never cleared. Every later call in the long-lived `rmx mcp` therefore retries the dead socket and then loads the model in-process again.

**Why:** before the remedy, each call ran `new_model_client`. After a hub outage that saw `shared_available()` false and spawned a private worker. The remedy fixed the leak (the original H1) by caching, but removed that recovery. This is a new defect from the remedy, on the no-daemon path R-H1 exists for.

**Evidence:** `bsd-r1-embed-client-probe.log`. The cached client is a `SharedWorkerClient` pointed at an absent `models.sock`. Three `shared_embedder` calls each logged "subprocess embedder unavailable (FileNotFoundError) ... falling back to in-process model". That is 3 in-process model loads, and the cached client keeps the same `id` throughout. (The probe replaces `Embedder` with a counter so it does not load the real model. That is probe-only, not a test.)

**Fix:** in `shared_embedder`'s transport `except` branch, drop the cached client when no `remote` was passed: under `_EMBED_CLIENT_LOCK`, close it and set `_EMBED_CLIENT = None`, mirroring the daemon's `on_fallback`. The next call then re-runs `new_model_client` and gets a private worker. Add a RED test: cached shared client fails, then the next call builds a new client. The effort is about 6 lines.

**Pattern match:** YES. This repeats [[project_shared_worker_private_split]] (a hub outage splits processes onto the wrong model path permanently), in a new process type.

### MEH: `curator status --drain` drains nothing, silently, behind an oversized head file {#m-1}

**File:** `src/refmatrix/cli.py:9067-9071`

**What:** `read_spool` always takes the oldest file first. If that file holds more distinct paths than `--limit` (default 10), which one daemon flush of a checkout easily does, that file is never fully shown. The operator `--drain` then keeps it on every run. It can also never reach the newer files, because the head file fills the read. The probe added three 2-entry files behind a 15-entry head: four runs left 21 entries in 4 files. The only output was the normal queue line; nothing said a drain was skipped.

**Why:** this is data-safe (R-B1's goal holds), but it is an uncounted skip on the curator path (CLAUDE.md#no-silent-failures).

**Fix:** after the drain, print `kept N spool file(s) not fully shown — raise --limit or use drain --token` to stderr.

### MEH: the shipped gmd-curator template still says the hooks drain {#m-2}

**File:** `src/refmatrix/templates/agents/gmd-curator.md:139,145`; `.claude/agents/gmd-curator.md:180,186`

**What:** the template still describes the old behaviour, which R-B1 removed and which is false for every project the template ships to:

- `rmx curator status --drain  # show + drain what it read (hooks do this)`
- "A token file already drained by someone else (the prompt hook)"

`--drain` also no longer drains "what it read"; it drains only the files it fully printed.

**Fix:** reword both lines. The [[bsd-plan3-task37-spec-r5-925f121]] impression already says to trace a protocol change through agent templates.

### MEH: the legacy parser takes any non-JSON line as a path {#m-3}

**File:** `src/refmatrix/gmd_curator.py:132-136`

**What:** any line that does not start with `{`, `[` or `"` becomes `{path: <line>, reason: legacy}`. The probe line `not a path at all` was adopted as a file change and would be shown to the curator agent as one. The rule runs for every spool file, not just adopted legacy queues.

**Fix:** accept a line as legacy only when it looks like a path (no internal whitespace, or has a path separator or suffix), and only in files adopted from `curator.queue`. Count the rest as bad.
