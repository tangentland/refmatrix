## Findings {#findings}

### SKETCHY: the pagerank rollback is untested — m9 survives {#s1}

**File:** `src/refmatrix/pagerank.py` `store_scores` (`except Exception: con.rollback(); raise`);
`tests/test_bug178_r2.py::test_red_store_scores_propagates_a_commit_failure`
**What:** The implementer added the rollback. Removing it leaves all 64 tests green. The RED test
asserts only that the error propagates, and its own `finally: if con.in_transaction:
con.rollback()` cleans up the state the mutation would leave. That makes the rollback invisible
to the test.
**Why it matters:** Probe 1b, manual replay without the rollback. After the failed commit the
connection stays `in_transaction=True`. The next unrelated `bulk_upsert_entity` + commit then
fails with the same `FOREIGN KEY constraint failed`. On the daemon's long-lived SQLite connection,
every later write would fail until something rolled back. With the rollback, the prior pagerank
rows survive byte-identical and the connection is clean.
**Fix:** In that test, before the `finally`, assert two things: `not con.in_transaction` after the
raise, and that a pagerank row written by a prior successful `store_scores` is unchanged (seed one
first). About 5 lines. It kills m9.
**Pattern match:** YES. `imp-convergence-tests-sites-not-helper` has the same shape: a promise
the implementer added that the test does not observe.

### MEH: the store_scores comment names a failure production cannot hit {#m2}

**File:** `src/refmatrix/pagerank.py` comment above `con.commit()`
**What:** The comment says the swallow hid "a SQLite commit refused at COMMIT time (a deferred FK
on `pagerank.entity_id`)". The SQLite schema declares that FK immediate (store.py:487-494). No
`src/` path sets `defer_foreign_keys` (grep), so an FK violation raises at the INSERT inside
`bulk_write`, not at commit. Only the RED test sets the pragma, to manufacture a real commit
failure. The commit failures production can actually hit are `SQLITE_BUSY` / I/O.
**Fix:** Reword the comment: the busy/I/O case is the production one, and the deferred-FK case is
the test's way to force a commit failure. The repo reads its history through these comments.
