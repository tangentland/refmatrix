### BULLSHIT #b-1: `rmx memory brief --gmd` raises `AttributeError` on every real invocation {#b-1}

**File:** `src/refmatrix/brief.py:407`, called from `src/refmatrix/cli.py:11243`
**What:** `--gmd` is advertised in `--help` ("Emit the GMD index instead of a table") and is task
8.3's shipped surface.
**Why it's bullshit:** the daemon op serialises briefs (`b.as_dict()`, `daemon.py:4292`), the verb
returns dicts over the wire, and the CLI hands those dicts straight to `render_gmd`, which indexes
`b.cls` / `b.label`. Every `Brief` attribute access fails.
**Evidence** (real daemon, real store):
```
$ rmx memory brief --gmd ; echo EXIT=$?

EXIT=1
cli.log: {"argv":["memory","brief","--gmd"], "exit_code":1, "out_bytes":0,
          "error":"AttributeError: 'dict' object has no attribute 'cls'"}
```
`--json`, `--save`, `--class`, `--limit`, `--min-mentions`, `--compile` all work end to end through

**Fix:** rehydrate in the CLI (`[brief_mod.Brief(cls=d["class"], **…) for d in briefs]`) or teach
`render_gmd` to accept dicts. Add a `CliRunner` test that invokes `--gmd`.
**Pattern match:** YES — identical to plan-3 r6 #b-1 (`memory get --degree 1` → bare `NameError`,

### BULLSHIT #b-5: the GMD "round trip" is faked — `parse_gmd` cannot recover evidence {#b-5}
