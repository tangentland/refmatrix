# Brief: tc-215 — term-and-clique overlap as the `used` comparison {#root}

Measure whether a delivered recall item was "used" by comparing its TERMS and CLIQUES with the
terms and cliques of the agent's activity after the delivery, under three clique sources, against
a control. Counts only; read-only; report as text. The user decides the clique source from this
measurement (2026-11-13: "the used comparison really needs always be on the terms and cliques";
"can we measure 1, 2, and 3 before deciding?").

## The comparison {#comparison}

- **Item terms T(E):** the delivered entity's concepts from `entity_links` (all linkage types;
  report the per-linkage contribution), each weighted by idf over the store's own df notion
  (find what `content_rank` / `memory compile` use in `src/refmatrix/`; reuse, do not invent).
  Hub concepts get near-zero weight; also report the `hub_df_frac`-excluded variant.
- **Activity terms A(window):** for each prompt after the delivery, the concepts of the agent's
  activity: touched paths → their entities' concepts; tokens of tool inputs (Bash command, Grep
  pattern, Agent prompt, Edit `new_string`, mcp args) resolved to concept names by the store's own
  concept-name matching; assistant reply text from the session transcript
  (`~/.claude/projects/<slug>/<session>.jsonl`). Report each source's contribution.
- **Term score:** idf-weighted coverage of T(E) by A(window), per lag, times the lag kernel; unit
  score = max over lags.
- **Clique score, three sources (the question):**
  1. **Compiled memory subjects** (`subject_*` memory rows + their `part-of` edges, from
     `memory compile`, `src/refmatrix/consolidate.py`): item and activity concepts mapped to
     subjects; credit when the activity lands in a subject the item belongs to. Memories only —
     report coverage (what share of delivered items has any subject).
  2. **STM topic composites** (`stm.topic_composites`, `src/refmatrix/stm.py:1972`, built from
     the ring as a pure function): the activity window's topics vs the topic(s) holding the
     item's terms. Covers every kind, activity-defined, short-lived.
  3. **Store-wide concept cliques:** tightly co-linked concept groups over the whole catalog,
     built as the hypertree spike built its groupings (`docs/measurements/hypertree-spike-2026-10-20.md`
     `#method`, scripts in `eval/spike_hypertree/`, `common.py`). Report the clique construction
     (threshold, size distribution) and its build cost.
  For each source: clique credit = the activity hits a clique containing ≥ 1 item term that the
  exact-term score did NOT already cover; weight by the clique's specificity (inverse size or idf
  of its members), times the lag kernel.
- **Control:** never-delivered units per `#r7`, scored with the SAME term/clique rules and kernel.
  The comparison is delivered vs control, never a raw rate.

## Validation by labels {#labels}

Label a stratified sample of credits that ONLY the term or clique scores produce (no file/name
match): up to 20 per clique source per corpus, plus 20 term-only, using lbl-215's rubric
(CAUSED / INFORMED / CONSISTENT / UNRELATED / UNJUDGEABLE, from the transcript). Report
precision with Wilson 95% intervals. Merge lbl-215's labels for pairs that coincide.
